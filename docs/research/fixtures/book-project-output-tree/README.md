# 書籍プロジェクト出力ツリー検証fixture

## 目的

書籍プロジェクト全体を複製せず、入力原稿ツリーだけを生成済み原稿ツリーへミラーする構成で、Vivliostyleが利用できる書籍を生成できるか検証する。

調査の背景、方式の比較、責務候補および未決定事項は、[書籍プロジェクトの生成済み原稿ツリーに関する調査](../../book-project-output-tree.md)を参照する。

このfixtureは、書籍プロジェクトの設定形式、CLIおよび変換処理の最終仕様を決定するものではない。`project/book.mjs`と`scripts/build-project.mjs`は、原稿順序の一元管理、Markdownと静的ファイルの扱い、出力先の保護およびVivliostyleとの接続を検証するためのプロトタイプである。

Markdownの変換には、`FIXTURE_SOURCE_TOKEN`を`FIXTURE_TRANSFORMED_TOKEN`へ置き換えるfixture固有の処理を使用する。これはMarkdownだけが変換対象になることを識別するための処理であり、clono本体の変換パイプラインを模擬または先行実装するものではない。

## 構成

```text
project/
├── book.mjs
├── vivliostyle.config.mjs
├── manuscripts/
│   ├── chapter-one.md
│   ├── appendix.html
│   ├── images/
│   │   └── diagram.svg
│   └── nested/
│       └── chapter-two.md
├── build/
│   └── manuscripts/       # 検証時に生成し、Gitでは管理しない
└── themes/
    └── theme.css
```

`project/book.mjs`を原稿順序の唯一の入力とし、プロトタイプの一括変換処理と`vivliostyle.config.mjs`の両方から参照する。

入力原稿ツリーのファイルは、次の規則で`project/build/manuscripts/`へ出力する。

- Markdownは相対パスを保ったまま検証用変換を適用する
- 画像とHTMLは相対パスと内容を保ってコピーする
- 原稿ツリー外のテーマCSSと設定ファイルはコピーしない
- シンボリックリンクは扱わず、検出した場合は失敗する
- 生成先には所有マーカー`.clono-output.json`を配置する

## 出力先の保護

プロトタイプは、出力先が次のいずれかである場合だけ生成する。

- 存在しないディレクトリ
- 空のディレクトリ
- このfixtureと一致する所有マーカーを持つディレクトリ

所有マーカーのない空でないディレクトリは変更せず、処理を失敗させる。入力原稿、書籍プロジェクト、その祖先または子孫関係にある危険な出力先も拒否する。

変換結果は出力先と同じ親ディレクトリに作成したstagingディレクトリへすべて生成する。処理が完了した場合だけ既存の所有済み出力と置き換える。

## 固定した依存関係

- `@vivliostyle/cli` 11.1.0
- `@vivliostyle/vfm` 2.7.0
- `mupdf` 1.28.0

`package-lock.json`で推移的依存関係も固定する。

## 実行方法

```shell
set -eu
npm ci
npm run verify
```

個別に確認する場合は、次のコマンドを使用する。

```shell
set -eu
npm run verify:output
npm run verify:pdf
```

生成した原稿ツリーは`project/build/`、PDFは`output/`へ出力するが、調査資材には含めない。

## 自動検証

`npm run verify:output`は、次を検証する。

- Markdownだけに検証用変換が適用される
- ネストした原稿と画像の相対パスが保たれる
- HTMLと画像の内容が変更されない
- 原稿ツリー外のテーマと設定が出力へコピーされない
- 所有マーカーを持つ出力は再生成でき、古い生成物が残らない
- 所有マーカーのない空でない出力は変更されない

`npm run verify:pdf`は、生成済み原稿をVivliostyle CLI 11.1.0でPDFへ変換し、次を検証する。

- ルートとネストした位置にある変換済みMarkdownが掲載される
- コピーしたHTMLが独立した原稿として掲載される
- コピーしたSVG画像を参照できる
- 原稿ツリー外のテーマCSSが各原稿へ適用される

## 検証結果

2026-08-24にmacOSとNode.js 24.19.0で`npm run verify`を実行し、出力ツリーとPDFの自動検証がすべて成功した。

- 入力原稿ツリーと同じ相対位置へMarkdown、HTMLおよび画像を出力することで、ルートとネストした原稿の両方から画像を参照できた
- `book.mjs`の原稿一覧をプロトタイプとVivliostyle設定で共有し、原稿順序を二重管理せずにPDFを生成できた
- Vivliostyle設定とテーマを原稿ツリー外に残したまま、生成済み原稿へテーマを適用できた
- 存在しない出力と空の出力を初期化し、所有済み出力を再生成できた
- 所有マーカーのない非空出力を拒否し、既存ファイルを保持できた

以上から、書籍プロジェクト全体ではなく原稿ツリーだけをミラーする方式は、初期の一括変換基盤の候補として成立する。

この検証では、最終的な設定形式、clono本体の変換パイプラインとの結合、原稿ツリー外にある静的ファイル、シンボリックリンク、複数OSでのディレクトリ置き換え、および処理中にプロセスが強制終了した場合の復旧を扱っていない。
