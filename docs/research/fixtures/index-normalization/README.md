# 索引の読み正規化・分類・並べ替え検証用fixture

## 目的

索引項目へ明示された読みから、環境に依存しない分類キーと並べ替えキーを生成できるか検証する。VivliostyleによるHTMLまたはPDF生成から切り離し、次の処理を純粋なデータ変換として確認する。

- Unicode正規化、カタカナからひらがなへの変換および英字の小文字化
- 濁音、半濁音、促音、小書き仮名および音引きの正規化
- 「英数字」「あ行」から「わ行」までの固定分類
- 正規化後のキーが同じ索引項目を含む決定的な並べ替え
- 同じ表記の索引項目に対する出現箇所の統合と読みの競合検出

このfixtureは、索引記法、許可文字の最終的な範囲、診断文言または実装APIを確定するものではない。仕様策定前の候補アルゴリズムを検証するものであり、clono本体からは参照しない。

## 候補規則

読みはNFKCで正規化した後、カタカナの`ァ`から`ヺ`までをひらがなへ、ASCII英字を小文字へ変換する。対応する単一のひらがながない`ヷ`、`ヸ`、`ヹ`および`ヺ`は、それぞれ`わ`、`ゐ`、`ゑ`および`を`と結合濁点の組み合わせへ変換する。日本語の並べ替えキーは、さらに次の順で変換する。

1. 音引きを直前のかなが表す母音へ展開する
2. 濁点と半濁点を除去する
3. 促音を含む小書き仮名を対応する通常のかなへ変換する

たとえば、`ばっくなんばー`の並べ替えキーは`はつくなんはあ`となる。

初期候補では、読みとして次のいずれかだけを受理する。

- ひらがな、カタカナの`ァ`から`ヺ`まで、および音引きだけからなる日本語
- ASCII英数字から始まり、ASCII英数字、半角空白および`.+@#/_-`だけからなる英数字列

全角の英数字と記号はNFKCによって対応するASCII文字へ変換できる場合に受理する。`.gitignore`のように表示語が記号から始まる場合も、読みには`gitignore`のような分類可能な値を指定する候補とする。

## 決定的な並べ替え

索引項目は次のキーを順に比較する。文字列比較は実行環境のロケールやICUへ委譲せず、Unicodeコードポイント順で行う。

1. 固定された分類順
2. 濁点、小書き仮名および音引きを正規化した並べ替えキー
3. それらを保持した正規化済みの読み
4. NFKCで正規化した表示語
5. 元の表示語
6. 原稿中の初出位置

この順序により、`一気（いっき）`と`五木（いつき）`の並べ替えキーがともに`いつき`となっても、常に`一気`、`五木`の順となる。同じ読みを持つ`橋`と`箸`も表示語のコードポイント順で安定する。

## 重複の扱い

- 同じ表示語かつ正規化後の読みが同じ項目は一つへ統合し、出現箇所を原稿順に保持する
- 同じ表示語へ異なる正規化済みの読みが指定された場合は、曖昧な索引を生成せずエラーにする
- 異なる表示語が同じ読みを持つ場合は統合せず、決定的な順序で両方を残す

## 検証環境

- 実行確認: macOS、Node.js 24.19.0、Temurin JDK 21.0.12
- 対応範囲: Node.js 22.13.0以降の22系、または24系
- shadow-cljs 3.4.12

正確な依存関係は`package.json`と`package-lock.json`で固定する。

## 実行方法

```shell
set -eu
npm ci
npm run verify
```

`target/`、`.shadow-cljs/`および`node_modules/`は生成物であり、Gitの管理対象には含めない。

## 自動検証

`src/test/clono/research/index_normalization_test.cljs`は、次を確認する。

- `バックナンバー`、`コンピューター`などから期待する日本語の並べ替えキーを生成する
- `ヷ`、`ヸ`、`ヹ`、`ヺ`およびNFKCで`ヷ`となる半角入力を、濁点の意味を保持してひらがな化し、後続する音引きも処理する
- 全角英数字、ASCII英字の大文字小文字および技術用語で使う記号を正規化する
- 空の読み、漢字を含む読み、日英混在の読み、分類不能な音引きを拒否する
- 固定された分類順を使用し、空の分類を出力しない
- 正規化後の並べ替えキーが同じ場合も結果が決定的になる
- 同じ表示語の出現箇所を統合する
- 同じ表示語に異なる読みが指定された場合は競合として拒否する
- 異なる表示語が同じ読みを持つ場合は両方を保持する

## 検証範囲の境界

このfixtureは、索引記法のmdast解析、原稿からのマーカー収集、ページ番号の集約、索引Markdownの生成、書籍プロジェクト設定、VFM変換またはVivliostyleによるPDF生成を検証しない。これらは後続の書籍プロジェクト結合fixtureと、既存の[索引fixture](../vivliostyle-index/)で検証する。

また、初期候補に含まれない読みの自動取得、漢字からの読み推定、ユーザー定義の分類および階層索引も扱わない。
