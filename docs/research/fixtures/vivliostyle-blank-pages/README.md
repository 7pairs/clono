# Vivliostyle空白ページ検証fixture

## 目的

書籍の原稿ファイル間へ、本文や柱を持たず、連続するページ番号だけを表示する空白ページを必ず1ページ挿入できるか検証する。

このfixtureは著者向け記法を決定するものではない。単一原稿内方式では、将来clonoが空白ページ記法を変換した後の出力候補をraw HTMLで模擬する。

## 比較する方式

- `inline-marker`: 1つのMarkdown原稿内へ空白ページ要素を配置する
- `markdown-entries`: 空白ページ専用Markdownを独立した`entry`として配置する
- `html-entries`: 空白ページ専用HTMLを独立した`entry`として配置する

独立`entry`方式では1つの空白ページ資材を繰り返し参照し、各参照へ異なる`output`を指定する。異なる`output`を指定しない場合、Vivliostyle CLIは同じ出力先を上書きする構成としてビルドを失敗させる。

各方式で次の8ページを生成する。

| ページ | 内容 |
| ---: | --- |
| 1 | 先頭の空白ページ |
| 2 | `CONTENT BEFORE` |
| 3 | 途中の空白ページ |
| 4 | `CONTENT MIDDLE` |
| 5 | 連続する空白ページA |
| 6 | 連続する空白ページB |
| 7 | `CONTENT FINAL` |
| 8 | 末尾の空白ページ |

## 固定した依存関係

- `@vivliostyle/cli` 11.1.0
- `@vivliostyle/vfm` 2.7.0
- `mupdf` 1.28.0

`package-lock.json`で推移的依存関係も固定する。

## 実行方法

```shell
set -eu
npm ci
npm run verify
```

## 自動検証

`npm run verify`は各方式について、古いPDFを削除してからVivliostyle CLIを実行し、次を検証する。

- PDFが空でなく、正確に8ページある
- ページ番号が1から8まで連続し、各ページに1回だけ存在する
- 1、3、5、6、8ページ目には、そのページ番号以外の文字が存在しない
- 本文ページは所定の位置にあり、通常の柱とページ番号を持つ

生成されたPDFは`output/`へ出力するが、調査資材には含めない。

## 調査結果

2026-08-23にmacOSとNode.js 24.19.0で検証した結果、3方式すべてが自動検証を通過した。生成した全ページを画像化して、次の点も目視で確認した。

- 先頭、途中、連続、末尾の各位置へ、指定1回につき空白ページが正確に1ページ挿入される
- 空白ページにも通常ページと連続するページ番号が表示される
- 空白ページでは通常ページの柱が表示されない
- 各方式の本文は同じページ、同じ位置へ配置される

名前付きページ`clono-blank`を空白ページ要素へ指定し、通常の`@page`で定義した柱を同名の`@page`規則で無効化することで、ページ番号だけを残せた。

Thunder Clawの用途では空白ページを原稿ファイル間だけへ挿入するため、初期仕様は書籍構成で独立`entry`を配置する方式が適している。単一原稿内方式も技術的には成立するが、初期の著者向け記法として採用する必要性は低い。

MarkdownとHTMLの独立`entry`はどちらも要件を満たした。どちらを生成・同梱するかは、書籍プロジェクト一括変換の設計時に決定する。

製品用テーマとの統合、見開きの左右、隠しノンブルは今回の検証範囲に含めない。
