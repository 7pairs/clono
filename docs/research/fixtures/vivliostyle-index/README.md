# Vivliostyle索引検証用fixture

## 目的

clonoが収集・整理した索引情報をVivliostyleへ渡す場合に、紙面上のページ番号と各出現位置へのPDF内部リンクを生成できるか検証する。同時に、組版後のページ番号に依存する同一ページ重複をVivliostyleだけで除去できるか確認する。

## 前提

2026年8月19日時点の公式ドキュメントでは、VFMに索引項目を指定する構文はなく、Vivliostyle CLIにも目次の`toc`に相当する索引収集・生成設定は確認できない。このfixtureでは、索引項目の収集、読みの正規化、分類、並べ替え、索引文書の構造生成をVivliostyleの責務とみなさない。

一方、Vivliostyleは`target-counter()`とPDF内部リンクを扱える。このfixtureは、clonoの変換後を模した本文マーカーと索引文書を入力し、組版へ委譲できる範囲を検証する。

## 検証対象

- 本文とコラム内の索引マーカーが、指定した語だけを通常の本文として表示する
- 索引項目を「英数字」と五十音の行へ分類して表示する
- 正規化済みの読みを表すソートキーの順序を保持する
- 同じ項目を一つへまとめ、複数の出現位置を列挙する
- 各出現位置の紙面上のページ番号を`target-counter()`で表示する
- 各ページ番号を、対応する本文中の索引マーカーへのPDF内部リンクにする
- 同じ項目が同じページに複数回ある場合の挙動を確認する

階層索引、ページ範囲、索引項目間の相互参照、主要ページの強調、脚注とキャプション内の索引指定は対象に含めない。

## 入力と出力の境界

`chapter-one.md`と`chapter-two.md`には、clonoの変換後を模した索引マーカーを記述する。マーカーは出現ごとに一意なIDを持ち、表示語と読みを属性へ保持する。

```html
<span
  id="index-backnumber-1"
  class="index-marker"
  data-index-term="バックナンバー"
  data-index-reading="ばっくなんばー"
>バックナンバー</span>
```

`index.md`は、clonoが生成する候補となる索引文書を模している。索引項目は読みと正規化済みのソートキーを持ち、各出現位置への空のリンクを列挙する。

```html
<div
  class="index-entry"
  data-index-term="バックナンバー"
  data-index-reading="ばっくなんばー"
  data-index-sort-key="はつくなんはあ"
>
  <dt>バックナンバー</dt>
  <dd><a class="index-page" href="chapter-two.html#index-backnumber-1"></a></dd>
</div>
```

このfixtureは、`ばっくなんばー`から`はつくなんはあ`を生成する正規化アルゴリズムを検証しない。正規化済みのソートキーを出力構造へ保持し、その順序と紙面表示をVivliostyleが壊さないことを検証する。

## 同一ページ重複の能力プローブ

第1章には`Android`を同じページへ二回配置し、第2章へもう一回配置する。索引文書は三つの出現位置をすべて列挙するため、Vivliostyleの出力は`2, 2, 3`となる。

PDF検証では、最初の二つがどちらもページ`2`を表示し、それぞれ別の本文マーカーへ移動する独立したリンクであることを明示的に確認する。これは製品要件として重複表示を承認するものではなく、Vivliostyleの`target-counter()`がページ番号を表示しても同一ページの参照を自動的には統合しない、という責務境界を固定するための検証である。

clonoは組版前には最終的なページ番号を知らないため、同一ページ重複を除去するには、要件の調整、組版後の処理、またはVivliostyleと連携する別の仕組みを検討する必要がある。

## 依存関係

- Node.js 22.13.0以降の22系、または24系
- `@vivliostyle/cli` 11.1.0
- `@vivliostyle/vfm` 2.7.0
- `mupdf` 1.28.0

依存関係はこのディレクトリの`package-lock.json`に固定する。

## 実行方法

```shell
set -eu
npm ci
npm run verify
```

個別に確認する場合は、次のコマンドを使用する。

```shell
set -eu
npm run verify:webpub
npm run verify:pdf
```

生成物は`output/`に出力され、Gitの管理対象には含めない。

## 自動検証

`scripts/verify-webpub.mjs`は、次を確認する。

- 本文とコラム内の11個の索引マーカーがID、表示語、読みを保持する
- 各マーカーの表示内容が指定した索引語だけである
- 索引の分類と項目が期待する順序で出力される
- 索引項目が読み、正規化済みソートキー、すべての出現位置を保持する
- 各リンク先のHTML文書と索引マーカーIDが存在する
- 索引が本文の後、後付の前に配置される

`scripts/verify-pdf.mjs`は、次を確認する。

- PDFが5ページであり、全ページのノンブルが1から5まで連続する
- 索引が4ページ目にあり、1ページに収まる
- 分類見出しと索引項目が期待する順序で表示される
- 11件のページ番号が、それぞれ対象ページの番号を表示する
- 11件のPDF内部リンクが、それぞれ期待する索引マーカーID、ページ、マーカー付近の座標へ解決される
- 同一ページにある二つの`Android`が、`2, 2`という別々のページ番号リンクになる
- 索引以外のPDF内部リンクが存在しない

## 目視確認

`output/index.pdf`を開き、次を確認する。

- 索引語、分類見出し、ページ番号に欠落、重なり、意図しない改行がない
- 本文とコラム内の索引語が、周囲の本文と同じ見た目で表示される
- 索引項目とページ番号の対応が読み取れる
- `Android`のページ番号が`2, 2, 3`となり、同一ページ重複の限界が再現される
- 各ページ番号をクリックし、対応する索引語へ移動できる

## 未検証・未決定

- 読みを正規化する具体的なアルゴリズムと例外
- 英数字の大文字・小文字、記号、全角文字を含む場合のソート規則
- 空の分類見出しを表示するか
- 同一ページの重複を除去する方法
- 索引マーカーがページをまたぐ場合のリンク先
- 脚注、画像・表・コードリストのキャプション内の索引指定
- Thunder Clawの実際の項目数を含む複数ページの索引
- 製品用テーマにおける索引の紙面レイアウト
