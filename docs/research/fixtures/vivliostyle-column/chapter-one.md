<p class="column-title">SHOULD要素を含むコラム</p>

コードブロック、画像、表を一つのコラムに含める。

```kotlin
fun columnMessage(): String = "inside column"
```

![青い図形と線のコラム内画像](column-image.svg)

| 要素 | 状態 |
| --- | --- |
| コード | 検証 |
| 画像 | 検証 |
| 表 | 検証完了 |

<aside id="long-column" class="column">

<p class="column-title">ページをまたぐ長いコラム</p>

長いコラムの開始を示す固有の文章。

第01段落。長いコラムを複数ページへ分割できることを確認するための文章。

第02段落。同じコラムの内容が欠落せずに続くことを確認する。

第03段落。分割後のページでタイトルを繰り返さない。

第04段落。内容は通常のMarkdown段落として処理される。

第05段落。組版エンジンがページの空きに応じて配置する。

第06段落。コラムの外観はテーマCSSの責務とする。

第07段落。一ページに収まらない場合だけ分割を許容する。

第08段落。長い雑談もコラムの外へ溢れないことを確認する。

第09段落。各段落は検証時に識別できる固有の番号を持つ。

第10段落。紙面上で文章が重ならず表示されることも確認する。

第11段落。ページの境界で内容が消失しないことが重要である。

第12段落。この段落も長いコラムの一部である。

第13段落。コラムは入れ子にせず単一のコンテナとする。

第14段落。見出しは初期の検証対象に含めない。

第15段落。コラム自体への連番や参照も初期要件ではない。

第16段落。著者向け記法は別の調査で決定する。

第17段落。現在は変換後を模したHTML構造を入力する。

第18段落。VFMが内部のMarkdownを解釈できることを検証する。

第19段落。Vivliostyleが長い囲み枠を組版できることを検証する。

第20段落。最後の内容まで同じコラムとして表示する。

第21段落。ページをまたいだ後も通常の段落として続く。

第22段落。分割位置は組版時のページの空きに応じて決まる。

第23段落。コラムのタイトルは続きのページで繰り返さない。

第24段落。囲み枠の内部に必要な余白をテーマCSSで指定する。

第25段落。ページ境界の前後で文字が重ならないことを確認する。

第26段落。ページ境界の前後で文字が欠落しないことも確認する。

第27段落。コラムが複数ページに分かれても一つの構造として扱う。

第28段落。長いコラムは必要な場合だけ許容する想定である。

第29段落。短いコラムはできるだけ同じページへまとめる。

第30段落。これが長いコラムの最後の番号付き段落である。

長いコラムの終了を示す固有の文章。
