# Vivliostyleの連番・相互参照に関する結合調査

- 状態: 調査済み
- 初回調査日: 2026-08-18
- 最終更新日: 2026-08-19
- 検証環境:
  - 実行環境: macOS、Node.js 24.19.0
  - HTML変換: `@vivliostyle/vfm` 2.7.0
  - PDF生成: `@vivliostyle/cli` 11.1.0
    - CLIが依存する`@vivliostyle/vfm` 2.7.0
    - CLIが使用するVivliostyle.js 2.44.1
  - PDF検証: `mupdf` 1.28.0

## 背景

見出し、画像、表、コードリストの個別調査では、CSSカウンターによる章ごとの連番と、`target-counter()`および`target-text()`による相互参照が要件を満たすことを確認した。

一方、個別fixtureはそれぞれ異なるテーマCSSと参照属性を使用していた。図、表、コードリストのカウンターを同じテーマで使用した場合の独立性や、種類の異なる参照を一つの出力契約で扱えることは確認していなかった。このため、横断的な責務判断を確定する前に結合検証を行った。

## 検証範囲

二つのMarkdownファイルを一章ずつVivliostyle CLIの`entry`へ登録し、同じテーマCSSを適用した。原稿には次の要素を同時に配置した。

- 章と節の見出し
- 番号付き画像、表、コードリスト
- 番号なし画像、表、コードブロック
- 見出し、画像、表、コードリストの番号参照
- 見出し、画像、表、コードリストの番号とタイトルの参照
- 同一Markdownファイル内、別Markdownファイル間、前方、後方の参照
- 各章に一つずつの基本的な`dpub`脚注

脚注はほかの要素と共存し、章ごとに番号が1から始まることだけを確認した。コラム内脚注の責務判断は、コラムの構文と出力HTMLを決定した後の結合検証へ委ねる。

## 技術検証

調査結果を再検証できるように、[検証用fixture](fixtures/vivliostyle-reference-integration/)をリポジトリ内へ保存している。このfixtureは`clono`本体から独立したnpmプロジェクトであり、`package.json`と`package-lock.json`によって検証環境の依存関係を固定する。

HTMLの検証プログラムは、見出しと各番号付き要素のID、class、キャプションID、コードの構文強調、参照の`href`と`data-title-href`、脚注の構造を確認する。番号なし要素が番号付きの構造へ変換されていないことも確認する。

PDFの検証プログラムは、既存のPDFを削除してからVivliostyle CLIで再生成し、次を自動で確認する。

- 図、表、コードリストが独立した連番を使用し、第2章でそれぞれ`2.1`へリセットされる
- 番号なし画像、表、コードブロックが対応するカウンターを消費しない
- 見出し、画像、表、コードリストの番号とタイトルが期待する文字列で表示される
- 16件の論理的な参照が、それぞれ期待する対象ID、ページ、対象付近の座標へ解決される
- 同一Markdownファイル内、別Markdownファイル間、前方、後方の参照がPDF内部リンクになる
- 基本的な脚注の参照と本文が欠落せず、内部リンクとして解決される

生成したPDFは全5ページを画像へ変換し、見出し、画像、表、コード、参照文字列、脚注の欠落や重なりがないことを目視確認した。目視確認で番号なし画像が紙面幅を超える問題を発見したため、統合テーマのすべての画像へ紙面幅の上限を設定し、再検証した。

## 統合した出力契約

### カウンターの初期化

個別fixtureでは、`body`の`counter-reset`へ一種類のカウンターだけを指定していた。同じプロパティを複数のCSS規則へ分けると後の宣言が前の宣言を上書きするため、統合テーマでは必要なカウンターを一つの宣言へまとめる。

```css
body {
  counter-reset: figure table listing;
}
```

番号付き要素だけが対応するカウンターをインクリメントすることで、番号なし要素と各種類の連番を独立して扱える。

### タイトル取得先

個別fixtureでは、タイトル取得に使用する属性が要素の種類によって異なっていた。結合fixtureでは、すべての番号・タイトル参照へ`data-title-href`を出力する契約に統一した。

`href`は番号の取得とPDF内部リンクの移動先に使用する。`data-title-href`はタイトルの取得先に使用する。見出しでは両方が同じ見出しIDを指し、画像、表、コードリストでは`data-title-href`がキャプションのIDを指す。

```html
<a
  class="xref-listing xref-title"
  href="#listing-greeting"
  data-title-href="#listing-greeting-caption"
></a>
```

```css
a.xref-title::after {
  content: " " target-text(attr(data-title-href url), content);
}
```

この契約により、共通のCSS規則で各種類のタイトルだけを取得できた。

## 調査結果

- 図、表、コードリストのカウンターは、同じテーマCSSと文書で独立して動作する
- 各カウンターを一つの`counter-reset`へまとめることで、章ごとの初期化を共存させられる
- 番号なし要素は、番号付き要素のclassを付けなければ対応するカウンターを消費しない
- `data-title-href`へタイトル取得先を統一することで、すべての参照種別に共通するタイトル参照規則を使用できる
- 見出し、画像、表、コードリストの番号とタイトルは、同一・別Markdownファイル、前方・後方のいずれからも参照できる
- 参照は、対象要素へ移動するPDF内部リンクとして保持される
- 基本的な`dpub`脚注は、連番と相互参照を同時に使用する文書でも動作する

## 責務判断

基本的な書籍構成では、見出し、画像、表、コードリストの番号と参照文字列の生成をVivliostyleとテーマCSSへ委譲できる。clonoが番号を計算し、原稿や出力へ番号を直接埋め込む処理は実装しない方針とする。

clonoは、著者向け記法から次の情報を持つHTML構造を生成する責務を担う候補とする。

- 参照対象を識別するID
- 番号付き要素と参照種別を表すclass
- 画像、表、コードリストのキャプションと、そのタイトル参照用ID
- 番号とクリック先を示す`href`
- タイトル取得先を示す`data-title-href`
- 別Markdownファイルを参照する場合の変換後の出力パス

clonoは、未定義の参照ID、重複したID、不正な参照種別も診断する候補とする。

## 成立条件と後続の検証

今回確認した章番号は、「一つのMarkdownファイルが一つの章に対応し、Vivliostyle設定の`entry`が章順に並ぶ」構成を前提とする。

[目次の調査](vivliostyle-table-of-contents.md)では、前付、本文、付録、索引、後付、目次、表紙相当、空白ページ相当、奥付を含む構成で、本文と付録の見出し番号、番号なし文書、連続するページ番号を検証した。この結果、章として数えない文書を含む基本的な書籍構成でも、原稿ごとに適用するテーマを分けて見出しカウンターを制御できることを確認した。

一方、この目次fixtureには図、表、コードリスト、脚注とその相互参照を含めていない。次の事項は、今回の責務判断を妨げないため、必要な設計が決まった段階で検証する。

- 章として数えない前付・後付、目次、索引を含む書籍全体での図、表、コードリスト、脚注のカウンター制御と相互参照
- Thunder Clawの製品用テーマでの紙面レイアウト

書籍全体の結合検証は、索引とコラムの調査が進み、実際の`entry`構成と脚注の配置を設計するときに行う。これは各カウンターの起点とリセットに関わるため、最終的なカウンター設計を固定する前に完了させる。

製品用テーマとの結合は責務境界ではなく組版結果の受け入れ検証であるため、テーマが具体化した後に行う。

## 再現方法

検証に使用する入力、HTMLとPDFの自動検証、PDFの目視確認手順は、[検証用fixtureのREADME](fixtures/vivliostyle-reference-integration/README.md)を参照する。fixture内で`npm ci`を実行した後、`npm run verify`で再検証できる。

## 再調査する条件

- VFMが見出し、画像、表、コードまたは脚注から生成するHTML構造を変更した場合
- Vivliostyle.jsのCSSカウンター、`target-counter()`または`target-text()`の実装が変更された場合
- 書籍の原稿ファイル構成が、一章一ファイルの前提を満たさなくなった場合
- 実際の前付・後付、目次、索引を含む構成で章番号や参照が期待どおりにならなかった場合
- 製品用テーマで番号、タイトル、リンクまたは参照先の配置が期待どおりにならなかった場合
