# Vivliostyleの空白ページに関する調査

- 状態: 調査済み
- 調査日: 2026-08-23
- 最終更新日: 2026-09-01
- 検証環境:
  - 実行環境: macOS、Node.js 24.19.0
  - HTML変換: `@vivliostyle/vfm` 2.7.0
  - PDF生成: `@vivliostyle/cli` 11.1.0
    - CLIが依存する`@vivliostyle/vfm` 2.7.0
    - CLIが使用するVivliostyle.js 2.44.1
  - PDF検証: `mupdf` 1.28.0

## 背景

Thunder Clawの書籍では、印刷および紙面構成の都合により、原稿ファイル間へ内容を持たないページを意図的に挿入する場合がある。印刷所へ入稿するPDFでは全ページにノンブルが必要なため、ここでいう空白ページは完全な白紙ではなく、本文と柱を表示せず、連続するページ番号だけを表示するページを指す。

既に実装した強制改ページ記法は、後続の内容を次ページから開始する機能である。文書先頭、文書末尾または連続した指定を禁止しており、内容を持たない一ページの挿入には使用しない。

空白ページを著者向け記法として原稿内へ指定すべきか、書籍構成として独立した原稿間の要素にすべきかを判断するため、両方の出力候補を技術検証した。

## Thunder Clawの要件

- 空白ページは原稿ファイル間へ挿入できればよく、原稿ファイル内の任意位置では必要ない
- 指定1回につき、左右の調整とは無関係に必ず一ページを挿入する
- 書籍の先頭、途中、末尾へ挿入できる
- 複数の空白ページを連続して挿入できる
- 空白ページでもページカウンターを進め、前後と連続するアラビア数字のノンブルを表示する
- 本文、見出し、柱および装飾は表示しない
- PDFで要件を満たせればよく、Web出版物やEPUBで空白ページとして表示することは初期要件に含めない
- 隠しノンブル、左右に応じた空白ページ、別形式のページ番号は初期要件に含めない

## 公式情報の確認

Vivliostyle CLI 11.1.0は、複数のMarkdownまたはHTMLを`entry`として書籍の読み順へ配置できる。各`entry`には、変換後の出力先を示す`output`を指定できる。

Vivliostyle.js 2.44.1は、CSS Paged Mediaの名前付きページ、`page`プロパティ、ページマージンボックスおよび`page`カウンターに対応している。要素へ名前付きページを指定すると、その要素が配置されるページだけに固有の`@page`規則を適用できる。

通常ページの`@page`規則で柱とノンブルを定義し、空白ページ用の名前付き`@page`規則で柱だけを`none`へ上書きすると、通常ページと連続するノンブルを残したまま柱を非表示にできる。

## 技術検証

調査結果を再検証できるように、[検証用fixture](fixtures/vivliostyle-blank-pages/)をリポジトリ内へ保存している。このfixtureはclono本体から独立したnpmプロジェクトであり、`package.json`と`package-lock.json`によって検証環境の依存関係を固定する。

### 比較した方式

次の3方式を同じCSSとページ構成で比較した。

1. 単一のMarkdown原稿内へ、clonoによる変換後を模した空白ページ要素を配置する
2. 空白ページ専用Markdownを独立した`entry`として原稿ファイル間へ配置する
3. 空白ページ専用HTMLを独立した`entry`として原稿ファイル間へ配置する

単一原稿内方式は、著者向け記法を正式採用するものではなく、記法を空白ページ要素へ変換した場合の技術的な成立性だけを確認する。

独立`entry`方式では、一つの空白ページ資材を複数の位置から参照した。Vivliostyle CLI 11.1.0では、同じ資材をそのまま複数回指定すると変換後の出力先が衝突するため、各参照へ異なる`output`を指定した。この構成により、空白ページ資材を複製せず再利用できた。

### 変換後の構造とCSS

空白ページ要素には、検証用の候補として次の構造を使用した。

```html
<div class="clono-blank-page" aria-hidden="true"></div>
```

この要素に空白ページ専用の名前付きページと前後の改ページを指定した。

```css
.clono-blank-page {
  page: clono-blank;
  break-before: page;
  break-after: page;
  min-block-size: 1px;
}
```

通常ページの柱とノンブルに対して、名前付きページでは柱だけを無効化した。

```css
@page {
  @top-center {
    content: "RUNNING HEADER";
  }

  @bottom-center {
    content: counter(page);
  }
}

@page clono-blank {
  @top-center {
    content: none;
  }

  @bottom-center {
    content: counter(page);
  }
}
```

class名、名前付きページ名、HTML要素およびCSSは検証用の候補であり、書籍プロジェクト一括変換の最終的な出力契約ではない。

### ページ構成と自動検証

各方式で、次の8ページを生成した。

| ページ | 内容 |
| ---: | --- |
| 1 | 先頭の空白ページ |
| 2 | 1番目の本文ページ |
| 3 | 途中の空白ページ |
| 4 | 2番目の本文ページ |
| 5 | 連続する空白ページA |
| 6 | 連続する空白ページB |
| 7 | 3番目の本文ページ |
| 8 | 末尾の空白ページ |

PDFの検証プログラムは、既存のPDFを削除してから各方式を再生成し、次の内容を確認する。

- PDFが空でなく、正確に8ページある
- 1から8までのページ番号が、対応する各ページに1回だけ存在する
- 1、3、5、6、8ページ目には、そのページ番号以外の文字が存在しない
- 2、4、7ページ目には、期待する本文、通常ページの柱およびページ番号が存在する

生成した3方式、合計24ページを画像へ変換した。すべての空白ページにノンブルだけが表示され、本文と柱が表示されないことを目視確認した。3方式の本文ページは、同じページと同じ位置へ配置された。

## 検証結果

3方式すべてで、書籍の先頭、途中、末尾および連続する位置へ、指定1回につき正確に一ページの空白ページを挿入できた。空白ページは通常ページと同じ`page`カウンターを使用し、ページ番号が1から8まで連続した。

名前付きページの`@page`規則により、空白ページだけ通常の柱を非表示にし、ノンブルを残せた。物理的なページ生成、ページカウンターの増加、柱とノンブルの表示は、Vivliostyle.jsとCSSへ委譲できる。

Thunder Clawでは空白ページを原稿ファイル間だけへ配置するため、原稿内の著者向け記法より、書籍構成へ空白ページを指定して独立`entry`へ変換する方式が要件に合う。単一原稿内方式も技術的には成立するが、初期仕様で著者向け記法を追加する必要はない。

MarkdownとHTMLの独立`entry`はどちらも要件を満たした。後続の[書籍プロジェクト仕様](../specifications/book-project.md)では、変換を必要としないHTML資材を生成する方式を採用した。

## 責務判断

### Vivliostyleへ委譲する責務

- 書籍の読み順に配置された各`entry`を別ページから開始する
- 名前付きページと改ページ指定に従い、内容を持たないページを生成する
- 空白ページを含めて`page`カウンターを増加させる
- `@page`規則に従って空白ページの柱を非表示にし、ノンブルを表示する
- 前後の本文を後続のページへ継続して配置する

### clonoが担う責務

- 原稿順序の中へ空白ページを指定できる書籍構造の入力契約を提供する
- 空白ページが指定された場合に、共通のHTML資材を生成済み原稿ツリーへ生成する
- 名前付きページを使用する空白ページ用の構造と基盤CSSを提供する
- 書籍の先頭、末尾および連続する空白ページ指定を保持する
- 不正な書籍構造または生成先の衝突を診断する

### 利用者が担う責務

- `clono.config.mjs`の書籍構造を`vivliostyle.config.mjs`から参照し、原稿と空白ページをVivliostyle CLIの`entry`へ変換する
- 同じ空白ページHTMLを複数回参照する場合、各`entry`へ衝突しない`output`を割り当てる
- 利用者テーマの`@page clono-blank`で、空白ページに残すノンブルと非表示にする柱を指定する

初期仕様では、clono設定をVivliostyle設定へ変換するヘルパーを提供しない。ヘルパーを導入した場合は、`entry`への変換と一意な`output`の割り当てをclonoの責務へ移せるか改めて判断する。

空白ページは単一原稿の内容ではなく、書籍の読み順を構成する要素として扱う。このため、初期仕様では原稿内の著者向け記法と単一ファイル変換CLIの責務に含めない。

## 成立条件と未確認事項

今回の結果は、通常ページと空白ページで同じ用紙サイズ、余白およびページ番号の形式を使用する構成を前提とする。

次の事項は未確認または未決定である。

- Thunder Clawの製品用テーマとの統合
- 縦書き、右開き、左開きまたは見開きの左右を指定する空白ページ
- 隠しノンブルと、通常ページとは異なる位置または形式のノンブル
- Web出版物とEPUBにおける空白ページの扱い

書籍構造の設定形式、HTML資材、class名、名前付きページ名、HTML構造および基盤CSSの契約は、[書籍プロジェクト仕様](../specifications/book-project.md)で決定した。柱とノンブルを指定する`@page clono-blank`は利用者テーマの責務とする。残る事項は今回の責務判断を妨げないため、製品用テーマまたは対象出力の仕様が具体化した段階で検討する。

## 再調査する条件

- Vivliostyle CLIの`entry`または`output`の契約が変更された場合
- VFMがraw HTMLまたは空のHTML要素の扱いを変更した場合
- Vivliostyle.jsの名前付きページ、改ページ、ページカウンターまたはページマージンボックスの実装が変更された場合
- 書籍プロジェクト一括変換で、原稿ファイル内の任意位置にも空白ページが必要になった場合
- Thunder Clawの原稿や製品用テーマで、ページ数、ノンブルまたは柱が期待どおりにならなかった場合
