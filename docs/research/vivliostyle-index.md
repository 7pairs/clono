# Vivliostyleの索引に関する調査

- 状態: 調査済み
- 初回調査日: 2026-08-19
- 最終更新日: 2026-08-21
- 検証環境:
  - 実行環境: macOS、Node.js 24.19.0
  - HTML変換: `@vivliostyle/vfm` 2.7.0
  - PDF生成: `@vivliostyle/cli` 11.1.0
    - CLIが依存する`@vivliostyle/vfm` 2.7.0
    - CLIが使用するVivliostyle.js 2.44.1
  - PDF検証: `mupdf` 1.28.0

## 背景

Thunder Clawの前作では、本文中へ索引項目と読みを明示する独自記法を置き、ビルドスクリプトで索引項目を収集していた。スクリプトは読みを使って項目を並べ替え、各出現位置のページ番号を巻末の索引へ表示するための原稿を生成していた。

```text
[index:索引項目|さくいんこうもく]
[index:バックナンバー|はつくなんはあ]
```

前作では、濁音、半濁音、促音、音引きを除いた読みを著者が指定していた。clonoでは`ばっくなんばー`から`はつくなんはあ`のようなソート用の読みを生成し、著者の負担を減らすことを目指す。

索引はclonoの中心的な機能である。現在のVivliostyleへ委譲できる範囲と、clonoが実装すべき範囲を判断するため、公式情報の確認と技術検証を行った。

## Thunder Clawの要件

- 著者が本文中で索引へ掲載する語と読みを明示できる
- 索引指定は指定した語だけを表示し、周囲の本文と同じ見た目にする
- 同じ項目を複数箇所で指定し、一つの索引項目へまとめられる
- 各出現ページの紙面上のページ番号を表示する
- 同じ項目が同じページに複数回ある場合、初期仕様では同じページ番号の重複表示を許容する
- 各ページ番号をクリックし、対応する索引指定位置へ移動できる
- 英数字を日本語と分け、少なくとも「英数字」「あ行」「か行」などの単位で分類する
- 読みを索引用に正規化し、正規化後の読みで項目を並べ替える
- 索引は本文、付録などの後に配置し、目次へ掲載する
- 初期仕様では単一階層の索引だけを扱う
- ページ範囲、索引項目間の相互参照、主要ページの強調は扱わない
- 索引指定は通常の本文とコラムを必須対象とし、脚注と各種キャプションは後続候補とする
- 索引指定がページをまたぐ場合は、先頭ページを参照できればよい

## 公式情報の確認

検証に使用した[VFM 2.7.0の公式ドキュメント](https://github.com/vivliostyle/vfm/blob/v2.7.0/docs/ja/vfm.md)には、索引項目と読みを指定する構文は記載されていない。

[Vivliostyle CLI 11.1.0の設定リファレンス](https://github.com/vivliostyle/vivliostyle-cli/blob/v11.1.0/docs/config.md)には目次を自動生成する`toc`設定があるが、本文から索引項目を収集し、分類、並べ替え、統合して索引文書を生成する設定は確認できない。2026年8月19日に確認した[公式チュートリアル](https://vivliostyle.org/ja/tutorials/)にも目次の自動・手動生成はあるが、索引生成は記載されていない。

これは公式ドキュメントが「索引機能は存在しない」と明記していることを意味しない。一方、VFMとVivliostyle CLIの文書化された公開インターフェースには、clonoの要件を満たす索引収集・生成機能は確認できない。このため、現時点ではVivliostyleによる索引の自動生成を前提としない。

VivliostyleはCSSの`target-counter()`とPDF内部リンクをサポートする。索引構造と出現位置へのリンクを事前に用意すれば、リンク先の紙面上のページ番号を組版時に取得し、PDF内部リンクとして保持できる可能性がある。この範囲を技術検証の対象とした。

## 技術検証

調査結果を再検証できるように、[検証用fixture](fixtures/vivliostyle-index/)をリポジトリ内へ保存している。このfixtureはclono本体から独立したnpmプロジェクトであり、`package.json`と`package-lock.json`によって検証環境の依存関係を固定する。

fixtureでは、表紙相当、第1章、第2章、索引、後付の5文書を一冊として構成した。第1章と第2章へ11個の索引指定を配置し、clonoの変換後を模した索引文書を本文の後、後付の前へ置いた。

### 本文中の索引マーカー

本文中の索引指定は、出現ごとに一意なID、表示語、読みを持つ`span`へ変換された状態を模した。

```html
<span
  id="index-backnumber-1"
  class="index-marker"
  data-index-term="バックナンバー"
  data-index-reading="ばっくなんばー"
>バックナンバー</span>
```

VFMはこの構造と属性を保持した。索引語の表示内容は指定した語だけになり、索引用の追加情報は紙面へ表示されなかった。通常の本文と、HTMLの`aside`で模したコラムのどちらでも、索引語を周囲と同じ見た目で表示できた。

このfixtureはコラムの著者向け記法や最終的な出力構造を決定するものではない。コラム内でも通常のインライン要素として索引マーカーを保持できることだけを確認した。

### 索引文書の構造

索引文書は、clonoが生成する候補となるHTML構造を原稿へ直接記述した。分類は「英数字」「あ行」「か行」「さ行」「は行」とし、各項目へ表示語、読み、正規化済みのソートキー、すべての出現位置へのリンクを持たせた。

```html
<div
  class="index-entry"
  data-index-term="バックナンバー"
  data-index-reading="ばっくなんばー"
  data-index-sort-key="はつくなんはあ"
>
  <dt>バックナンバー</dt>
  <dd><a class="index-page" href="chapter-two.html#index-backnumber-1"></a></dd>
</div>
```

この構造はVFM変換後のWeb出版物にも保持された。Web出版物の自動検証では、次を確認した。

- 本文とコラム内の11個の索引マーカーがID、表示語、読みを保持する
- 索引の分類と項目が定義した順序で出力される
- 各索引項目が読み、正規化済みソートキー、すべての出現位置を保持する
- 各リンクの完全な`documentPath#targetId`が期待値と一致し、リンク先のHTML文書に索引マーカーIDが存在する
- 索引が本文の後、後付の前に配置される

このfixtureは読みの正規化、分類、並べ替えを実行するアルゴリズムを検証しない。あらかじめ与えた正規化済みソートキーと順序をVFMが壊さず、Vivliostyleで組版できることを検証する。

### ページ番号とPDF内部リンク

索引の各リンクを空の`a`要素とし、CSSの`target-counter()`でリンク先の`page`カウンターを表示した。

```css
.index-page::after {
  content: target-counter(attr(href url), page);
}
```

生成したPDFは5ページとなり、全ページの下部中央へ1から5まで連続するノンブルを表示した。自動検証では、各ページ番号と一致し、かつページ下部10%以内かつ水平中央からページ幅の5%以内にあるテキストブロックが一つ存在することを確認した。索引は4ページ目に1ページで収まり、11件のリンクへそれぞれ期待する出現ページの番号を表示できた。

PDFの自動検証では、11件のリンクについて次を個別に確認した。

- 期待するページ番号が表示される
- 期待する索引マーカーIDを参照する
- 期待するページへ解決される
- リンク先の座標が索引語を含む本文付近にある
- 同じ索引項目のページ番号が同じ行に定義順で並ぶ
- 索引語、区切り、すべてのページ番号を含む索引行全体が期待する表示と一致する

生成したPDFは全5ページを画像へ変換し、本文、コラム、分類見出し、索引語、ページ番号に欠落、重なり、意図しない改行がないことを目視確認した。

## 同一ページ重複の検証

第1章には`Android`を同じページへ二回配置し、第2章へもう一回配置した。索引文書には三つの出現位置をすべて列挙した。

Vivliostyleは各リンク先のページ番号を正しく取得し、索引へ`2, 2, 3`と表示した。最初の二つは同じページ番号だが、それぞれ異なる本文マーカーへ移動する独立したPDF内部リンクになった。`target-counter()`はページ番号を生成するが、同じページ番号を持つ参照を自動的には統合しなかった。

clonoはVivliostyleによる組版前にMarkdownを変換するため、その時点では各索引マーカーの最終的なページ番号を知らない。したがって、通常の事前変換だけでは「同じページにある出現位置を一つへまとめる」という要件を判定できない。

この問題については、次の対応候補がある。

- 同一ページの重複表示を許容するよう要件を変更する
- Vivliostyleの組版結果を利用する二段階または組版後の処理を設ける
- Vivliostyleと連携し、組版結果を索引生成へ戻せる拡張方法を調査する

初期仕様では最初の候補を採用し、同一ページ番号の重複表示を許容する。索引の目的を考えると、近い位置にある同じ語を索引対象として繰り返し指定する必要性は低く、前身のビルドスクリプトでも重複表示を許容した状態で書籍制作が成立していたためである。

この判断は、同じ索引項目の複数の出現を一つの索引項目へまとめる機能を外すものではない。clonoはすべての出現位置を一つの索引項目へ列挙し、Vivliostyleは各出現位置のページ番号とリンクを生成する。同じページに複数の出現がある場合だけ、`2, 2, 3`のような表示を既知の制約として受け入れる。

初期仕様では、同一ページ重複の除去を目的とする二段階組版、組版後処理、Vivliostyleとの追加連携を導入しない。Thunder Clawの実原稿で重複表示が索引の可読性を損なうと確認された場合に、必要性と実装方式を改めて調査する。

## 調査結果

- VFMとVivliostyle CLIの文書化された公開インターフェースには、要件を満たす索引記法や索引自動生成設定は確認できない
- 本文とコラム内の索引マーカーは、VFM変換後もID、表示語、読みを保持できる
- 生成済みの分類、項目、読み、ソートキー、出現位置を持つ索引構造をVFMが保持できる
- VivliostyleとテーマCSSへ、紙面上のページ番号生成とPDF内部リンクを委譲できる
- 同じ項目の複数の出現位置を一つの索引項目へ列挙できる
- `target-counter()`は同一ページにある複数の参照を自動的に統合せず、`2, 2`のように表示する
- 同一ページ重複の除去は最終的なページ番号に依存するため、組版前のclonoだけでは判断できない

## 責務判断

索引項目の指定、収集、読みの正規化、分類、並べ替え、項目の統合、出現位置の管理、索引文書の構造生成はclonoが担う候補とする。Vivliostyleへ索引の自動生成を期待しない。

生成済み索引の紙面レイアウト、各出現位置のページ番号生成、PDF内部リンクは、VivliostyleとテーマCSSへ委譲する。

初期仕様では同一ページ番号の重複表示を許容し、その除去をclono、VFM、Vivliostyleのいずれの責務にも含めない。

### Vivliostyleへ委譲する責務

- 本文中の索引マーカーと属性を保持する
- 生成済みの分類、索引項目、出現位置へのリンクを持つ索引構造を組版する
- `target-counter()`で各出現位置の紙面上のページ番号を生成する
- 各ページ番号を、対応する索引マーカーへのPDF内部リンクとして保持する
- テーマCSSに従って分類見出し、索引語、ページ番号を表示する

### clonoが担う候補となる責務

- 索引語と読みを指定できる著者向け記法を提供する
- 著者向け記法を、一意なID、表示語、読みを持つ索引マーカーへ変換する
- 読みを索引用に正規化する
- 英数字と五十音の行へ分類し、正規化済みの読みで項目を並べ替える
- 同じ索引項目を一つへまとめ、すべての出現位置を管理する
- 分類、表示語、読み、ソートキー、出現位置へのリンクを持つ索引文書を生成する
- 読みの不足、不正な指定、IDの重複などを診断する候補とする

## 成立条件と未確認事項

今回の結果は、索引項目とすべての出現位置を持つ索引構造が、Vivliostyleによる組版前に生成されていることを前提とする。

次の事項は未確認または未決定である。

- 読みを正規化する具体的なアルゴリズムと例外
- 英数字の大文字・小文字、記号、全角文字を含む場合のソート規則
- 空の分類見出しを表示するか
- 索引マーカーがページをまたぐ場合のリンク先
- 脚注、画像・表・コードリストのキャプション内の索引指定
- 階層索引、ページ範囲、索引項目間の相互参照、主要ページの強調
- Thunder Clawの実際の項目数を含む複数ページの索引
- 目次、脚注、図、表、コードリスト、索引を同じ書籍へ配置した結合結果
- 製品用テーマにおける索引の紙面レイアウト

階層索引、ページ範囲、索引項目間の相互参照、主要ページの強調は、Thunder Clawの次回作における要件ではないため、具体的な必要性が高まるまで調査しない。

## 再調査する条件

- VFMに索引項目を指定する構文が追加された場合
- Vivliostyle CLIに索引を収集・生成する設定が追加された場合
- VFMが索引マーカーまたは生成済み索引のHTML構造を保持できなくなった場合
- Vivliostyle.jsの`target-counter()`、ページカウンターまたはPDF内部リンクの実装が変更された場合
- 同一ページ重複を除去する要件または許容範囲が変わった場合
- clonoの処理を組版後まで拡張する設計候補を検討する場合
- Thunder Clawの実際の原稿や製品用テーマで、分類、項目、ページ番号またはリンクが期待どおりにならなかった場合
