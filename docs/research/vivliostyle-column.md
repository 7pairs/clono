# Vivliostyleのコラム表現に関する調査

- 状態: 調査済み
- 調査日: 2026-08-20
- 検証環境:
  - 実行環境: macOS、Node.js 24.19.0
  - HTML変換: `@vivliostyle/vfm` 2.7.0
  - PDF生成: `@vivliostyle/cli` 11.1.0
    - CLIが依存する`@vivliostyle/vfm` 2.7.0
    - CLIが使用するVivliostyle.js 2.44.1
  - PDF検証: `mupdf` 1.28.0
  - PDFに埋め込まれたフォント: ヒラギノ角ゴ ProN W3およびW6、Osaka-Mono

## 背景

Thunder Clawでは、本文から独立した雑談や補足をコラムとして囲み枠へ表示する。前身のビルドスクリプトでは、独自記法を`div.column`へ変換していた。

コラムは次回作でも必須である。また、[脚注の調査](vivliostyle-footnotes.md)では、コラム内から参照した脚注を本文と同じページ下部へ出力できるか未確認だった。現在のVFMとVivliostyleへ委譲できる範囲と、clonoが担うべき構造変換を判断するため、コラム単体と脚注との結合を調査した。

著者向け記法と最終的なHTML出力契約は、この調査では決定しない。

## Thunder Clawの要件

### コラムの構造

- 初期仕様では一種類のコラムを扱う
- プレーンテキストのタイトルを必須とする
- タイトルを目次へ掲載する必要はない
- 複数段落を含められる
- コラムの入れ子、ID参照、連番は初期要件に含めない

### 内部のMarkdown

次を必須とする。

- 強調
- インラインコード
- リンク
- 箇条書き
- 番号付きリスト
- 脚注

次は可能であれば対応する。

- コードブロック
- 画像
- 表

見出しは初期要件に含めない。

### ページ分割

- 一ページに収まるコラムは、可能な限り同じページへまとめる
- 一ページに収まらないコラムは、複数ページへの分割を許容する
- 分割後のページでタイトルを繰り返さない
- 枠線、背景色、余白、分割位置などの外観はテーマCSSで決定する

### 脚注との結合

- コラム内でVFMのPandoc風脚注記法を使用する
- コラム内から参照した脚注本文を、コラムの枠内ではなく参照ページの下部へ出力する
- 本文とコラムの脚注を参照順に連番とする
- 章が変わった場合は脚注番号を1へ戻す
- 脚注内のインラインコードとリンクを保持する

## 公式情報と出力候補

VFM 2.7.0は、原稿へ記述したHTMLを保持し、HTML要素の内側に空行を置くことで内部のMarkdownも変換できる。コラムの変換後候補として、補足的な内容を表す`aside.column`を使用した。タイトルは目次へ掲載される見出しとして扱われないよう、`p.column-title`とした。

```html
<aside class="column">

<p class="column-title">コラムのタイトル</p>

コラムの本文。

</aside>
```

VFMの`dpub`脚注モードは、Pandoc風脚注記法から`role="doc-noteref"`を持つ参照と、`aside[role="doc-footnote"]`を生成する。Vivliostyle.jsはこの構造を脚注として認識し、脚注本文を参照ページの下部へ配置できる。

Vivliostyle.jsは、囲み枠に使用する枠線、背景、余白と、分割制御に使用する`break-inside`を扱える。コラムの構造と内部のMarkdownをVFMから受け取り、紙面上の外観とページ分割をテーマCSSへ委譲できる可能性がある。

## 技術検証

調査結果を再検証できるように、[検証用fixture](fixtures/vivliostyle-column/)をリポジトリ内へ保存している。このfixtureはclono本体から独立したnpmプロジェクトであり、`package.json`と`package-lock.json`によって検証環境の依存関係を固定する。

fixtureは二つのMarkdownファイルを一章ずつVivliostyle CLIの`entry`へ登録し、次のコラムを配置する。

- 必須のインライン要素、リスト、脚注を含む短いコラム
- コードブロック、画像、Markdown表を含む短いコラム
- 30個の段落を含み、複数ページへ分割される長いコラム
- 第2章での脚注番号リセットを確認するコラム

HTMLの検証プログラムは、次を自動で確認する。

- `aside`のIDとclass、および必須のプレーンテキストタイトルが保持される
- コラムタイトルが見出しにならない
- 強調、インラインコード、リンク、箇条書き、番号付きリストがHTMLへ変換される
- 構文強調付きコードブロック、画像、Markdown表がHTMLへ変換される
- コラム内脚注を含め、各章の脚注が参照順に連番となる
- 脚注本文がコラムの外に生成される
- 脚注内のインラインコードとリンクが保持される
- 第2章の脚注番号が1へ戻る

PDFの検証プログラムは、既存のPDFを削除してからVivliostyle CLIで再生成し、次を自動で確認する。

- PDFが空でなく、一ページ以上を持つ
- 二つの短いコラムが、それぞれタイトルから末尾まで一つのページに収まる
- 長いコラムが複数ページへ分割され、タイトルは一度だけ表示される
- 長いコラムの開始、中間、末尾の内容が欠落しない
- 本文とコラムから参照した脚注が、それぞれの参照ページで本文より下にまとまり、本文領域から分離される
- 五つの脚注参照と五つの戻りリンクが、すべて対応する対象へ解決される
- コラム内と脚注内の外部リンクがPDFへ保持される
- 第2章の脚注番号が1へ戻り、コラム内脚注へ2として連続する

検証済み環境で生成したPDFは5ページとなった。全ページを画像へ変換し、枠線、背景色、余白、コード、画像、表、脚注に欠落、重なり、意図しない改行がないことを目視確認した。長いコラムのページ境界でも内容の欠落や重複はなく、続きのページにタイトルは表示されなかった。

テーマCSSは汎用ファミリーの`sans-serif`を使用するため、別のOSでは解決されるフォント、改行位置、総ページ数が異なる可能性がある。責務判断は5ページという結果や脚注の絶対座標に依存させず、コラム内の要素同士とページ間の相対関係によって検証する。

## 検証結果

### 内部のMarkdown

VFMは`aside.column`と`p.column-title`を保持し、内部の複数段落、強調、インラインコード、リンク、箇条書き、番号付きリストをHTMLへ変換した。初期要件では任意としたコードブロック、画像、Markdown表も同じコラム内で変換できた。コードブロックには構文強調が適用された。

したがって、初期要件に必要な本文要素と、今回確認した任意要素のMarkdown解析およびHTML変換はVFMへ委譲できる。

### ページ分割と外観

検証済み環境では、二つの短いコラムが、それぞれ一ページの中へタイトルから末尾まで配置された。一ページに収まらない長いコラムは二ページへ分割され、タイトルは最初のページに一度だけ表示された。

枠線、背景色、余白、`break-inside: avoid`をテーマCSSで指定し、コラムの外観と分割をVivliostyleへ反映できた。今回の短いコラムはページ末尾の残り領域へ置く能力プローブではないため、ページ末尾に収まらない短いコラムを常に次ページへまとめて移動できることまでは確認していない。

### コラム内脚注

第1章で、本文、コラム、本文の順に脚注を参照した。VFMが生成した参照番号は`1`、`2`、`3`となり、コラムから参照した脚注本文は`aside.column`の外へ生成された。Vivliostyleは三つの脚注本文を同じ参照ページの下部へ配置した。

第2章では、本文の脚注が`1`、コラム内の脚注が`2`となった。一章を一つのMarkdownファイルとして別々の`entry`へ登録する構成では、本文とコラムの区別なく参照順に連番となり、章ごとに1へ戻る。

すべての脚注参照と戻りリンクはPDF内部リンクとして対応する対象へ解決された。コラム本文と脚注本文の外部リンクもPDFへ保持された。脚注内のインラインコードはWeb出版物とPDFの両方に表示された。

## 責務判断

コラムの内部にあるMarkdownの解析、HTML変換、Pandoc風脚注から`dpub`脚注構造への変換はVFMへ委譲する。囲み枠の外観、ページ分割、脚注のページ下部への配置はVivliostyleとテーマCSSへ委譲する。

clonoは、コラムを指定する著者向け記法を、必須タイトルと本文を保持できる用途別のコンテナへ変換する責務を担う候補とする。原稿中の脚注記法は独自のHTMLへ変換せず、VFMが解釈できる形を維持する。

### VFMとVivliostyleへ委譲する責務

- コラム内部のMarkdownをHTMLへ変換する
- Pandoc風脚注記法を`dpub`脚注構造へ変換する
- テーマCSSに従って枠線、背景色、余白とページ分割を紙面へ反映する
- 本文とコラムの脚注を参照順に連番とし、参照ページの下部へ配置する
- 一章一ファイルの構成で、章ごとに脚注番号を1へ戻す
- 脚注参照、戻りリンク、外部リンクをPDFのリンクとして保持する

### clonoが担う候補となる責務

- コラムと必須タイトルを指定できる著者向け記法を提供する
- 著者向け記法を、タイトルと複数のブロックを保持できるコラム用コンテナへ変換する
- タイトルが存在し、初期仕様で許可するプレーンテキストであることを検証する
- 内部のMarkdownとPandoc風脚注記法を壊さずVFMへ渡す
- 閉じられていないコラム、入れ子、初期仕様で許可しない見出しなどを診断する候補とする

## 成立条件と未確認事項

脚注番号の章ごとのリセットは、一つのMarkdownファイルを一つの章として別々の`entry`へ登録する構成を前提とする。

今回使用した`aside.column`、`p.column-title`、class名は、Vivliostyleへ渡す候補を検証するものであり、clonoの最終的な出力契約ではない。枠線、背景色、余白も製品用テーマのデザインではない。

次の事項は未確認または未決定である。

- 著者向け記法と最終的なHTML出力契約
- ページ末尾に収まらない短いコラムを次ページへまとめて移動する場合の詳細
- 複数種類のコラムと種類ごとのデザイン
- コラム内の見出し、入れ子、ID参照、連番
- コラムの途中にある脚注がページをまたぐ長さになった場合
- 製品用テーマの枠線、背景色、余白、分割位置

複数種類のコラム、見出し、入れ子、ID参照、連番はThunder Clawの次回作における初期要件ではないため、具体的な必要性が高まるまで調査しない。

## 再現方法

検証に使用する入力、Web出版物とPDFの自動検証、PDFの目視確認手順は、[検証用fixtureのREADME](fixtures/vivliostyle-column/README.md)を参照する。fixture内で`npm ci`を実行した後、`npm run verify`で再検証できる。

## 再調査する条件

- VFMがraw HTML、HTML内のMarkdownまたは`dpub`脚注の出力契約を変更した場合
- Vivliostyle.jsの枠線、背景、余白、`break-inside`または脚注組版の実装が変更された場合
- コラムの著者向け記法または最終的なHTML出力契約を決定する場合
- 複数種類、見出し、入れ子、ID参照、連番など、初期要件外の機能が必要になった場合
- Thunder Clawの実原稿や製品用テーマで、ページ分割、外観または脚注配置が期待どおりにならなかった場合
