# Vivliostyleの基本表現機能に関する調査

- 状態: 調査済み
- 調査日: 2026-08-20
- 検証環境:
  - 実行環境: macOS、Node.js 24.19.0
  - HTML変換: `@vivliostyle/vfm` 2.7.0
  - PDF生成: `@vivliostyle/cli` 11.1.0
    - CLIが依存する`@vivliostyle/vfm` 2.7.0
    - CLIが使用するVivliostyle.js 2.44.1
  - PDF検証: `mupdf` 1.28.0

## 背景

Thunder Clawの前作では、通常のMarkdownだけでは表現できなかった空行、強制改ページ、段落の右寄せ、定義リストを、独自記法からHTMLへ変換していた。強制改行にも独自記法を用意していた。

現在のVFMとVivliostyleへ委譲できる範囲と、clonoによる変換が必要な範囲を判断するため、コラム以外の基本的な表現機能をまとめて調査した。著者向けの独自記法は、この調査では決定しない。

## Thunder Clawの要件

### 空行

- ブロック間へ一行相当の意図的な空白を表示できる
- 連続する空行と、ページ先頭または末尾にある空行の扱いは問わない
- 前身で使用した`<p><br></p>`という出力形式にはこだわらない

### 強制改行

- 段落内の指定位置で改行できる
- 現時点では次回作に不要であり、VFMの標準記法で実現できる場合はclono独自の記法を追加しない

### 強制改ページ

- 指定位置より後の任意のブロックを次ページの先頭から開始する
- 改ページを示す線や記号を紙面へ表示しない
- 前身で使用した`hr`要素とインラインstyleにはこだわらない

### 段落の右寄せ

- 装飾のない段落を右寄せできる
- 日付と名前など、複数の段落を一つの右寄せブロックへ含められる
- 強調、インラインコード、リンクへの対応は必須としない

### 定義リスト

- 一つの用語と一つの説明を表示できる
- 説明内で基本的なインラインMarkdownを使用できる
- 複数の用語または説明、複数段落、入れ子は初期要件に含めない

## 公式情報と標準記法の確認

VFM 2.7.0は、通常のMarkdownからのHTML変換に加えて、空白を必要とせず改行位置へ`br`を追加する`hardLineBreaks`オプションを提供する。また、そのまま記述したHTMLを保持し、HTMLの内側に空行を置くことで内部のMarkdownも変換できる。

技術検証では、VFM固有のオプションを有効にしない状態でも、標準Markdownの行末にバックスラッシュを置くことで`br`へ変換できた。このため、今回の強制改行要件にVFM固有のオプションやclonoの変換は必要ない。

通常のMarkdownに複数の空行を記述した場合、VFMは前後の文章を別々の`p`要素へ変換するが、空行自体を可視の要素として出力しなかった。空行の数も出力へ保持されないため、意図的な一行分の空白には別の構造が必要となる。

VFM 2.7.0の文書化された記法には定義リストがなく、次のような定義リスト風のMarkdownも、技術検証では一つの通常段落へ変換された。

```markdown
用語
: 説明
```

一方、原稿へ直接記述した`dl`、`dt`、`dd`は保持され、`dd`の内側に置いたインラインコード、強調、リンクは、それぞれ`code`、`strong`、`a`へ変換された。

Vivliostyle.jsは、CSSの`text-align`、寸法、改ページに使用する`break-before`を扱える。VFMが保持した用途別のHTML構造へclassを付け、見た目と改ページをテーマCSSへ委譲できる。

## 技術検証

調査結果を再検証できるように、[検証用fixture](fixtures/vivliostyle-basic-presentation/)をリポジトリ内へ保存している。このfixtureはclono本体から独立したnpmプロジェクトであり、`package.json`と`package-lock.json`によって検証環境の依存関係を固定する。

fixtureは、標準Markdownの強制改行と、clonoによる変換後を模した次のHTML構造を一つの原稿へ記述する。

- `blank-line`クラスを持つ空の`div`
- `text-align-right`クラスを持ち、二つの段落を含む`div`
- `definition-list`クラスを持つ`dl`、`dt`、`dd`
- `page-break`クラスを持つ空の`div`

空の要素には`aria-hidden="true"`を付け、紙面上の見た目は持つが内容を持たないことを示す。class名と要素構造は検証用の候補であり、clonoの最終的な出力契約ではない。

HTMLの検証プログラムは、VFM変換後に次の内容が保持されることを確認する。

- 標準Markdownの強制改行が、一つの`p`要素内にある一つの`br`へ変換される
- 空行、右寄せ、定義リスト、二つの改ページマーカーのID、class、`aria-hidden`、要素構造
- 右寄せコンテナ内にある日付と名前の二つの段落
- 定義の説明内にあるインラインコード、強調、リンク
- 改ページマーカーが、それぞれ後続の見出しまたは通常段落より前にある

PDFの検証プログラムは、既存のPDFを削除してからVivliostyle CLIで再生成し、次の内容を確認する。

- 二つの強制改ページによってPDFが3ページになる
- 強制改行の前後が、同じ開始位置を持つ別々の行になる
- 空行を挟んだ段落間の垂直方向の空きが、通常の段落間より10pt以上広い
- 日付と名前の右端が2pt以内の差で揃い、左寄せの基準より右側へ配置される
- 定義の説明が用語より15pt以上字下げされる
- 改ページ前の段落が1ページ目、後続の見出しが2ページ目、別の改ページ後の通常段落が3ページ目に配置される
- 改ページ後の見出しと通常段落が、それぞれページ上端から70pt以内に配置される

生成したPDFは全3ページを画像へ変換し、強制改行、空行、右寄せ、定義リストに欠落、重なり、意図しない改行がないことを目視確認した。二つの改ページでは線や記号が表示されず、見出しと通常段落がそれぞれ新しいページの先頭付近に配置された。

## 検証結果

### 空行

空の`div.blank-line`にCSSで一行相当の`block-size`を指定することで、通常の段落間より広い空白を表示できた。VFMは空の要素、ID、class、`aria-hidden`を保持した。

通常のMarkdownの空行は可視の空白として保持されないため、意図的な空行には著者向け記法と、空白用の構造への変換が必要である。空白の寸法と紙面上の表示はテーマCSSへ委譲できる。

### 強制改行

標準Markdownのバックスラッシュによる強制改行を、VFMが`br`へ変換した。生成したPDFでも、改行前後の文章が同じ段落内の別々の行へ表示された。

Thunder Clawの要件には標準Markdownで対応できるため、clono独自の強制改行記法や変換を追加する必要はない。

### 強制改ページ

空の`div.page-break`へ`break-before: page`を適用することで、後続の見出しと通常段落をそれぞれ新しいページから開始できた。空のマーカーには紙面上の線や記号が表示されなかった。

改ページのタイミングはVivliostyleとテーマCSSへ委譲できる。一方、通常のMarkdownだけでは意図的な改ページを表現できないため、著者向け記法と、改ページ用の構造への変換はclonoが担う候補となる。

### 段落の右寄せ

二つの`p`要素を含む`div.text-align-right`へ`text-align: right`を適用し、日付と名前を別々の段落として右寄せできた。VFMは外側のコンテナと内側のMarkdown段落を保持した。

文字揃えはテーマCSSへ委譲できる。一方、複数段落を一つの右寄せ範囲として指定する著者向け記法と、その範囲を意味のあるコンテナへ変換する処理はclonoが担う候補となる。

### 定義リスト

VFMは、そのまま記述した`dl`、`dt`、`dd`を保持し、説明内のインラインMarkdownを変換した。VivliostyleとテーマCSSにより、説明を用語より字下げして表示できた。

VFM 2.7.0の標準記法だけでは定義リストを生成できないため、著者向け記法と、`dl`、`dt`、`dd`への構造変換はclonoが担う候補となる。定義内のインラインMarkdownの解析とHTML変換はVFMへ委譲できる。

## 責務判断

強制改行は標準MarkdownとVFMへ完全に委譲する。clonoは記法を壊さず後段へ渡し、独自記法や変換を実装しない。

空行、強制改ページ、段落の右寄せ、定義リストは、変換後の用途別のHTML構造をVFMが保持し、VivliostyleとテーマCSSで要件を満たせる。著者向け記法と構造変換はclonoが担う候補とし、紙面上の寸法、改ページ、文字揃え、字下げはVivliostyleとテーマCSSへ委譲する。

### VivliostyleとVFMへ委譲する責務

- 標準Markdownの強制改行を`br`へ変換する
- HTML構造、ID、class、`aria-hidden`と、HTML内のMarkdownを保持または変換する
- テーマCSSに従って、空白の寸法、改ページ、文字揃え、定義リストの字下げを紙面へ反映する

### clonoが担う候補となる責務

- 意図的な空行を指定する著者向け記法を、空白用の構造へ変換する
- 強制改ページの著者向け記法を、改ページ用の構造へ変換する
- 右寄せする範囲を指定する著者向け記法を、複数段落を保持できるコンテナへ変換する
- 定義リストの著者向け記法を、`dl`、`dt`、`dd`へ変換する
- 変換対象の内容と内部のMarkdownを壊さず、VFMへ渡す
- 不正な属性、内容を持てない記法、閉じられていない範囲などを診断する

## 成立条件と未確認事項

今回使用したclass名とHTML構造は、Vivliostyleへ渡す候補を検証するものであり、clonoの最終的な出力契約ではない。

次の事項は未確認または未決定である。

- 各機能の著者向け記法と属性
- 空行の連続指定、ページ先頭または末尾にある空行の扱い
- 強制改ページを連続して指定した場合と、既にページ先頭にある場合の扱い
- 右寄せブロック内の強調、インラインコード、リンク、複雑なブロック要素
- 複数の用語または説明、複数段落、入れ子を持つ定義リスト
- 製品用テーマで使用するclass名、寸法、余白、改ページ、文字揃え

要件で優先度を下げた事項は、Thunder Clawの次回作で具体的な必要性が生じるまで調査しない。
