# VivliostyleのコードリストID・キャプション・連番・相互参照に関する調査

- 状態: 調査済み
- 初回調査日: 2026-08-17
- 最終更新日: 2026-08-17
- 検証環境:
  - 実行環境: macOS、Node.js 24.19.0
  - HTML変換: `@vivliostyle/vfm` 2.7.0
  - PDF生成: `@vivliostyle/cli` 11.1.0
    - CLIが依存する`@vivliostyle/vfm` 2.7.0
    - CLIが使用するVivliostyle.js 2.44.1
  - PDF検証: `mupdf` 1.28.0

## 背景

Thunder Clawの前作では、コードリストへ参照用ID、任意のキャプション、章番号を含む連番を付与し、別の場所から番号または番号とタイトルを参照する処理を独自のビルドスクリプトで実装していた。

VFMはコードフェンスの言語とキャプションを扱えるが、前作の執筆時にはコードリスト全体へ参照用IDを付ける方法を確認できなかった。このため、前身のビルドスクリプトはIDを持つ`div`要素でコードを囲んでいた。

現在のVFMとVivliostyleへ委譲できる範囲と、clonoによる変換が必要な範囲を判断するため、コードリストのID、キャプション、連番、同一Markdownファイル内および別Markdownファイル間の相互参照を調査した。複数ページにまたがるコードリストも対象に含めた。

## Thunder Clawの要件

- 番号を付けるコードリストと、本文中の短い番号なしコードブロックを区別できることが望ましい
- 番号付きコードリストへ安定した参照用IDと任意のキャプションを付けられる
- リスト番号は章ごとにリセットし、`リスト1.1`、`リスト1.2`、`リスト2.1`の形式にする
- 図、表、コードリストはそれぞれ独立した連番を使用する
- キャプションはコードの上へ配置する
- 番号とキャプションを参照する場合は、`リスト1.1 挨拶を表示する関数`のように番号、半角スペース、キャプションの順で表示する
- 同一Markdownファイル内だけでなく、別Markdownファイルのコードリストも参照できる
- 製品となるPDFで参照をクリックし、対象のコードリストへ移動できる
- 言語を指定したコードの構文強調を、可能であれば維持する
- 長いコードリストを複数ページへ分割できる
- 長いコードリストのキャプションは最初に一度だけ表示し、継続ページでは繰り返さない
- 行番号はあれば望ましいが、今回の必須要件には含めない

## 公式情報の確認

VFMは、言語を指定したコードフェンスをHTMLの`pre`と`code`へ変換し、Prismを使用して構文強調用の要素とclassを生成する。

コードフェンスで`kotlin:Main.kt`または`kotlin title=Main.kt`のように指定すると、VFMは`figure`、`figcaption`、`pre`、`code`を生成し、キャプションをコードの上へ配置する。

VFMは、そのまま記述したHTMLの内側に空行を置くことで、内側のMarkdownもHTMLへ変換できる。この仕組みを利用すると、IDとclassを持つ`figure`の内側で通常のコードフェンスを構文強調し、ファイル名に限定されない任意のキャプションを別の`figcaption`として保持できる。

VivliostyleはCSSカウンター、`target-counter()`、`target-text()`に対応している。章番号には、見出し、画像、表の調査と同じく、`@page :first`による初期化と`@page :nth(1)`による原稿ファイルごとのインクリメントを利用できる。

## 技術検証

調査結果を再検証できるように、[検証用fixture](fixtures/vivliostyle-code-listing-references/)をリポジトリ内へ保存している。このfixtureは`clono`本体から独立したnpmプロジェクトであり、`package.json`と`package-lock.json`によって検証環境の依存関係を固定する。

fixtureでは、第1章と第2章を別々のMarkdownファイルに記述し、Vivliostyle CLIの`entry`へ章順に登録する。第1章には番号付きコードリスト二つと番号なしコードブロック一つを、第2章には複数ページにまたがる番号付きコードリスト一つを配置する。

clonoの著者向けコードリスト記法は未決定であるため、番号付きコードリストにはclonoによる変換後を模したHTMLの外枠とコードフェンスを原稿へ直接記述する。

````markdown
<figure class="numbered-listing" id="listing-greeting">
<figcaption id="listing-greeting-caption">挨拶を表示する関数</figcaption>

```kotlin
fun greet(name: String): String {
    return "Hello, $name!"
}
```
</figure>
````

番号なしコードブロックには、通常のコードフェンスを使用する。

参照元には、変換後の出力を模した空の`a`要素を直接記述する。番号とタイトルを参照する要素は、クリック先と番号の取得に使用する`href`と、キャプションの取得に使用する`data-caption-href`を別々に持つ。

```html
<a class="xref-listing xref-title"
   href="chapter-two.html#listing-device-properties"
   data-caption-href="chapter-two.html#listing-device-properties-caption"></a>
```

HTMLの検証プログラムは、VFM変換後の番号付きコードリストが、`figure`のIDとclass、IDを持つ`figcaption`、構文強調された`pre`と`code`を保持することを確認する。通常のシェルコードブロックが番号付きの`figure`で囲まれないことと、長いコードリストの検証行が一度ずつ順番どおりに出力されることも確認する。

PDFの検証プログラムは、既存のPDFを削除してからVivliostyle CLIで再生成し、次を自動で確認する。

- 番号付きコードリストのリスト番号とキャプションが期待する文字列で出力される
- 番号なしコードブロックが表示され、リストカウンターを消費しない
- 同一Markdownファイル内と別Markdownファイル間の参照文字列が出力される
- 四つの論理的なコードリスト参照がそれぞれ期待するコードリストIDを参照する
- 各参照が、期待するキャプションと同じページにあるキャプション付近の座標へ解決される
- すべてのPDF内部リンク注釈が、検証対象のいずれか一つの論理的なコードリスト参照に属する
- 長いコードリストの60個の検証行が、一度ずつ順番どおりに出力される
- 長いコードリストの先頭行と末尾行が異なるページにある
- キャプションと先頭行が同じページにあり、末尾行のページではキャプションが繰り返されない

生成したPDFは全3ページを画像へ変換し、コード、構文強調、見出し、キャプション、本文の欠落や重なりがないことも目視確認した。

### 番号付きコードリストと番号なしコードブロック

番号付きコードリストだけに`numbered-listing`クラスを付け、次のCSSでリストカウンターをインクリメントした。

```css
body {
  counter-reset: listing;
}

.numbered-listing {
  counter-increment: listing;
}
```

通常のシェルコードブロックを二つの番号付きコードリストの間へ配置した結果、番号付きコードリストは`リスト1.1`、`リスト1.2`となり、番号なしコードブロックはリストカウンターを消費しなかった。第2章の最初の番号付きコードリストは`リスト2.1`となり、章ごとのリセットも確認できた。

リストカウンターには`listing`という固有の名前を使用する。図の`figure`、表の`table`とは異なる名前であり、個別のfixtureではそれぞれ独立して動作した。ただし、三種類を同じ文書へ配置した結合テストはまだ実施していない。

### ID、キャプション、構文強調

番号付きコードリストの参照用IDと`numbered-listing`クラスを`figure`へ付け、その内側へタイトル参照用IDを持つ`figcaption`と通常のコードフェンスを配置した。

VFMは外側の`figure`と`figcaption`を保持し、コードフェンスをKotlinの構文強調用classを持つ`pre`、`code`、`span`へ変換した。fixtureのCSSによって、キーワード、関数名、文字列を異なる色でPDFへ表示できた。

キャプションをコードフェンスの前に配置することで、`リスト1.1 挨拶を表示する関数`の形式でコードの上へ表示できた。キャプションはファイル名に限定されず、任意の説明文を使用できた。

VFM標準のキャプション付きコードフェンスでも`figure`と`figcaption`は生成できる。一方、今回の要件を満たす番号付きコードリストの出力契約としては、表全体のID、用途別のclass、タイトル参照用IDを明示した構造へclonoが変換する方法が明確である。

### 番号とキャプションの参照

`target-counter()`を使用し、参照先の章番号とリスト番号を取得できた。

コードリスト全体の`figure`にはキャプションだけでなくコード本文も含まれる。表の調査と同じく、番号とクリック先には`figure`のIDを使用し、タイトル取得には`figcaption`の別IDを使用する構造とした。

```css
a.xref-listing::before {
  content: "リスト" target-counter(attr(href url), chapter) "." target-counter(attr(href url), listing);
}

a.xref-title::after {
  content: " " target-text(attr(data-caption-href url), content);
}
```

この構造により、リンクはコードリスト全体を表す`figure`への内部リンクとして解決され、参照文字列には`リスト1.1 挨拶を表示する関数`のように番号とキャプションだけを表示できた。

### 別Markdownファイル間の参照

変換後のHTMLファイル名とコードリストIDを組み合わせた`chapter-two.html#listing-device-properties`のような`href`と、キャプションIDを組み合わせた`data-caption-href`を使用し、別Markdownファイルの番号とキャプションを参照できた。

生成したPDFでは、同一ファイル内、別ファイル間、前方参照、後方参照のすべてが、対象のコードリスト全体を表す`figure`への内部リンクとして解決された。

### 複数ページにまたがるコードリスト

`numbered-listing`と`pre`へ`break-inside: auto`を指定することで、60個の検証行を含むコードリストを二つのページへ分割できた。最初のページにはキャプションと先頭行から31番目までが表示され、継続ページには32番目から60番目、閉じ括弧が表示された。

`figcaption`へ`break-after: avoid`を指定し、キャプションとコード先頭を同じページへ配置できた。キャプションは最初のページだけに一度表示され、継続ページでは繰り返されなかった。すべての検証行が一度ずつ順番どおりに出力され、改ページによる欠落、重複、順序の崩れはなかった。

## 責務判断

コードリストの構文強調、連番、キャプション表示、ページ分割、番号参照、番号とキャプションの参照は、VFM、VivliostyleおよびテーマCSSを利用して要件を満たせる。clonoがリスト番号や参照文字列を計算し、出力へ直接埋め込む処理は実装しない方針とする。

一方、番号付きコードリストに必要な参照用ID、用途別のclass、任意のキャプションとそのタイトル参照用IDは、著者向け記法から明示的な構造へ変換する必要がある。この変換はclonoが担う候補とする。

### Vivliostyleへ委譲する責務

- コードフェンスを構文強調された`pre`、`code`、`span`へ変換する
- CSSカウンターを使用して章ごとのリスト番号を生成する
- リスト番号をコードの上にあるキャプションへ表示する
- `break-inside`と`break-after`に従って長いコードリストをページ間で分割する
- `target-counter()`と`target-text()`を使用して参照文字列を生成する
- 参照をPDF内部リンクとして保持する

### clonoが担う候補となる責務

- 番号付きコードリストと番号なしコードブロックを区別できる著者向け記法を提供する
- 番号付きコードリストを、IDと用途別のclassを持つ`figure`、タイトル参照用IDを持つ`figcaption`、言語指定とコード内容を持つコードフェンスへ変換する
- 著者向けの参照記法を、コードリスト全体を指す`href`、キャプションを指す`data-caption-href`、用途別のclassを持つ空の`a`要素へ変換する
- 別Markdownファイルを参照する場合に、変換後の出力パスを反映した`href`と`data-caption-href`を生成する
- 未定義の参照ID、重複したID、不正な参照種別を診断する
- 番号なしコードブロックの通常のコードフェンス、言語指定、コード内容を壊さず、VFMへ渡す

### 他の参照種別との結合

見出し、画像、表、コードリストの個別fixtureは、それぞれの要件を満たした。ただし、fixtureごとのCSSを単純に一つのテーマへ結合することはできない。

各fixtureは`body`の`counter-reset`へ一種類のカウンターだけを指定している。複数の規則を単純に並べると、同じプロパティの後勝ちによって先に指定したカウンターのリセットが失われる。統合テーマでは、必要なカウンターを一つの`counter-reset`へまとめる必要がある。

また、画像はタイトル取得に`href`を使用するが、表とコードリストは`data-caption-href`を使用する。各fixtureの`.xref-title::after`をそのまま共存させると競合するため、参照種別ごとのセレクターに分けるか、出力契約を統一する必要がある。

このため、横断的な連番と参照の責務判断は、図、表、コードリストを同じ文書とテーマへ配置する結合テストが完了するまで調査中とする。

## 成立条件と未確認事項

章番号とリスト番号の組み合わせは、「一つのMarkdownファイルが一つの章に対応し、Vivliostyle設定の`entry`が章順に並ぶ」構成を前提とする。

次の事項は未確認または未決定である。

- clonoで使用する番号付きコードリストと参照の著者向け記法
- キャプションを省略した場合の補完規則
- キャプション内のMarkdown
- 言語指定を省略した番号付きコードリスト
- 行番号
- 特定行の強調と差分表示
- 製品用テーマでの長い行の折り返しと禁則処理
- キャプションがページ末尾の近くに配置される原稿での改ページ
- 図、表、コードリストを同じ文書とテーマへ配置した場合のカウンターと参照規則
- 存在しないIDや重複IDに対するVFMおよびVivliostyleの挙動
- 章として数えない前付・後付などを別のMarkdownファイルとして`entry`へ含める場合のカウンター制御

行番号、特定行の強調、差分表示はThunder Clawの次回作における必須要件ではないため、具体的な必要性が高まるまで調査しない。

## 再現方法

検証に使用する入力、HTMLとPDFの自動検証、PDFの目視確認手順は、[検証用fixtureのREADME](fixtures/vivliostyle-code-listing-references/README.md)を参照する。fixture内で`npm ci`を実行した後、`npm run verify`で再検証できる。

## 再調査する条件

- VFMがコードフェンス、キャプションまたは構文強調から生成するHTML構造を変更した場合
- Vivliostyle.jsのCSSカウンター、ページ分割、`target-counter()`または`target-text()`の実装が変更された場合
- 書籍の原稿ファイル構成が、一章一ファイルの前提を満たさなくなった場合
- 製品用テーマでコード、番号、キャプション、ページ分割または参照の表示が期待どおりにならなかった場合
- Thunder Clawで行番号、特定行の強調、差分表示などが必要になった場合
