# プラグイン仕様

- 状態: 策定中
- 作成日: 2026-09-22
- 最終更新日: 2026-09-22

## 目的

この文書は、利用者がclonoの組み込み記法の出力を差し替えるための、最小のプラグイン契約を定める。最初の対象はコラム記法の出力とする。Thunder Clawの印刷用テーマに必要な多重のHTML要素や装飾用要素を、clono本体へ固定せずに生成できるようにする。

clonoの主要な出力は引き続きVFMが処理できるMarkdownとし、完成したHTMLやPDFの生成はVivliostyleへ委譲する。組み込みの既定出力も外部rendererと同じ境界で扱えるようにする。

この文書は策定中であり、ここに記す拡張機能はまだ利用できない。現時点の動作は[コラム記法の仕様](authoring-syntax.md)と、各CLI・書籍プロジェクト仕様を正本とする。調査fixtureの設定項目、関数名、入出力例は、この文書で明示的に採用した部分を除き、正式な公開APIではない。

## 初期対象と対象外

初期対象は、利用者が用意したローカルのJavaScriptモジュールにより、組み込みのコラム記法の出力を差し替えることとする。コラムの著者向け記法や意味検証はclonoが担い、rendererは検証後のコラムを出力用の断片へ変換する。プラグインは利用者が信頼して実行するコードとし、clonoはプラグインを隔離するサンドボックスを提供しない。

次の機能は、この初期契約に含めない。

- 新しい著者向け記法や、コラム以外の組み込み記法に対する公開拡張点
- MarkdownのH1など、Generic Directives以外のASTノードを置換する公開拡張点
- 複数rendererの合成、プラグイン間の依存関係や状態共有
- プラグインの配布、探索、依存関係の解決やサンドボックス化
- 非同期renderer

これらを将来追加できる可能性は残すが、初期契約だけを理由にAPIを先行公開しない。

## 設定と読み込み

### `clono.config.mjs`での指定

プラグインは、`clono.config.mjs`のdefault exportにある省略可能な`plugins`配列へ、使用する順に明示する。省略した場合と空配列を指定した場合は、外部プラグインを読み込まず、組み込みの既定rendererを使用する。自動探索や暗黙の登録は行わない。

```javascript
export default {
  sourceRoot: "manuscripts",
  outputRoot: "build/manuscripts",
  publication: [
    { type: "document", path: "chapter-one.md", kind: "chapter", includeInToc: true },
  ],
  plugins: ["./plugins/column-theme.mjs"],
};
```

配列の各要素は、設定ファイルがあるディレクトリを基準とする、ローカルの`.mjs`ファイルへの相対パス文字列とする。`./`で始まり、区切り文字にはOSにかかわらず`/`を使用する。パスはプロジェクトルート内に収め、`..`による外部への移動、絶対パス、`file:`などのURL、npmパッケージ名、globおよび空文字列は受理しない。途中のパス要素を含めてシンボリックリンクを経由せず、読み取り可能な通常ファイルを指定する。設定を起動時のカレントディレクトリとは異なる場所から読み込んでも、プラグインパスの基準は変わらない。

`plugins`を指定した場合、その値は配列とし、各要素の型、パス形式、実在とファイル種別を原稿の変換前に確認する。同じパスを重複指定しない。既存の書籍設定と同様、定義していないトップレベルの設定項目は受理しない。`plugins`の追加によって、`sourceRoot`、`outputRoot`および`publication`の既存の必須条件は変えない。

### プラグインモジュール

各ファイルはNode.jsのES Moduleとし、default exportに次の形のJavaScriptオブジェクトを置く。

```javascript
import { renderColumn } from "./render-column.mjs";

export default {
  name: "column-theme",
  version: "1.0.0",
  apiVersion: 1,
  renderers: {
    column: renderColumn,
  },
};
```

| 項目 | 初期契約 |
| --- | --- |
| `name` | 空でない文字列。診断でプラグインを識別するための名前 |
| `version` | 空でない文字列。プラグイン自身のバージョン。初期契約では書式を検証しない |
| `apiVersion` | 数値の`1`。対応するclonoプラグインAPIの版 |
| `renderers` | `column`というキーに関数を持つオブジェクト |

default exportが存在しない場合、オブジェクトでない場合、必須項目の欠落・型の不一致、対応外の`apiVersion`、または未知の項目・renderer名がある場合は受理しない。`name`の一意性、rendererの競合および失敗時の診断は後述の契約に従う。`column`関数の入力と戻り値は、それぞれ以下の節で定める。

設定とモジュールはNode.jsの標準ES Moduleとして評価し、top-level awaitを使用できる。ファイルシステム上のパスは`file:` URLを文字列連結で組み立てず、`pathToFileURL()`で変換してから動的`import()`へ渡す。プラグインモジュールは設定順に一件ずつ読み込み、前の読み込みが完了してから次を開始する。ただし、プラグイン自身が開始した非同期の副作用の完了順は保証しない。Node.jsの通常のモジュールキャッシュに従い、同一プロセス内のホットリロードは提供しない。

プラグインモジュールの評価では利用者のコードが実行される。clonoはその権限を制限せず、設定値や戻り値の検証によって副作用を取り消すこともできない。信頼できるローカルファイルだけを指定する。

## コラムrendererの入力

`renderers.column`には、コラム一件につき一つのJavaScriptオブジェクトを第一引数として渡す。これはコラム記法専用の入力であり、将来のすべてのrendererに共通するインターフェイスではない。

```javascript
{
  title: "ちょっと休憩",
  body: "本文には**強調**がある。",
}
```

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `title` | 文字列 | `:::column[タイトル]`のラベルから得た、意味検証済みのプレーンテキスト |
| `body` | 文字列 | コラム本文の子要素に必要なclonoの変換を適用し、VFM向けに直列化したMarkdown断片 |

`title`には解析したラベルのテキスト値を、HTML用のエンコードを施さずに渡す。原稿のエスケープ表記とのバイト単位の一致は保証しない。空白だけのタイトルやインラインMarkdownを含むタイトルは、[コラム記法の内容モデル](authoring-syntax.md#コラム記法)に従ってrendererの呼び出し前に診断する。表示するときのエンコードは、rendererの出力先に応じて行う。

`body`にはコラムの開始・終了フェンス、タイトルのラベル、コラム用の外枠を含めない。まずコラム内で許可された記法を検証し、索引指定など、clonoが処理する子要素を変換する。その後に本文だけをMarkdownへ直列化して渡す。脚注参照、リンク参照、画像参照などの定義がコラム外にある場合、その定義を`body`へ複製しない。コラム本文の通常のMarkdownからHTMLへの変換は引き続きVFMが担う。

`body`はHTML文字列ではなくMarkdown断片だが、索引マーカーなどclonoが生成したraw HTMLを含むことがある。元の原稿とのバイト単位の一致や、空白・改行の具体的な整形は保証しない。一方、許可された本文のMarkdown構造と意味は保持する。rendererは`body`を再解析して記法の意味検証をやり直す必要はない。

clonoは`title`と`body`だけを持つオブジェクトを作り、`Object.freeze()`してからrendererへ渡す。rendererが入力を書き換えることは契約に含めず、返却後に入力が変化しないことを前提とする。追加の引数や`this`への値は公開APIとせず、mdastノード、原稿パス、書籍全体の参照情報、設定オブジェクトなども初期契約では渡さない。入力を増やす場合は、その用途と互換性を別途検討する。

## コラムrendererの戻り値とHTML安全条件

`renderers.column`は同期的に、空白以外の内容を持つJavaScriptの文字列を返す。Promiseなどのthenable、文字列以外の値、および空文字列・空白だけの文字列は受理しない。これらを検出した場合の診断と出力停止の詳細は、後続の失敗契約で定める。

戻り値は、コラム一件を表すVFM向けMarkdown断片であり、完成したHTML文書ではない。rendererは、必要なraw HTMLの要素と、渡された`body`のMarkdownを一つの断片に組み合わせる。clonoはこの断片を変換後Markdownへ組み込み、HTMLへの変換と組版はVFMおよびVivliostyleへ委譲する。レンダリング済みのHTML、mdastノード、`{ html: ... }`のようなオブジェクトは返せない。

rendererは、コラムの本文を省略・重複させず、一つの本文領域に`body`をMarkdownとして配置する。raw HTMLの開始タグと本文の間、および本文と終了タグの間には空行を置き、VFMが本文のMarkdownを処理できる境界を作る。タイトルもコラムのタイトルとして出力する。外枠の内側へ装飾用の`div`や`span`を増やすことはできるが、複数のコラムへ分割したり、文書全体の`html`・`head`・`body`要素を返したりしない。

例えば、次の断片は既定rendererが再現すべき基本構造を示す。空白や改行のバイト単位の一致は要求しない。

```markdown
<aside class="clono-column">

<p class="clono-column-title">ちょっと休憩</p>

本文には**強調**がある。

</aside>
```

clono基盤CSSのコラム用規則は`.clono-column`と`.clono-column-title`へ適用される。カスタムrendererがこれらの規則を利用する場合は、該当する外枠とタイトル要素にclassを残す。classを変更または省略する場合、同等の分割制御や外観は利用者のテーマCSSで用意する責任がある。

### 動的な値と信頼境界

`title`はHTML用にエンコードされていない。rendererはこれをHTMLのテキスト内容へ入れる場合、少なくとも`&`、`<`、`>`などをテキスト文脈に応じてエンコードし、タグや属性へ脱出させない。HTML属性値へ入れる場合は、その属性の文脈に応じたエンコードを別に行う。`body`はMarkdownとして配置し、HTML属性値や要素名へ埋め込まない。`body`全体をHTMLテキストとしてエンコードすると、Markdownの処理が失われる。

要素名と属性名は、プラグインが意図した固定の構造から選ぶ。`title`や`body`など原稿由来の値を要素名・属性名として直接使用しない。動的なURL属性を生成する場合は、用途ごとに許可する形式とスキームを決め、URLを検証したうえでHTML属性値としてエンコードする。少なくとも`javascript:`のような実行可能な不許可スキームや、動的なイベントハンドラー属性を生成しない。

プラグインは利用者が信頼して実行するローカルコードであり、clonoはrendererの戻り値をHTMLサニタイズせず、許可する要素・属性や親子関係を自動検証しない。上記の出力構造とエンコードはプラグイン作者が守る契約であり、clonoによるセキュリティ保証ではない。プラグイン作者は、特殊文字を含むタイトル、必要に応じたURL、および`body`内のMarkdownが、VFM変換後も意図した構造になることをテストする。clono自身の既定rendererが生成するraw HTMLには、[変換パイプラインのADR](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)の安全条件を適用する。

## 競合と失敗時の診断

### 変換前の検査

プラグインを使用する場合は、原稿のAST変換を始める前に次の順で検査を完了する。

1. `clono.config.mjs`の`plugins`配列と各パスの形式・実在を検証する。
2. 設定順にモジュールを読み込み、default exportと必須項目を検証する。
3. 読み込んだプラグインの`name`とrenderer登録の競合を検査する。

設定値の独立した誤りは可能な範囲でまとめて報告する。設定診断が一件でもあれば、プラグインモジュールを評価せずに失敗する。モジュールの読み込みまたはexportの検証に失敗した場合は、その設定項目で停止し、後続のプラグインを評価しない。すべてのモジュールが有効な場合だけ競合を検査し、競合があれば原稿の変換を始めない。プラグインがない場合は組み込みの既定rendererを使用し、これは外部rendererとの競合とは扱わない。

| 失敗 | 診断で示す対象と理由 |
| --- | --- |
| `plugins`の型、パス形式、重複、ファイル種別などの不正 | `clono.config.mjs`、`plugins`の配列位置、指定値または対象パス、および違反した条件 |
| モジュールの読み込み・評価失敗 | 対象のプラグインパス、`plugins`の配列位置、および読み込みまたは評価の失敗理由 |
| default export、基本情報、`apiVersion`またはrenderer登録の不正 | 対象のプラグインパス、`plugins`の配列位置、および不正な項目・値の条件 |
| プラグイン名の重複 | 重複した`name`と、該当する各プラグインパス |
| renderer名の競合 | 競合したrenderer名と、該当する各プラグイン名・パス |

初期契約で登録できるrenderer名は`column`だけであり、各プラグインはこれを一つ登録する。このため、初期契約で有効な外部プラグインは高々一つである。`plugins`を配列とするのは将来の拡張点を追加できる余地のためであり、現時点で複数の`column` rendererを暗黙に合成したり、先勝ち・後勝ちで選んだりしない。

設定・モジュール・競合の診断には、原稿に存在しない架空の行・列を付けない。設定の不正と競合は`clono.config.mjs`、個別モジュールの失敗は対象プラグインのパスを診断のファイルとして扱う。表示形式は既存CLIの位置を持たない診断に合わせ、少なくとも対象と理由を一行で示す。JavaScriptのスタックトレースを通常の利用者向け診断へそのまま表示しない。

### renderer呼び出し時の失敗

`renderers.column`が例外を投げた場合、Promiseなどのthenableを返した場合、文字列以外を返した場合、または空文字列・空白だけの文字列を返した場合は、そのコラムの変換を失敗とする。thenableは完了を待たずに拒否し、値を文字列へ暗黙に変換しない。rendererの実行中に発生した例外は呼び出し境界で捕捉し、例外の要点を診断へ変換する。

この診断には、原稿ファイル名、`column`開始位置の行・列、directive名`column`、rendererの識別情報、および失敗理由を含める。外部rendererの場合はプラグインの`name`を、組み込みの既定rendererの場合は「組み込みの既定renderer」であることを識別情報として示す。利用者向けの説明は改行を含まない一行に整え、例外のスタックトレースや内部のClojureScript例外をそのまま表示しない。原稿位置を示せるため、既存の位置付き診断形式`<file>:<line>:<column>: <message>`に従う。

同じ原稿では最初に失敗したrenderer呼び出しで後続のrenderer呼び出しを止め、成功済みのコラムを含めてその原稿の出力Markdownを返さない。`clono transform`は既存の出力ファイルを変更しない。`clono build`は独立した残りの原稿について可能な範囲で変換と診断収集を継続するが、診断が一件でもあれば部分的な生成済み原稿ツリーを公開せず、既存の正式な出力を保持する。複数の原稿診断は[書籍プロジェクト仕様](book-project.md)の原稿順に表示する。

モジュール評価やrenderer実行による外部への副作用は、clonoの出力保護の対象外とする。信頼されたローカルコードが無期限に待機する場合のタイムアウトや、返されたHTMLの安全性違反をclonoが自動診断することも、初期契約では保証しない。診断コードと文言の完全一致は公開APIとせず、上記の対象、位置の有無、理由および失敗時の出力契約を保証する。

## `transform`と`build`への適用

### 単一ファイルの`transform`

プラグインを使用する単一ファイル変換では、次のように`--project`で書籍プロジェクトを明示する。

```text
clono transform <input> --output <output> --project <project>
clono transform <input> -o <output> --project <project>
```

`--project`は省略可能で、入力・出力オプションとの指定順を問わない。指定できるのは一回だけとし、値の欠落、`-`で始まる値、重複指定は引数エラーとする。`--project=<project>`形式および短縮形`-p`は初期契約に含めない。相対パスの`<project>`はclonoを起動したカレントディレクトリを基準に解決し、指定したディレクトリ直下の`clono.config.mjs`だけを読み込む。入力ファイルの親や祖先にある設定は探索しない。

`--project`を省略した場合は設定ファイルを一切読み込まず、組み込みの既定rendererを使用する。指定した場合は既存の書籍設定と[設定と読み込み](#設定と読み込み)の契約で設定全体を検証し、登録された外部`column` rendererをこの一回の変換へ適用する。`plugins`を省略した設定または空配列の設定では、既定rendererを使用する。設定やプラグインが不正な場合は、入力MarkdownのAST変換を始めず、出力ファイルを新規作成・更新しない。

`--project`はプラグインの選択に使用し、`<input>`と`<output>`を設定の`sourceRoot`や`outputRoot`から導出しない。入力は`publication`への掲載や`sourceRoot`配下への配置を必要としない。`--project`を指定しても変換モードは単一ファイルのままであり、別原稿の参照対象収集、索引文書の生成、書籍全体の番号確定、および基盤CSSのコピーは行わない。既存の単一ファイル用プレースホルダーと出力ファイル保護の契約も変えない。

### 書籍プロジェクトの`build`

`clono build [project]`は、従来どおりプロジェクトルート直下の`clono.config.mjs`を読み込む。その`plugins`設定を原稿のAST変換より前に一度検証・読み込み、選択した`column` rendererを同じビルド内のMarkdown変換へ適用する。`plugins`がない場合は既定rendererを使用する。

適用対象は、`publication`への掲載有無にかかわらず、変換計画に含まれる入力Markdownの`column`である。コピーする通常ファイル、通過HTML、clonoが生成する空白ページ資材および索引Markdownには適用しない。プラグインはVivliostyleの設定、テーマCSSまたはPDF生成へ直接介入しない。

設定・プラグインの事前検査または原稿変換が失敗した場合は、[競合と失敗時の診断](#競合と失敗時の診断)および[書籍プロジェクト仕様](book-project.md)に従い、生成済み原稿ツリーを公開せず、既存の正式な出力を保持する。プラグインを使用すること自体はファイルのコピー操作を追加しない。ただし、プラグインファイルを`sourceRoot`内に配置すると通常ファイルのコピー規則に従って出力へ含まれるため、コピーを避ける場合は`sourceRoot`の外へ置く。

この節はプラグイン導入後の契約を定める。現行のCLIには`--project`とプラグイン適用をまだ実装していない。[単一ファイル変換CLI仕様](single-file-cli.md)および[書籍プロジェクト仕様](book-project.md)にも、実装予定のコマンドと設定項目を記載する。

| 5 | 競合、読み込み失敗、実行時例外の診断と失敗契約 | 決定済み |
| 6 | `transform`と`build`での設定選択と適用範囲 | 決定済み |

採用理由と見送った案は[ADR 0005](../decisions/0005-adopt-local-column-renderer-plugins.md)へ記録する。CLIと書籍プロジェクトに影響する決定は、それぞれの仕様にも反映する。この表の「決定済み」は設計上の合意を表し、実装済みを意味しない。

## 調査との関係

[プラグイン読み込み方式の調査](../research/plugin-loading.md)では、ローカルES Moduleの読み込みとClojureScriptからのrenderer呼び出し、主な失敗形の識別を確認した。[コラムrenderer契約の調査](../research/plugin-renderer-contract.md)では、既定出力の再現、多重ラッパーを持つ出力、本文MarkdownとVFMの結合、失敗時の部分出力停止、単一ファイル変換からの設定選択を候補として検証した。

これらは技術的な成立性を示す資料であり、資料中の候補がそのまま正式な設定構造や公開APIになるわけではない。上表の各契約は、既存の[変換パイプラインのADR](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)および[プロジェクト憲章](../project-charter.md)との整合性を確認しながら、この文書で確定する。
