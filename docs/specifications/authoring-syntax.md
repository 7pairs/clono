# clono著者向け記法

- 状態: 策定中
- 作成日: 2026-08-22
- 最終更新日: 2026-09-17

## 目的

この文書は、`clono`を利用する著者が原稿に記述できる記法と、その開発状態の正本である。`clono`の独自記法だけでなく、Thunder Clawの書籍制作に必要だが、標準Markdown、VFM、VivliostyleまたはテーマCSSへ委譲するため`clono`独自記法の対象としない機能も記録する。

Vivliostyleと`clono`の責務分担は、[Vivliostyleとclonoの責務整理](../vivliostyle-responsibilities.md)を正本とする。この文書では調査根拠を重複して記述せず、著者向けの入力方法と実装状態を示す。

## 状態の定義

| 状態 | 意味 |
| --- | --- |
| 検討前 | 必要性と責務は把握しているが、著者向け記法と詳細仕様をまだ検討していない |
| 仕様策定中 | 候補記法または要件を検討しており、実装契約が確定していない |
| 実装予定 | 著者向け記法と実装契約は確定したが、実装または自動テストが完了していない |
| 実装中 | 仕様の一部に対応する実装と自動テストはあるが、仕様全体の実装が完了していない |
| 実装済み | 仕様に対応する実装と自動テストがあり、利用できる |
| 保留 | 将来再検討し得るが、現在の開発対象に含めない |
| 対象外 | 原稿内の`clono`独自記法を実装せず、標準Markdown、VFM、Vivliostyle、テーマCSSまたは原稿外の入力へ委譲する |

`clono`の機能として必要ないと判断した場合は「対象外」とし、必要性はあるが初期開発で扱わない場合は「保留」とする。書籍構成など原稿外の入力で`clono`が扱うが、著者向け原稿記法を設けない機能も、この文書では「対象外」とする。「対象外」は、書籍制作でその機能を利用できないことを意味しない。

## 垂直余白記法

### 目的

垂直余白記法は、二つの通常段落の間へ、本文一行相当の紙面上の余白を明示的に追加する。目立たせたい短い段落の前後など、通常のMarkdownによる段落間隔より広い空きを著者が意図して指定する用途を想定する。

通常のMarkdownにある空行は段落を区切るための構文であり、空行の数はVFMの出力へ可視要素として保持されない。この仕様の垂直余白は、Markdownの段落区切りとしての空行とは異なる機能として扱う。

垂直余白は、内容を持たない一ページを挿入する空白ページや、後続のブロックを次ページから開始する強制改ページとも異なる。

### 構文

Leaf directiveの`space`を、垂直余白を追加する二つの段落の間へ記述する。

```markdown
通常の本文。

::space

ここぞという決めの一言。
```

`space`はLeaf directiveとして記述する。Text directiveまたはContainer directiveとして記述した場合はエラーとする。

`space`は内容、ラベルおよび属性を持たない。ラベルまたは属性が一つでも指定された場合はエラーとする。初期仕様では、余白の行数、寸法、前後の方向または用途を指定する属性を扱わない。

### 配置

`space`はMarkdown文書のルート直下に記述し、前後の最寄りの表示ブロックがどちらも通常段落である場合だけ使用できる。文書の先頭と末尾には記述できない。見出し、箇条書き、番号付きリスト、引用、コードブロック、画像ブロック、表、文字揃え、コラムなど、通常段落以外の表示ブロックと`space`の間には使用できない。

この配置規則の通常段落は、mdastの`paragraph`ノードを指す。Markdown画像または参照形式の画像だけからなる`paragraph`は画像ブロックとみなし、通常段落に含めない。文章の一部にインライン画像を含む`paragraph`は通常段落として扱う。

リンクおよび画像の定義と脚注定義は、その記述位置に紙面上の内容を生成しないため、前後の表示ブロックを判定するときには読み飛ばす。これらの定義を読み飛ばした結果、文書の先頭または末尾になる場合や、最寄りの表示ブロックが通常段落でない場合はエラーとする。

二つの`space`の間に紙面へ表示されるブロックがない連続指定は許可しない。二つの`space`の間にリンク定義、画像の定義または脚注定義だけがある場合も連続指定としてエラーにする。二行以上の余白を作るために`space`を連続させることはできない。

段落、リスト項目、引用、文字揃え、コラム、脚注定義など、他のブロックの内部に`space`を記述した場合はエラーとする。

### 変換結果

`clono`は`space`を、要素名とclass名が固定された次のraw HTMLを含むMarkdownへ変換する。

```html
<div class="clono-space" aria-hidden="true"></div>
```

垂直余白用の要素は紙面へ表示する内容を持たないため、`aria-hidden="true"`を付ける。著者が指定した値を要素名、属性名またはclass名へ埋め込まず、IDも付与しない。

### CSS

`clono`は、垂直余白用の要素が本文一行相当の余白として機能するため、次の規則を基盤CSSへ追加する。

```css
.clono-space {
  block-size: 1lh;
}
```

`1lh`は、垂直余白用の要素に適用される行送り一行分を表す。基盤CSSは、npmパッケージ内の`styles/clono.css`として同梱する。書籍プロジェクト変換では、[書籍プロジェクト仕様](book-project.md)に従って生成済み原稿ツリーへ基盤CSSをコピーする。

一行相当の既定値は垂直余白記法の機能に含める。利用者テーマは、書籍のデザインに応じて`.clono-space`の寸法を上書きできる。初期仕様では、著者向け記法から任意のCSS寸法を指定する機能を提供しない。

### ページ境界

原稿上で二つの段落の間にある`space`が、組版結果でもページ内のどの位置へ配置されるかは保証しない。ページ末尾または次ページの先頭に配置される場合を含め、clonoは垂直余白を自動的に削除せず、前後の段落を同じページへ固定せず、改ページ位置を予測または調整しない。実際のページ分割と配置はVivliostyleおよび利用者テーマへ委譲する。

### 診断と出力

directiveの種類、ラベル、属性または配置がこの仕様に適合しない場合は、[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従ってファイル名、行、列、directive名、問題の説明を持つ診断を生成する。

診断が一件でもある場合はAST変換を実行せず、部分的な出力Markdownも返さない。同じ文書に複数の独立した問題がある場合は、可能な範囲で入力位置の順に診断を収集する。`clono transform`と`clono build`は同じ垂直余白の変換および診断契約を使用する。

## 強制改ページ記法

### 目的

強制改ページ記法は、指定位置より後にある任意のトップレベルブロックを次ページの先頭から開始する。改ページを示す線や記号は紙面へ表示しない。

強制改ページは、内容を持たない一ページを意図的に挿入する空白ページや、二つの通常段落の間へ一行相当の空きを追加する垂直余白とは異なる機能として扱う。

### 構文

Leaf directiveの`page-break`を、改ページ前のブロックと次ページから開始するブロックの間へ記述する。

```markdown
改ページ前の文章。

::page-break

# 次のページから始める見出し
```

`page-break`はLeaf directiveとして記述する。Text directiveまたはContainer directiveとして記述した場合はエラーとする。

`page-break`は内容、ラベルおよび属性を持たない。ラベルまたは属性が一つでも指定された場合はエラーとする。初期仕様では、左ページ、右ページ、recto、verso、奇数ページまたは偶数ページの指定を扱わない。

### 配置

`page-break`は、Markdown文書のルート直下にあるトップレベルブロックの間だけに記述できる。段落、リスト項目、引用、文字揃え、コラム、脚注定義など、他のブロックの内部に記述した場合はエラーとする。

文書の先頭と末尾には記述できない。`page-break`の前後には、紙面へ表示されるトップレベルブロックがそれぞれ1個以上必要である。リンク定義、画像の定義および脚注定義は、その記述位置に紙面上の内容を生成しないため、前後のブロックとして数えない。

複数の`page-break`の間に紙面へ表示されるトップレベルブロックがない場合は、連続指定としてエラーにする。二つの`page-break`の間にリンク定義、画像の定義または脚注定義だけがある場合も連続指定として扱う。

白紙ページの挿入を目的として、文書先頭、文書末尾または連続した`page-break`を使用しない。空白ページは原稿内の著者向け記法ではなく、書籍プロジェクトの構成要素として扱う。

### 変換結果

`clono`は`page-break`を、要素名とclass名が固定された次の空要素へ変換する。

```html
<div class="clono-page-break" aria-hidden="true"></div>
```

改ページ用の要素は紙面へ表示する内容を持たないため、`aria-hidden="true"`を付ける。著者が指定した値を要素名、属性名またはclass名へ埋め込まず、IDも付与しない。

組版時点で改ページ用の要素が既にページ先頭へ配置された場合を含め、物理的なページ分割の結果は`clono`で予測または調整せず、Vivliostyleへ委譲する。

### CSS

`clono`は、改ページ用の要素を次ページから開始するため、次の規則を基盤CSSへ追加する。

```css
.clono-page-break {
  break-before: page;
}
```

基盤CSSは、npmパッケージ内の`styles/clono.css`として同梱する。書籍プロジェクト変換では、[書籍プロジェクト仕様](book-project.md)に従って生成済み原稿ツリーへ基盤CSSをコピーする。改ページは強制改ページ記法の機能そのものであるため、利用者のテーマCSSを組み込まない場合も基盤CSSを読み込めば機能するようにする。

### 診断と出力

directiveの種類、ラベル、属性または配置がこの仕様に適合しない場合は、[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従ってファイル名、行、列、directive名、問題の説明を持つ診断を生成する。

診断が一件でもある場合はAST変換を実行せず、部分的な出力Markdownも返さない。同じ文書に複数の独立した問題がある場合は、可能な範囲で入力位置の順に診断を収集する。

## 文字揃え記法

### 目的

文字揃え記法は、複数のMarkdown段落を一つの範囲として指定し、範囲内の文字揃えを変更する。初期仕様では、「はじめに」などの署名を想定した右寄せだけに対応する。

### 構文

Container directiveの`align`を使用し、`position`属性に`right`を指定する。

```markdown
:::align{position="right"}
2026年8月22日

Thunder Claw
:::
```

`align`はContainer directiveとして記述する。Text directiveまたはLeaf directiveとして記述した場合はエラーとする。

初期仕様で許可する属性は`position="right"`だけである。次のいずれかに該当する場合はエラーとする。

- `position`属性がない
- `position`属性の値が`right`以外である
- `position`以外の属性がある

`left`、`center`、`justify`などへの対応は、具体的な必要性が確認された場合に別途仕様を決定する。`id`、`class`、`style`などを著者が任意に指定する機能は初期仕様に含めない。

### 内容モデル

`align`の直下には、1個以上のMarkdown段落だけを許可する。空の`align`はエラーとする。

段落内では、次のmdastノードに対応するインラインMarkdownを許可する。子要素を持つノードは再帰的に検証する。

- `text`
- `emphasis`
- `strong`
- `inlineCode`
- `link`
- `linkReference`
- `break`
- `footnoteReference`

次の内容は初期仕様で許可せず、`align`内に出現した場合はエラーとする。この一覧にないmdastノードも、許可する仕様を追加するまではエラーとする。

- 見出し
- 箇条書きと番号付きリスト
- コードブロック
- 画像と参照形式の画像
- 表
- raw HTML
- `align`自身を含むすべてのdirective

`align`の入れ子は許可しない。将来導入する他のContainer directive内に`align`を配置できるかは、外側の記法の内容モデルを決定する際に別途検討する。

### 変換結果

`clono`は`align`を、要素名とclass名が固定された次の構造へ変換する。範囲内の段落とインラインMarkdownは保持する。

```markdown
<div class="clono-align-right">

2026年8月22日

Thunder Claw

</div>
```

著者が指定した値を要素名、属性名またはclass名へ埋め込まない。変換後のMarkdownは解析と直列化によって空白や改行が正規化される可能性があるが、段落と許可されたインラインMarkdownの意味を保持する。

### CSS

`clono`は、生成した構造が右寄せとして機能するための次の最小限の基盤CSSを同梱する。

```css
.clono-align-right {
  text-align: right;
}
```

基盤CSSは、npmパッケージ内の`styles/clono.css`として同梱する。

基盤CSSは、`clono`が生成する構造の機能上必要な規則だけを担う。フォント、余白、色などの書籍全体のデザインは利用者のテーマCSSの責務とする。書籍プロジェクト変換での配置と読み込み順は、[書籍プロジェクト仕様](book-project.md)に従う。

### 診断と出力

構文、directiveの種類、属性または内容モデルがこの仕様に適合しない場合は、[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従ってファイル名、行、列、directive名、問題の説明を持つ診断を生成する。

診断が一件でもある場合はAST変換を実行せず、部分的な出力Markdownも返さない。同じ文書に複数の独立した問題がある場合は、可能な範囲で入力位置の順に診断を収集する。

## 定義リスト記法

### 目的

定義リスト記法は、複数の用語とそれぞれの説明を、一つの定義リストとして記述する。enumの値や専門用語など、表のセルへ収めるには説明が長い項目を列挙する用途を想定する。

初期仕様では、一つの項目を一つの用語と一つの説明で構成する。複数の用語が同じ説明を共有する記法は初期仕様に含めないが、将来は記法を変更せず、項目内に許可する用語の個数を増やすことで対応できる構造とする。

### 構文

リスト全体にはContainer directiveの`definition-list`、各項目にはContainer directiveの`definition`、各項目の用語にはLeaf directiveの`term`を使用する。

内側の`definition`を3個のコロンで囲むため、外側の`definition-list`は4個のコロンで囲む。

````markdown
::::definition-list
:::definition
::term[`READY`]

処理を開始できる**待機状態**。詳細は[状態遷移の仕様](https://example.com/state)を参照する。
:::

:::definition
::term[DONE]

処理が正常に完了した状態を表す。終了コードは`0`となる。
:::
::::
````

`definition-list`と`definition`はContainer directive、`term`はLeaf directiveとして記述する。同じ名前をText directiveとして使用した場合や、異なる種類のdirectiveとして記述した場合はエラーとする。

`definition-list`、`definition`および`term`には属性を一つも許可しない。`id`、`class`および`style`を含め、属性が一つでも指定された場合はエラーとする。`definition-list`と`definition`にはラベルを許可しない。

`term`のラベルは必須とし、空文字または空白だけの用語はエラーとする。項目を識別するID、用語への参照および定義リストの入れ子は初期仕様に含めない。同じ用語を複数の項目へ記述することは許可する。

### 内容モデル

`definition-list`の直下には、1個以上の`definition`だけを許可する。空の`definition-list`と、段落など`definition`以外の子要素を持つ`definition-list`はエラーとする。

各`definition`の直下には、次の順序で子要素を記述する。

1. 用語を表す`term`を1個
2. 説明を表す通常のMarkdown段落を1個

`term`がない場合、2個以上ある場合、説明段落がない場合、複数の説明段落がある場合、または順序が異なる場合はエラーとする。将来、複数の用語が同じ説明を共有する必要性が確認された場合は、説明段落の前へ1個以上の`term`を許可するよう個数制約を見直す。

用語のラベルには、次のmdastノードに対応するインラインMarkdownだけを許可する。

- `text`
- `inlineCode`

一つの用語内で通常テキストとインラインコードを組み合わせることも許可する。強調、太字、リンク、画像、raw HTML、改行およびdirectiveなど、この一覧にないmdastノードはエラーとする。

説明段落では、次のmdastノードに対応するインラインMarkdownを許可する。子要素を持つノードは再帰的に検証する。

- `text`
- `emphasis`
- `strong`
- `inlineCode`
- `link`
- `linkReference`
- `break`

説明内の画像、脚注参照、raw HTMLおよびdirectiveは初期仕様では許可しない。この一覧にないmdastノードも、許可する仕様を追加するまではエラーとする。参照形式のリンクを使用する場合、その定義は`definition-list`の外へ記述する。

### 配置

`definition-list`はMarkdown文書のルート直下に記述する。段落、リスト項目、引用、文字揃え、コラム、脚注定義または他のdirectiveの内部に記述した場合はエラーとする。

`definition`は`definition-list`の直接の子としてだけ使用できる。`term`は`definition`の直接の子としてだけ使用できる。`definition`または`term`を単独で使用した場合や、別の親要素へ配置した場合はエラーとする。

`definition-list`、`definition`および説明内へ、定義リスト自身を含むdirectiveを入れ子にすることは許可しない。

### 変換結果

`clono`は`definition-list`を一つの`dl.clono-definition-list`へ変換する。各`definition`は`div.clono-definition-item`で囲み、`term`の用語を`dt`へ、説明段落を一つの`dd`へ配置する。

前述の入力例は、次のraw HTMLとMarkdownを含む構造へ変換する。

```markdown
<dl class="clono-definition-list">

<div class="clono-definition-item">
<dt><code>READY</code></dt>
<dd>

処理を開始できる**待機状態**。詳細は[状態遷移の仕様](https://example.com/state)を参照する。

</dd>
</div>

<div class="clono-definition-item">
<dt>DONE</dt>
<dd>

処理が正常に完了した状態を表す。終了コードは`0`となる。

</dd>
</div>

</dl>
```

要素名とclass名は固定する。用語の通常テキストとインラインコードは、それぞれHTMLのテキスト内容と`code`要素へ変換し、動的なテキストをHTMLのテキスト内容としてエンコードする。著者が指定した値を要素名、属性名またはclass名へ埋め込まず、自動生成IDも付与しない。

説明の段落と許可されたインラインMarkdownは、`dd`内へMarkdownのまま保持する。説明内のMarkdownからHTMLへの変換と、定義リストの意味構造の保持はVFMへ委譲する。変換後のMarkdownは解析と直列化によって空白や改行が正規化される可能性があるが、許可された構造と意味を保持する。

### CSSとページ分割

`clono`は、一つの用語と説明がページ境界で分断されることを可能な限り避けるため、次の規則を基盤CSSへ追加する。

```css
.clono-definition-item {
  break-inside: avoid;
}
```

基盤CSSは、npmパッケージ内の`styles/clono.css`として同梱する。書籍プロジェクト変換での配置、利用者テーマとの読み込み順、および上書き可能性の保証範囲は、[書籍プロジェクト仕様](book-project.md)に従う。

定義項目が一ページに収まらない場合は、Vivliostyleが項目内を分割することを許容する。用語と説明を常に同じページへ配置できることは保証しない。

字下げ、項目間の余白、フォント、罫線、背景色などの外観は基盤CSSで指定せず、利用者のテーマCSSへ委譲する。

### 診断と出力

構文、directiveの種類、ラベル、属性、内容モデルまたは配置がこの仕様に適合しない場合は、[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従ってファイル名、行、列、directive名、問題の説明を持つ診断を生成する。

診断が一件でもある場合はAST変換を実行せず、部分的な出力Markdownも返さない。同じ文書に複数の独立した問題がある場合は、可能な範囲で入力位置の順に診断を収集する。`clono transform`と`clono build`は同じ定義リストの変換および診断契約を使用する。

## コラム記法

### 目的

コラム記法は、本文から独立した雑談や補足を、必須タイトルと複数のMarkdownブロックを持つ一つの範囲として指定する。初期仕様では一種類のコラムだけに対応し、コラムの種類、ID、連番および参照は扱わない。

### 構文

Container directiveの`column`を使用し、directiveのラベルへタイトルを記述する。

```markdown
:::column[ちょっと休憩]
ここには本文を書く。

- 箇条書きも書ける
- 雑談も止まらない
:::
```

`column`はContainer directiveとして記述する。Text directiveまたはLeaf directiveとして記述した場合はエラーとする。

ラベルは必須とし、空文字または空白だけのタイトルはエラーとする。タイトルには改行を含まないプレーンテキストだけを許可し、強調、インラインコード、リンクなどのインラインMarkdownは許可しない。同じタイトルを持つ複数のコラムは許可する。

初期仕様では属性を一つも許可しない。`class`、`style`、`id`を含め、属性が一つでも指定された場合はエラーとする。複数種類のコラムが必要になった場合は、その用途と入力方法を別途決定する。

### 内容モデル

`column`の本文には、1個以上のMarkdownブロックを必要とする。タイトルだけで本文がないコラムはエラーとする。

初期仕様では、次のMarkdown表現を許可する。子要素を持つノードは再帰的に検証し、内部にも同じ内容モデルを適用する。ただし、索引指定には後述する段落内の配置制限を適用する。

- 段落
- 強調
- 太字
- インラインコード
- リンクと参照形式のリンク
- 強制改行
- 箇条書きと番号付きリスト
- 引用
- コードブロック
- 画像と参照形式の画像
- Markdown表
- 脚注参照
- 索引指定（段落の直接の子に限る）

索引指定は、コラム内にある通常の段落の直接の子としてだけ許可する。強調、太字、リンクまたはその他のインライン要素の子にある索引指定は、それらの要素自体が内容モデルで許可されていてもエラーとする。箇条書き、番号付きリストまたは引用に含まれる段落にも、同じ直接の子という規則を適用する。

リンク、画像および脚注の定義は、コラムの外へ記述する。特に、コラム内で脚注を使用する場合は、参照だけをコラム内へ置き、脚注定義をコラムの外へ置く。

```markdown
:::column[雑談]
これは脚注付きの雑談です[^column-note]。
:::

[^column-note]: コラムから参照する脚注。
```

次の内容は初期仕様で許可せず、`column`内に出現した場合はエラーとする。この一覧にないmdastノードも、許可する仕様を追加するまではエラーとする。

- 見出し
- 水平線
- raw HTML
- 脚注定義
- リンクおよび画像の定義
- `index`以外のすべてのdirective

`column`の入れ子は許可しない。索引指定だけは、[索引仕様](index.md)に従ってコラム内の通常の段落へ記述できる。文字揃え記法を含むその他のdirectiveは初期仕様では許可せず、将来導入する記法をコラム内で使用できるかは、各記法の必要性と組み合わせを確認したうえで個別に決定する。

### 変換結果

`clono`は`column`を、要素名とclass名が固定された次の構造へ変換する。タイトルを`p.clono-column-title`へ変換し、本文のMarkdownブロックとインラインMarkdownは保持する。

```markdown
<aside class="clono-column">

<p class="clono-column-title">ちょっと休憩</p>

ここには本文を書く。

</aside>
```

タイトルはHTMLのテキスト内容としてエンコードする。著者が指定した値を要素名、属性名またはclass名へ埋め込まず、自動生成IDも付与しない。タイトルを見出し要素へ変換しないため、目次の掲載対象としない。

変換後のMarkdownは解析と直列化によって空白や改行が正規化される可能性があるが、許可された本文のMarkdown構造と意味を保持する。コラム内部のMarkdownからHTMLへの変換と、Pandoc風脚注から脚注構造への変換はVFMへ委譲する。コラムのページ分割と脚注のページ下部への配置はVivliostyleへ委譲する。

### CSS

`clono`は、短いコラムを可能な限り一ページへまとめ、タイトルだけがページ末尾に残ることを避けるため、次の分割制御を基盤CSSへ追加する。

```css
.clono-column {
  break-inside: avoid;
}

.clono-column-title {
  break-after: avoid;
}
```

一ページに収まらないコラムは複数ページへの分割を許容し、分割後のページでタイトルを繰り返さない。枠線、背景色、余白、文字サイズなどの外観は基盤CSSで指定せず、利用者のテーマCSSの責務とする。

基盤CSSは、npmパッケージ内の`styles/clono.css`として同梱する。書籍プロジェクト変換での配置、利用者テーマとの読み込み順、および上書き可能性の保証範囲は、[書籍プロジェクト仕様](book-project.md)に従う。

### 診断と出力

構文、directiveの種類、タイトル、属性または内容モデルがこの仕様に適合しない場合は、[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従ってファイル名、行、列、directive名、問題の説明を持つ診断を生成する。

診断が一件でもある場合はAST変換を実行せず、部分的な出力Markdownも返さない。同じ文書に複数の独立した問題がある場合は、可能な範囲で入力位置の順に診断を収集する。
