# clono著者向け記法

- 状態: 策定中
- 作成日: 2026-08-22
- 最終更新日: 2026-09-04

## 目的

この文書は、`clono`を利用する著者が原稿に記述できる記法と、その開発状態の正本である。`clono`の独自記法だけでなく、Thunder Clawの書籍制作に必要だが、標準Markdown、VFM、VivliostyleまたはテーマCSSへ委譲するため`clono`独自記法の対象としない機能も記録する。

Vivliostyleと`clono`の責務分担は、[Vivliostyleとclonoの責務整理](../vivliostyle-responsibilities.md)を正本とする。この文書では調査根拠を重複して記述せず、著者向けの入力方法と実装状態を示す。

## 状態の定義

| 状態 | 意味 |
| --- | --- |
| 検討前 | 必要性と責務は把握しているが、著者向け記法と詳細仕様をまだ検討していない |
| 仕様策定中 | 候補記法または要件を検討しており、実装契約が確定していない |
| 実装予定 | 著者向け記法と実装契約は確定したが、実装または自動テストが完了していない |
| 実装中 | 仕様の一部に対応する実装と自動テストはあるが、仕様全体の実装が完了していない |
| 実装済み | 仕様に対応する実装と自動テストがあり、利用できる |
| 保留 | 将来再検討し得るが、現在の開発対象に含めない |
| 対象外 | 原稿内の`clono`独自記法を実装せず、標準Markdown、VFM、Vivliostyle、テーマCSSまたは原稿外の入力へ委譲する |

`clono`の機能として必要ないと判断した場合は「対象外」とし、必要性はあるが初期開発で扱わない場合は「保留」とする。書籍構成など原稿外の入力で`clono`が扱うが、著者向け原稿記法を設けない機能も、この文書では「対象外」とする。「対象外」は、書籍制作でその機能を利用できないことを意味しない。

### 基本表現

| --- | --- | --- | --- |

## 強制改ページ記法

### 目的

強制改ページ記法は、指定位置より後にある任意のトップレベルブロックを次ページの先頭から開始する。改ページを示す線や記号は紙面へ表示しない。

強制改ページは、内容を持たない一ページを意図的に挿入する空白ページや、ブロック間へ一行程度の空白を挿入する意図的な空行とは異なる機能として扱う。

### 構文

Leaf directiveの`page-break`を、改ページ前のブロックと次ページから開始するブロックの間へ記述する。

```markdown
改ページ前の文章。

::page-break

# 次のページから始める見出し
```

`page-break`はLeaf directiveとして記述する。Text directiveまたはContainer directiveとして記述した場合はエラーとする。

`page-break`は内容、ラベルおよび属性を持たない。ラベルまたは属性が一つでも指定された場合はエラーとする。初期仕様では、左ページ、右ページ、recto、verso、奇数ページまたは偶数ページの指定を扱わない。

### 配置

`page-break`は、Markdown文書のルート直下にあるトップレベルブロックの間だけに記述できる。段落、リスト項目、引用、文字揃え、コラム、脚注定義など、他のブロックの内部に記述した場合はエラーとする。

文書の先頭と末尾には記述できない。`page-break`の前後には、紙面へ表示されるトップレベルブロックがそれぞれ1個以上必要である。リンク定義、画像の定義および脚注定義は、その記述位置に紙面上の内容を生成しないため、前後のブロックとして数えない。

複数の`page-break`の間に紙面へ表示されるトップレベルブロックがない場合は、連続指定としてエラーにする。二つの`page-break`の間にリンク定義、画像の定義または脚注定義だけがある場合も連続指定として扱う。

白紙ページの挿入を目的として、文書先頭、文書末尾または連続した`page-break`を使用しない。空白ページは原稿内の著者向け記法ではなく、書籍プロジェクトの構成要素として扱う。

### 変換結果

`clono`は`page-break`を、要素名とclass名が固定された次の空要素へ変換する。

```html
<div class="clono-page-break" aria-hidden="true"></div>
```

改ページ用の要素は紙面へ表示する内容を持たないため、`aria-hidden="true"`を付ける。著者が指定した値を要素名、属性名またはclass名へ埋め込まず、IDも付与しない。

組版時点で改ページ用の要素が既にページ先頭へ配置された場合を含め、物理的なページ分割の結果は`clono`で予測または調整せず、Vivliostyleへ委譲する。

### CSS

`clono`は、改ページ用の要素を次ページから開始するため、次の規則を基盤CSSへ追加する。

```css
.clono-page-break {
  break-before: page;
}
```

基盤CSSは、npmパッケージ内の`styles/clono.css`として同梱する。書籍プロジェクト変換では、[書籍プロジェクト仕様](book-project.md)に従って生成済み原稿ツリーへ基盤CSSをコピーする。改ページは強制改ページ記法の機能そのものであるため、利用者のテーマCSSを組み込まない場合も基盤CSSを読み込めば機能するようにする。

### 診断と出力

directiveの種類、ラベル、属性または配置がこの仕様に適合しない場合は、[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従ってファイル名、行、列、directive名、問題の説明を持つ診断を生成する。

診断が一件でもある場合はAST変換を実行せず、部分的な出力Markdownも返さない。同じ文書に複数の独立した問題がある場合は、可能な範囲で入力位置の順に診断を収集する。

## 文字揃え記法

### 目的

文字揃え記法は、複数のMarkdown段落を一つの範囲として指定し、範囲内の文字揃えを変更する。初期仕様では、「はじめに」などの署名を想定した右寄せだけに対応する。

### 構文

Container directiveの`align`を使用し、`position`属性に`right`を指定する。

```markdown
:::align{position="right"}
2026年8月22日

Thunder Claw
:::
```

`align`はContainer directiveとして記述する。Text directiveまたはLeaf directiveとして記述した場合はエラーとする。

初期仕様で許可する属性は`position="right"`だけである。次のいずれかに該当する場合はエラーとする。

- `position`属性がない
- `position`属性の値が`right`以外である
- `position`以外の属性がある

`left`、`center`、`justify`などへの対応は、具体的な必要性が確認された場合に別途仕様を決定する。`id`、`class`、`style`などを著者が任意に指定する機能は初期仕様に含めない。

### 内容モデル

`align`の直下には、1個以上のMarkdown段落だけを許可する。空の`align`はエラーとする。

段落内では、次のmdastノードに対応するインラインMarkdownを許可する。子要素を持つノードは再帰的に検証する。

- `text`
- `emphasis`
- `strong`
- `inlineCode`
- `link`
- `linkReference`
- `break`
- `footnoteReference`

次の内容は初期仕様で許可せず、`align`内に出現した場合はエラーとする。この一覧にないmdastノードも、許可する仕様を追加するまではエラーとする。

- 見出し
- 箇条書きと番号付きリスト
- コードブロック
- 画像と参照形式の画像
- 表
- raw HTML
- `align`自身を含むすべてのdirective

`align`の入れ子は許可しない。将来導入する他のContainer directive内に`align`を配置できるかは、外側の記法の内容モデルを決定する際に別途検討する。

### 変換結果

`clono`は`align`を、要素名とclass名が固定された次の構造へ変換する。範囲内の段落とインラインMarkdownは保持する。

```markdown
<div class="clono-align-right">

2026年8月22日

Thunder Claw

</div>
```

著者が指定した値を要素名、属性名またはclass名へ埋め込まない。変換後のMarkdownは解析と直列化によって空白や改行が正規化される可能性があるが、段落と許可されたインラインMarkdownの意味を保持する。

### CSS

`clono`は、生成した構造が右寄せとして機能するための次の最小限の基盤CSSを同梱する。

```css
.clono-align-right {
  text-align: right;
}
```

基盤CSSは、npmパッケージ内の`styles/clono.css`として同梱する。

基盤CSSは、`clono`が生成する構造の機能上必要な規則だけを担う。フォント、余白、色などの書籍全体のデザインは利用者のテーマCSSの責務とする。書籍プロジェクト変換での配置と読み込み順は、[書籍プロジェクト仕様](book-project.md)に従う。

### 診断と出力

構文、directiveの種類、属性または内容モデルがこの仕様に適合しない場合は、[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従ってファイル名、行、列、directive名、問題の説明を持つ診断を生成する。

診断が一件でもある場合はAST変換を実行せず、部分的な出力Markdownも返さない。同じ文書に複数の独立した問題がある場合は、可能な範囲で入力位置の順に診断を収集する。

## コラム記法

### 目的

コラム記法は、本文から独立した雑談や補足を、必須タイトルと複数のMarkdownブロックを持つ一つの範囲として指定する。初期仕様では一種類のコラムだけに対応し、コラムの種類、ID、連番および参照は扱わない。

### 構文

Container directiveの`column`を使用し、directiveのラベルへタイトルを記述する。

```markdown
:::column[ちょっと休憩]
ここには本文を書く。

- 箇条書きも書ける
- 雑談も止まらない
:::
```

`column`はContainer directiveとして記述する。Text directiveまたはLeaf directiveとして記述した場合はエラーとする。

ラベルは必須とし、空文字または空白だけのタイトルはエラーとする。タイトルには改行を含まないプレーンテキストだけを許可し、強調、インラインコード、リンクなどのインラインMarkdownは許可しない。同じタイトルを持つ複数のコラムは許可する。

初期仕様では属性を一つも許可しない。`class`、`style`、`id`を含め、属性が一つでも指定された場合はエラーとする。複数種類のコラムが必要になった場合は、その用途と入力方法を別途決定する。

### 内容モデル

`column`の本文には、1個以上のMarkdownブロックを必要とする。タイトルだけで本文がないコラムはエラーとする。

初期仕様では、次のMarkdown表現を許可する。子要素を持つノードは再帰的に検証し、内部にも同じ内容モデルを適用する。

- 段落
- 強調
- 太字
- インラインコード
- リンクと参照形式のリンク
- 強制改行
- 箇条書きと番号付きリスト
- 引用
- コードブロック
- 画像と参照形式の画像
- Markdown表
- 脚注参照

リンク、画像および脚注の定義は、コラムの外へ記述する。特に、コラム内で脚注を使用する場合は、参照だけをコラム内へ置き、脚注定義をコラムの外へ置く。

```markdown
:::column[雑談]
これは脚注付きの雑談です[^column-note]。
:::

[^column-note]: コラムから参照する脚注。
```

次の内容は初期仕様で許可せず、`column`内に出現した場合はエラーとする。この一覧にないmdastノードも、許可する仕様を追加するまではエラーとする。

- 見出し
- 水平線
- raw HTML
- 脚注定義
- リンクおよび画像の定義
- `column`自身を含むすべてのdirective

`column`の入れ子は許可しない。文字揃え記法を含む他のdirectiveも初期仕様では許可せず、将来導入する記法をコラム内で使用できるかは、各記法の必要性と組み合わせを確認したうえで個別に決定する。

### 変換結果

`clono`は`column`を、要素名とclass名が固定された次の構造へ変換する。タイトルを`p.clono-column-title`へ変換し、本文のMarkdownブロックとインラインMarkdownは保持する。

```markdown
<aside class="clono-column">

<p class="clono-column-title">ちょっと休憩</p>

ここには本文を書く。

</aside>
```

タイトルはHTMLのテキスト内容としてエンコードする。著者が指定した値を要素名、属性名またはclass名へ埋め込まず、自動生成IDも付与しない。タイトルを見出し要素へ変換しないため、目次の掲載対象としない。

変換後のMarkdownは解析と直列化によって空白や改行が正規化される可能性があるが、許可された本文のMarkdown構造と意味を保持する。コラム内部のMarkdownからHTMLへの変換と、Pandoc風脚注から脚注構造への変換はVFMへ委譲する。コラムのページ分割と脚注のページ下部への配置はVivliostyleへ委譲する。

### CSS

`clono`は、短いコラムを可能な限り一ページへまとめ、タイトルだけがページ末尾に残ることを避けるため、次の分割制御を基盤CSSへ追加する。

```css
.clono-column {
  break-inside: avoid;
}

.clono-column-title {
  break-after: avoid;
}
```

一ページに収まらないコラムは複数ページへの分割を許容し、分割後のページでタイトルを繰り返さない。枠線、背景色、余白、文字サイズなどの外観は基盤CSSで指定せず、利用者のテーマCSSの責務とする。

基盤CSSは、npmパッケージ内の`styles/clono.css`として同梱する。書籍プロジェクト変換での配置、利用者テーマとの読み込み順、および上書き可能性の保証範囲は、[書籍プロジェクト仕様](book-project.md)に従う。

### 診断と出力

構文、directiveの種類、タイトル、属性または内容モデルがこの仕様に適合しない場合は、[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従ってファイル名、行、列、directive名、問題の説明を持つ診断を生成する。

診断が一件でもある場合はAST変換を実行せず、部分的な出力Markdownも返さない。同じ文書に複数の独立した問題がある場合は、可能な範囲で入力位置の順に診断を収集する。

## 更新方針

- 著者向け記法または実装契約を決定した場合は、この文書の対応する状態、記法、実現方法を同じPull Requestで更新する
- 仕様の一部を実装した場合は「実装中」とし、利用できる範囲と残る未実装の範囲を実現方法に明記する
- 「実装済み」に更新する場合は、仕様に対応する実装と自動テストが同じPull Requestに存在することを確認する
- 詳細仕様は、規模が小さい間はこの文書に追記する。索引や相互参照などの大きな機能は個別の仕様文書へ分離し、一覧から参照する
- 調査結果によって責務判断が変わった場合は、[Vivliostyleとclonoの責務整理](../vivliostyle-responsibilities.md)と関連する調査記録を先に、または同時に更新する
