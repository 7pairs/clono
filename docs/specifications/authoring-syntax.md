# clono著者向け記法

- 状態: 策定中
- 作成日: 2026-08-22
- 最終更新日: 2026-08-22

## 目的

この文書は、`clono`を利用する著者が原稿に記述できる記法と、その開発状態の正本である。`clono`の独自記法だけでなく、Thunder Clawの書籍制作に必要だが、標準Markdown、VFM、VivliostyleまたはテーマCSSへ委譲するため`clono`独自記法の対象としない機能も記録する。

Vivliostyleと`clono`の責務分担は、[Vivliostyleとclonoの責務整理](../vivliostyle-responsibilities.md)を正本とする。この文書では調査根拠を重複して記述せず、著者向けの入力方法と実装状態を示す。

## 状態の定義

| 状態 | 意味 |
| --- | --- |
| 検討前 | 必要性と責務は把握しているが、著者向け記法と詳細仕様をまだ検討していない |
| 仕様策定中 | 候補記法または要件を検討しており、実装契約が確定していない |
| 実装予定 | 著者向け記法と実装契約は確定したが、実装または自動テストが完了していない |
| 実装済み | 仕様に対応する実装と自動テストがあり、利用できる |
| 保留 | 将来再検討し得るが、現在の開発対象に含めない |
| 対象外 | `clono`独自記法または変換を実装せず、標準Markdown、VFM、Vivliostyle、テーマCSSなどへ委譲する |

`clono`の機能として必要ないと判断した場合は「対象外」とし、必要性はあるが初期開発で扱わない場合は「保留」とする。「対象外」は、書籍制作でその機能を利用できないことを意味しない。

| 定義リスト | 未定 | 検討前 | `clono`が著者向け記法を`dl`、`dt`、`dd`構造へ変換する候補 |
| コラム | 未定 | 検討前 | `clono`が必須タイトルと複数のブロックを保持するコンテナへ変換し、外観とページ分割をテーマCSSへ委譲する候補 |

| --- | --- | --- | --- |

## 文字揃え記法

### 目的

文字揃え記法は、複数のMarkdown段落を一つの範囲として指定し、範囲内の文字揃えを変更する。初期仕様では、「はじめに」などの署名を想定した右寄せだけに対応する。

### 構文

Container directiveの`align`を使用し、`position`属性に`right`を指定する。

```markdown
:::align{position="right"}
2026年8月22日

Thunder Claw
:::
```

`align`はContainer directiveとして記述する。Text directiveまたはLeaf directiveとして記述した場合はエラーとする。

初期仕様で許可する属性は`position="right"`だけである。次のいずれかに該当する場合はエラーとする。

- `position`属性がない
- `position`属性の値が`right`以外である
- `position`以外の属性がある

`left`、`center`、`justify`などへの対応は、具体的な必要性が確認された場合に別途仕様を決定する。`id`、`class`、`style`などを著者が任意に指定する機能は初期仕様に含めない。

### 内容モデル

`align`の直下には、1個以上のMarkdown段落だけを許可する。空の`align`はエラーとする。

段落内では、次のmdastノードに対応するインラインMarkdownを許可する。子要素を持つノードは再帰的に検証する。

- `text`
- `emphasis`
- `strong`
- `inlineCode`
- `link`
- `linkReference`
- `break`
- `footnoteReference`

次の内容は初期仕様で許可せず、`align`内に出現した場合はエラーとする。この一覧にないmdastノードも、許可する仕様を追加するまではエラーとする。

- 見出し
- 箇条書きと番号付きリスト
- コードブロック
- 画像と参照形式の画像
- 表
- raw HTML
- `align`自身を含むすべてのdirective

`align`の入れ子は許可しない。将来導入する他のContainer directive内に`align`を配置できるかは、外側の記法の内容モデルを決定する際に別途検討する。

### 変換結果

`clono`は`align`を、要素名とclass名が固定された次の構造へ変換する。範囲内の段落とインラインMarkdownは保持する。

```markdown
<div class="clono-align-right">

2026年8月22日

Thunder Claw

</div>
```

著者が指定した値を要素名、属性名またはclass名へ埋め込まない。変換後のMarkdownは解析と直列化によって空白や改行が正規化される可能性があるが、段落と許可されたインラインMarkdownの意味を保持する。

### CSS

`clono`は、生成した構造が右寄せとして機能するための次の最小限の基盤CSSを同梱する。

```css
.clono-align-right {
  text-align: right;
}
```

基盤CSSは、npmパッケージ内の`styles/clono.css`として同梱する。

基盤CSSは、`clono`が生成する構造の機能上必要な規則だけを担う。フォント、余白、色などの書籍全体のデザインは利用者のテーマCSSの責務とする。基盤CSSをVivliostyleのテーマへ組み込む方法は、書籍プロジェクトを扱うCLIの仕様とともに別途決定する。

### 診断と出力

構文、directiveの種類、属性または内容モデルがこの仕様に適合しない場合は、[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従ってファイル名、行、列、directive名、問題の説明を持つ診断を生成する。

診断が一件でもある場合はAST変換を実行せず、部分的な出力Markdownも返さない。同じ文書に複数の独立した問題がある場合は、可能な範囲で入力位置の順に診断を収集する。

## 更新方針

- 著者向け記法または実装契約を決定した場合は、この文書の対応する状態、記法、実現方法を同じPull Requestで更新する
- 「実装済み」に更新する場合は、仕様に対応する実装と自動テストが同じPull Requestに存在することを確認する
- 詳細仕様は、規模が小さい間はこの文書に追記する。索引や相互参照などの大きな機能は個別の仕様文書へ分離し、一覧から参照する
- 調査結果によって責務判断が変わった場合は、[Vivliostyleとclonoの責務整理](../vivliostyle-responsibilities.md)と関連する調査記録を先に、または同時に更新する
