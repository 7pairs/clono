# 単一ファイル変換CLI仕様

- 状態: 拡張予定
- 作成日: 2026-08-23
- 最終更新日: 2026-09-02

## 目的

この文書は、`clono`の変換パイプラインをコマンドラインから単一のMarkdownファイルへ適用するための初期仕様を定める。

このCLIは、著者が指定した入力Markdownを解析、検証、変換し、VFMが処理できるMarkdownを指定されたファイルへ出力する。Markdownの解析、診断、変換、直列化の契約は[ADR 0003](../decisions/0003-adopt-generic-directives-mdast-transformation-pipeline.md)に従い、利用可能な著者向け記法は[clono著者向け記法](authoring-syntax.md)を正本とする。

## 対象範囲

初期仕様では、`transform`サブコマンドでローカルファイルシステム上の入力ファイル1個を出力ファイル1個へ変換する。標準入力、標準出力、複数ファイル、ディレクトリおよび書籍プロジェクトの変換は扱わない。書籍プロジェクトの変換は、別の`build`サブコマンドが担う。

## コマンド形式

コマンド形式は次のとおりとする。

```text
clono transform <input> --output <output>
clono transform <input> -o <output>
```

- `<input>`には入力ファイルを位置引数として1個指定する
- `<output>`には出力ファイルを`--output`または`-o`で1個指定する
- 入力と出力の指定順は問わない
- 入力と出力の拡張子は制限しない
- `--output=<output>`形式は初期仕様ではサポートしない
- `-`で始まる引数はオプションとして扱う。`-output.md`のようなファイル名を指定する場合は、`./-output.md`のようにパスとして明示する
- 入力または出力を複数指定した場合は引数エラーとする
- 未知のオプションは引数エラーとする

相対パスは、`clono`を起動したときのカレントディレクトリを基準に解決する。

## ヘルプ

次の場合は使用方法と利用可能なオプションを標準出力へ表示し、ファイルを読み書きせず終了する。

- 引数を指定しない場合
- `-h`または`--help`を指定した場合

終了コードは`0`とする。`--version`は初期仕様では提供しない。

## 入出力ファイル

### 入力ファイル

入力には、読み取り可能な既存のファイルを指定する。次の場合はファイル操作エラーとする。

- 入力パスが存在しない
- 入力パスがディレクトリである
- 入力ファイルを読み取れない

入力はUTF-8のテキストとして読み込む。不正なUTF-8とBOMの扱いは、初期仕様の保証対象に含めない。

### 出力ファイル

出力先の親ディレクトリは、コマンド実行前に存在している必要がある。親ディレクトリが存在しない場合、`clono`はディレクトリを作成せず、ファイル操作エラーとする。

既存の出力ファイルは上書きする。出力パスがディレクトリである場合、または出力先へ書き込めない場合は、ファイル操作エラーとする。

入力と出力がファイルシステム上の同じファイルを指す場合は引数エラーとする。`input.md`と`./input.md`のようにパス表現だけが異なる場合も、同じファイルとして扱う。

### 出力形式

変換結果はUTF-8のMarkdownとして出力する。出力の改行コードは、実行OSにかかわらずLFとする。入力における空白、改行コード、末尾改行および記法上の表現を文字列として保持することは保証せず、解析と直列化を経たMarkdownの意味を保持する。

`clono`の基盤CSSは、この単一ファイル変換CLIではコピーまたは出力しない。書籍プロジェクト変換での基盤CSSの配置とVivliostyleへの組み込みは、[書籍プロジェクト仕様](book-project.md)で定める。

## 変換と診断

CLIは入力ファイルの内容と入力パスを既存の変換パイプラインへ渡す。

番号付き画像と画像参照を含む場合は、同じ入力ファイルにある参照対象を収集し、前方参照と後方参照を解決してから変換する。同じ入力ファイルに存在しない画像参照だけは、別原稿にある対象を参照している可能性があるため診断にせず、[番号付き画像と画像参照仕様](figure-references.md)で定める固定のプレースホルダーへ変換する。この例外は`clono transform`による単一ファイルでの執筆中のプレビューだけに適用し、不正な記法、重複IDまたは同一ファイル内で確認できる参照種別の不一致を許容しない。`clono build`ではこの例外を適用せず、`publication`に掲載したMarkdown原稿全体で参照を解決し、未定義参照を診断する。

変換パイプラインが一件以上の診断を返した場合は、すべての診断を入力位置の順に標準エラーへ出力する。各診断は次の形式とする。

```text
<file>:<line>:<column>: <message>
```

例を次に示す。

```text
manuscripts/introduction.md:3:1: `align`には`position="right"`が必要です。
```

診断がある場合は、出力ファイルを新規作成または更新しない。既存の出力ファイルがある場合も、その内容を保持する。

## 引数エラーとファイル操作エラー

引数エラーでは、問題の説明と使用方法を標準エラーへ出力する。ファイル操作エラーでは、対象パス、失敗した操作および利用者が原因を判断できる説明を標準エラーへ出力する。

通常の利用者向けエラーではJavaScriptのスタックトレースを表示しない。行と列を特定できない引数エラーおよびファイル操作エラーに、架空の位置情報を付与しない。

引数エラーまたは出力先の置き換え前にファイル操作エラーが発生した場合は、出力ファイルを新規作成または更新しない。既存出力の許可ビットを復元する処理は置き換え後に行うため、その処理だけが失敗した場合の状態は次節で定める。

## 出力ファイルの安全性

変換結果は、解析、検証、変換および直列化がすべて成功した後にだけファイルへ反映する。

書き込み途中の内容を出力ファイルとして公開しないため、変換結果を出力先と同じディレクトリの一時ファイルへ完全に書き込んだ後、出力先を置き換える。一時ファイルの作成または書き込みに失敗した場合は、既存の出力ファイルを保持する。最終的な置き換えに失敗した場合もファイル操作エラーとし、一時ファイルを可能な範囲で削除する。

一時ファイルは、所有者だけが読み書きできる権限で作成し、出力先へ置き換えるまでその権限を維持する。LinuxおよびmacOSでは、新しい出力ファイルの許可ビットを`0600`とする。既存の出力ファイルを置き換える場合は、`0600`の一時ファイルを出力先へ置き換えた後、既存ファイルが持っていた`0777`の範囲の許可ビットを最終的な出力ファイルへ適用する。

置き換え後に既存の許可ビットを復元できなかった場合は、LinuxおよびmacOSでは変換後の内容を`0600`の出力ファイルとして残し、ファイル操作エラーを標準エラーへ出力して終了コード`1`を返す。この段階では既存の内容が置き換え済みであり、安全な権限を持つ変換結果を削除することや、追加の失敗を招き得る復元処理は行わない。

Windowsでは、所有者、グループ、その他を区別するPOSIXの許可ビットを同じ数値として保証せず、Node.jsとファイルシステムが提供する書き込み権限の扱いに従う。所有者、ACL、拡張属性、タイムスタンプおよび特殊許可ビットの保持は、初期仕様の保証対象に含めない。

## 標準出力と終了コード

| 状況 | 標準出力 | 標準エラー | 終了コード |
| --- | --- | --- | --- |
| 変換成功 | なし | なし | `0` |
| 引数なし、`-h`、`--help` | 使用方法 | なし | `0` |
| 引数エラー | なし | 問題の説明と使用方法 | `1` |
| 変換パイプラインの診断 | なし | 位置付き診断 | `1` |
| ファイル操作エラー | なし | 問題の説明 | `1` |

## 初期仕様に含めない機能

次の機能は初期の単一ファイル変換CLIに含めない。具体的な必要性と、それを扱うCLIの責務を確認してから別途仕様を決定する。

- 標準入力からの読み込み
- 変換結果の標準出力への書き込み
- 複数ファイルの指定
- ディレクトリおよび書籍プロジェクトの一括変換
- 出力先ディレクトリの自動作成
- 設定ファイルの読み込み
- watchモード
- 基盤CSSのコピーまたはテーマへの自動組み込み
- プラグインの探索と読み込み
- JSONなど機械可読形式の診断
- 詳細なデバッグ出力
- `--version`

書籍プロジェクトの一括変換は、[書籍プロジェクト仕様](book-project.md)で別の`build`サブコマンドとして定める。単一ファイル変換は、書籍プロジェクト変換とのCLI統合時に`transform`サブコマンドへ移行した。npm公開前かつ実利用前の変更であるため、旧形式の`clono <input> --output <output>`との後方互換性は保証しない。

## 更新方針

- CLIの公開インターフェース、入出力契約、診断表示または終了コードを変更する場合は、実装と同じPull Requestでこの文書を更新する
- この仕様に対応する実装と自動テストが揃った場合は、状態を「実装済み」へ更新する
- 単一ファイル変換が利用可能になった場合は、READMEの開発状況、使用方法および制限事項を実装と同じPull Requestで更新する
