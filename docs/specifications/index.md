# 索引仕様

- 状態: 実装予定
- 作成日: 2026-09-13
- 最終更新日: 2026-09-13

## 目的

この文書は、Markdown原稿内で索引語と読みを指定し、書籍全体から出現位置を収集して、紙面上のページ番号と各出現位置へのリンクを持つ索引文書を生成するための初期仕様を定める。

clonoは、索引指定の解析、読みの正規化、分類、並べ替え、同じ項目の統合、本文マーカーおよび索引Markdownの生成を担う。VFMは生成済みのMarkdownとraw HTMLをHTMLへ変換し、VivliostyleとCSSは紙面上のページ番号、PDF内部リンクおよび索引のレイアウトを担う。

## 対象範囲

初期仕様では、次の機能を扱う。

- 索引語と読みを明示する著者向け記法
- ひらがな、カタカナおよび英数字の読みの正規化
- 濁点、半濁点、促音、小書き仮名および音引きを考慮した並べ替えキー
- 英数字と五十音の行への固定分類
- 実行環境に依存しない決定的な並べ替え
- 同じ索引項目の統合とすべての出現位置の保持
- 書籍全体で一意な本文マーカー
- `publication`に明示した位置への索引Markdownの生成
- 紙面上のページ番号と各本文マーカーへのPDF内部リンク
- 空の索引文書
- 不正な記法、読みの競合、設定の衝突などの診断

次の機能は初期仕様に含めない。

- 読みの省略、自動取得または推定
- 漢字の形態素解析または外部辞書との連携
- ユーザー定義の分類、分類順または分類見出し
- 階層索引
- ページ範囲
- 同一ページ番号の重複除去
- 主要ページの強調
- 索引項目間の相互参照
- 脚注、見出し、画像・表・コードリストのキャプション内の索引指定
- `clono transform`による索引文書の生成
- 索引だけを生成またはプレビューする専用コマンド
- `publication`からVivliostyle設定を生成するヘルパー

## 実装状況

2026年9月13日現在、この仕様は実装予定である。

[索引の読み正規化・分類・並べ替えに関する調査](../research/index-normalization.md)では、著者が指定した自然な読みから、正規化済み読みと並べ替えキーを生成し、固定分類、項目の統合および決定的な並べ替えを実行できることを確認している。

[書籍プロジェクトの生成索引に関する調査](../research/book-project-generated-index.md)では、`publication`を正本として索引指定を収集し、本文マーカーと索引Markdownを生成する候補パイプラインを確認している。[Vivliostyleの索引に関する調査](../research/vivliostyle-index.md)では、同じ候補構造から紙面上のページ番号とPDF内部リンクを生成できることを確認している。

## 索引指定

### 構文

索引指定には、Text directiveの`index`を使用する。

```markdown
これは:index[バックナンバー]{reading="ばっくなんばー"}についての説明です。
```

`index`のラベルを本文へ表示する索引語、`reading`属性を分類と並べ替えに使用する読みとする。索引語と`reading`はともに必須とし、空文字または空白だけの値を許可しない。

索引語には、改行を含まないプレーンテキストだけを許可する。強調、インラインコード、リンク、画像またはその他のMarkdownを含むラベルはエラーとする。同じ索引語を複数箇所へ指定できる。

初期仕様で許可する属性は`reading`だけである。`reading`の省略、または`reading`以外の属性をエラーとする。Container directiveまたはLeaf directiveとして記述した`index`もエラーとする。

### 配置

`index`は、通常の段落内へ記述できる。段落が次のブロックに含まれる場合も許可する。

- Markdown文書のルート
- 箇条書きと番号付きリストの項目
- 引用
- `column`の本文

`index`を強調、リンクまたは他のインライン要素の子として記述せず、通常のテキストと同じ位置へ置く。次の位置では初期仕様として許可しない。

- 見出し
- 脚注参照と脚注定義
- 画像、表およびコードリストのキャプション
- `column`以外のdirective
- コードブロックとインラインコード
- raw HTML

`index`を他の`index`へ入れ子にしない。許可されていない位置に索引指定がある場合は、黙って無視したり通常のテキストとして残したりせず診断する。

## 読みの正規化

### 入力範囲

`reading`はNFKCへ変換した後、次のいずれかとなる値を指定できる。

- ひらがな、カタカナの`ァ`から`ヺ`まで、および音引きだけからなる日本語
- ASCII英数字から始まり、ASCII英数字、半角空白および`.+@#/_-`だけからなる英数字列

半角カタカナ、全角の英数字および全角記号は、NFKCによって許可された値へ変換できる場合に受理する。入力の先頭または末尾に空白がある場合は、暗黙に取り除かずエラーとする。日本語と英数字が混在する読み、漢字を含む読み、許可していない記号を含む読み、および分類可能な英数字から始まらない読みもエラーとする。

日本語をひらがな化した後は、かなへ後置される結合濁点または結合半濁点を許可する。結合記号だけの入力、結合記号が連続する入力、先行するかなから母音を導出できない音引きはエラーとする。

### 正規化済み読み

clonoは著者が指定した読みから、次の順序で正規化済み読みを生成する。

1. Unicode正規化形式NFKCへ変換する
2. カタカナの`ァ`から`ヺ`までを対応するひらがなへ変換する
3. 英字をASCII小文字へ変換する

`ヷ`、`ヸ`、`ヹ`および`ヺ`は、それぞれ対応するひらがなと結合濁点の組み合わせへ変換する。正規化済み読みでは、濁点、半濁点、小書き仮名および音引きを保持する。

### 並べ替えキー

日本語の正規化済み読みに対し、次の順序で並べ替えキーを生成する。

1. 音引きを、直前のかなが表す母音へ展開する
2. 濁点と半濁点を除去する
3. 促音を含む小書き仮名を、対応する通常のかなへ変換する

たとえば、`ばっくなんばー`の並べ替えキーは`はつくなんはあ`となる。英数字の正規化済み読みは追加変換せず、そのまま並べ替えキーとする。

著者が指定した読み、正規化済み読みおよび並べ替えキーは別の値として扱う。正規化済み読みと並べ替えキーは内部データとして使用し、本文マーカーまたは生成索引へ属性として出力しない。

## 分類と並べ替え

### 固定分類

並べ替えキーの先頭文字を使用し、次の固定順で分類する。

| 順序 | 識別子 | 見出し | 対象となる先頭文字 |
| --- | --- | --- | --- |
| 1 | `alphanumeric` | 英数字 | `a`から`z`、`0`から`9` |
| 2 | `a` | あ行 | あ、い、う、え、お |
| 3 | `ka` | か行 | か、き、く、け、こ |
| 4 | `sa` | さ行 | さ、し、す、せ、そ |
| 5 | `ta` | た行 | た、ち、つ、て、と |
| 6 | `na` | な行 | な、に、ぬ、ね、の |
| 7 | `ha` | は行 | は、ひ、ふ、へ、ほ |
| 8 | `ma` | ま行 | ま、み、む、め、も |
| 9 | `ya` | や行 | や、ゆ、よ |
| 10 | `ra` | ら行 | ら、り、る、れ、ろ |
| 11 | `wa` | わ行 | わ、ゐ、ゑ、を、ん |

項目を一つも持たない分類は生成索引へ出力しない。

### 決定的な並べ替え

索引項目は、次のキーを順に比較する。

1. 固定された分類の順位
2. 並べ替えキー
3. 正規化済み読み
4. NFKCで正規化した索引語
5. 元の索引語
6. `publication`順と原稿内の入力位置からなる初出位置

各文字列はUnicodeコードポイント順で比較し、`localeCompare()`、`Intl.Collator`または実行環境のロケールへ委譲しない。この規則は環境に依存しない決定性を保証するためのものであり、一般的な日本語辞書順の完全な再現を目的としない。

### 項目の統合

入力された索引語の文字列が一致し、かつ正規化済み読みが一致する索引指定は、一つの索引項目へ統合する。すべての出現位置は、`publication`順、その中では原稿内の入力位置順に保持する。

索引語自体はUnicode正規化によって統合しない。異なる索引語は、読みまたは並べ替えキーが一致しても別の項目とする。

同じ索引語へ異なる正規化済み読みが指定された場合は、一方を暗黙に採用せず読みの競合として診断する。並べ替えキーだけが一致し、正規化済み読みが異なる場合も競合とする。

## 本文マーカー

### 収集順とID

`clono build`は、`publication`に`document`として掲載され、拡張子を小文字化した結果が`.md`となる原稿だけを索引収集の対象とする。原稿は`publication`順、その中では索引指定の入力位置順に収集する。

各索引指定には、書籍全体の収集順で1から始まる連番を割り当て、次のHTML IDを生成する。

```text
clono-index-marker-<連番>
```

`clono-index-marker-`で始まるIDをclonoの予約名前空間とする。著者は見出しIDまたはraw HTMLのIDにこの接頭辞を使用しない。

clonoは、管理対象である見出し、番号付き画像、番号付き表、番号付きコードリストおよび索引マーカーから導出したHTML ID同士の衝突を診断する。著者が直接記述した任意のraw HTMLまたはVFMが生成するすべてのIDとの衝突を網羅的に検出することは保証しない。

### 変換後Markdownに含める構造

索引指定は、要素名、class名およびIDの接頭辞が固定されたraw HTMLへ変換する。

```html
<span class="clono-index-marker" id="clono-index-marker-1">バックナンバー</span>
```

索引語はHTMLのテキスト内容としてエンコードする。読みと並べ替えキーを要素の内容、classまたは`data-*`属性へ出力しない。VFM変換後も、同じ要素、class、IDおよび索引語を保持することを期待する。clono基盤CSSでは本文マーカーの外観を変更せず、周囲の本文と同じ見た目で表示する。

### `clono transform`

`clono transform`は、単一の入力Markdownにある索引指定を入力位置順に収集し、その文書内で1から始まるIDを持つ本文マーカーへ変換する。索引文書、分類またはページ番号は生成しない。

単一ファイル変換で生成するIDはプレビュー用であり、`clono build`が書籍全体の収集順から割り当てるIDとの一致を保証しない。構文、読みまたは配置が不正な場合は診断し、部分的な変換結果を出力しない。

`clono build`で`publication`に掲載されていないMarkdownは、索引収集へ含めず、単一文書として同じ規則で本文マーカーへ変換する。そのローカルIDは書籍全体の名前空間へ登録せず、生成索引にも掲載しない。

## 生成索引

### `publication`の設定

生成索引は、`clono.config.mjs`の`publication`へ次の形式で明示する。

```javascript
{
  type: "index",
  path: "generated/index.md",
  title: "索引",
  includeInToc: true,
}
```

各項目はすべて必須とし、次の意味を持つ。

| 項目 | 型 | 意味 |
| --- | --- | --- |
| `type` | 文字列 | `index` |
| `path` | 文字列 | `outputRoot`からの相対索引Markdownパス |
| `title` | 文字列 | 索引文書のH1として出力するプレーンテキスト |
| `includeInToc` | 真偽値 | Vivliostyleの目次へ掲載するか |

`path`には、安全な相対パスであり、拡張子を小文字化した結果が`.md`となるパスを指定する。空文字、絶対パス、`outputRoot`の外側へ出るパスまたはディレクトリを指定できない。

生成先が`sourceRoot`内の入力ファイルと同一である場合、または一方が他方の祖先・子孫となる場合は、入力ツリーのコピーまたは索引の書き込みと衝突するためエラーとする。パス要素の境界を使って判定し、文字列の接頭辞が一致するだけの別パスは衝突としない。`_clono/`予約領域も生成先に使用できない。

`title`は空でないプレーンテキストとする。Markdownとして意味を持つ文字を含めることはできるが、生成時にmdastの`text`ノードとして扱い、意図しないMarkdownへ解釈しない。`type`、`path`、`title`および`includeInToc`以外の項目はエラーとし、`kind`は指定しない。

`publication`に`index`を最大一件だけ指定できる。`index`はすべての`chapter`および`appendix`文書より後、すべての`backmatter`文書より前へ配置する。`blank-page`はこの順序検証の対象外とし、索引の前後へ配置できる。生成索引は章番号または付録番号を持たず、それらのカウンターも進めない。

`includeInToc`が`true`の場合は、利用者が`vivliostyle.config.mjs`で索引を目次へ掲載する。初期仕様では、clonoがVivliostyle設定を生成または変更しない。

### 索引指定と設定の関係

掲載Markdownに索引指定が一件以上ある場合は、`publication`に`index`が必要である。生成索引がない場合は設定と原稿の不整合として診断する。

`index`があり、掲載Markdownに索引指定が一件もない場合は、タイトルだけを持つ空の索引Markdownを生成する。執筆途中に索引指定がまだ存在しないことをエラーとしない。

### 生成するMarkdown

生成索引の先頭には、`title`をプレーンテキストとして持つH1を一つ出力する。続いて、項目を持つ分類だけを固定順で出力する。空の索引ではH1だけを出力する。

各分類は、分類を表す`section`、H2および索引項目を持つ`dl`で構成する。たとえば、は行は次の構造となる。

```html
<section class="clono-index-group clono-index-group-ha">
<h2>は行</h2>
<dl class="clono-index-list">
<div class="clono-index-entry">
<dt>バックナンバー</dt>
<dd><a class="clono-index-page" href="../chapter-two.html#clono-index-marker-8" aria-label="バックナンバーの出現1"></a></dd>
</div>
</dl>
</section>
```

分類ごとのclassには、固定分類で定めた識別子を使用する。索引語は`dt`のテキスト内容としてエンコードする。同じ項目が複数箇所にある場合は、一つの`dd`へ出現順に空の`a.clono-index-page`を並べ、リンクの間へ次の固定要素を置く。

```html
<span class="clono-index-separator">,&nbsp;</span>
```

各リンクの`aria-label`は、索引語、固定文言`の出現`および項目内で1から始まる出現番号から生成する。動的な索引語、タイトル、URLおよび属性値は、埋め込むHTMLの文脈に応じてエンコードする。

### 出現位置へのURL

各リンクの`href`は、生成索引の変換後HTMLパスから、索引指定を含む原稿の変換後HTMLパスへの相対URLと本文マーカーIDを組み合わせる。

ファイルシステム上の相対パスを計算した後、各パス要素をUTF-8でパーセントエンコードし、`/`を区切り文字として保持する。エンコード済みパスの後へ`#clono-index-marker-<連番>`を追加し、完成したURLをHTML属性値としてエンコードする。

## CSSとVivliostyle

clono基盤CSSは、空のページ番号リンクへ、参照先の紙面上のページ番号を表示するための次の規則を持つ。

```css
.clono-index-page::after {
  content: target-counter(attr(href url), page);
}
```

Vivliostyleは、`target-counter()`によるページ番号の生成と、各`a`要素から本文マーカーへのPDF内部リンクを担う。同じ索引項目が同一ページへ複数回出現する場合も、clonoはすべての出現位置を保持する。Vivliostyleが生成するページ番号は`2, 2, 3`のように重複し得るが、初期仕様ではこれを許容する。

索引語が改ページ位置をまたぐ場合は、本文マーカーの先頭があるページを出現ページとして扱えればよく、複数ページの範囲は生成しない。

基盤CSSは索引の機能に必要なページ番号生成だけを担う。分類見出し、段組み、余白、字下げ、罫線、色、リンク装飾、改ページ制御などの紙面デザインは利用者テーマの責務とする。

## 診断と失敗時の契約

次の問題を含め、この仕様に適合しない設定または索引指定を診断する。

- `publication`に複数の`index`がある
- `index`の必須項目、不明な項目、型、パス、タイトルまたは配置が不正である
- 生成索引のパスが入力ツリーまたはclonoの予約領域と衝突する
- 掲載Markdownに索引指定があるが`index`がない
- `index`のdirective種類、索引語、属性、読みまたは配置が不正である
- 同じ索引語へ異なる正規化済み読みが指定されている
- clonoが管理するHTML IDが衝突する
- 出現位置への相対URLを安全に生成できない

`clono build`は、索引固有の設定を検証した後、掲載Markdownをすべて解析し、可能な範囲で索引診断を収集する。位置を持たない設定診断を`publication`の順に、原稿に属する診断を`publication`順および原稿内の入力位置順に並べる。同じ索引語の読みが競合する場合は、最初の指定と異なる正規化済み読みを持つ後続の指定位置を診断する。

索引診断が一件でもある場合は、いずれの掲載Markdownについても索引マーカーへのAST変換とMarkdownの直列化を開始せず、索引Markdownも生成しない。部分的な変換計画を後続処理へ渡さず、正式な`outputRoot`と既存の生成済み原稿ツリーを変更しない。

`clono transform`で索引診断が一件でもある場合も、部分的な出力Markdownを返さず、既存の出力ファイルを変更しない。CLIにおける診断の表示形式、終了コードおよび出力保護は、[単一ファイル変換CLI仕様](single-file-cli.md)と[書籍プロジェクト仕様](book-project.md)に従う。

## 更新方針

- 著者向け記法、読みの正規化、分類、統合、出力構造、設定または診断契約を変更する場合は、実装と同じPull Requestでこの文書を更新する
- 実装へ着手した場合は状態を「実装中」、仕様に対応する実装と自動テストが揃った場合は「実装済み」へ更新する
- Vivliostyle、VFMまたは生成構造の変更によって責務判断が変わる場合は、関連する調査記録と責務整理表も更新する
- 読みの自動取得、ユーザー定義分類または同一ページ重複の除去を追加する場合は、初期仕様へ暗黙に含めず、要件と実装方式を改めて決定する
