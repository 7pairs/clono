# 0009 調査用REPLスクリプトの個人環境依存を解消する

- 状態：手順書の独立レビュー・再レビュー完了。本作業未着手。

## 1. 目的

実装環境の調査で使用した`observe-repl.mjs`から、個人のホームディレクトリを含むJDKの固定指定を取り除く。

実行前に選択した環境を使ってREPLを観測できるようにし、macOSでESM・CommonJS両ターゲットの接続・評価を確認する。過去の調査記録は保持し、今回の検証結果と区別する。

## 2. 対象範囲

### 今回扱うもの

- `research/implementation-environment/scripts/observe-repl.mjs`の環境変数の扱いの修正。
- 環境変数の引き継ぎを確認するテスト。
- macOSでのESM・CommonJS両ターゲットの実REPL検証。
- 関連する再現手順とbacklogの更新。
- 今回の変更を踏まえた構造の見直し。

### 今回扱わないもの

- スクリプトによるJDKの自動探索・自動選択・インストール。
- Node.js・npm・JDKや依存パッケージの採用版の変更。
- Windows・Linuxでの動作確認とCIへの組み込み。
- 製品のREPL基盤や、調査スクリプト全体の改修。
- 保存済みログの再加工、過去の実験結果・ハッシュ・判断の書換え。
- READMEや開発環境仕様など、現行案内全体の整理。
- Git履歴や外部サービス上の情報の変更。

対象外の対応が必要になった場合は、理由と影響を整理して相談する。

## 3. 修正と検証の方針

### 3.1 実行環境の引き継ぎ

JDKは、実行前にリポジトリルートの`.sdkmanrc`と`sdk env`などで選択する。

スクリプトは、実行元の`JAVA_HOME`と`PATH`を子プロセスへ引き継ぐ。固定のJDKパスを設定したり、`PATH`へJDKの配置先を追加したりしない。`JAVA_HOME`が未設定の場合も、スクリプト独自の値を補わない。

ESM・CommonJSの観測、評価する式、ログの形式と相対保存先は維持する。環境の引き継ぎと無関係な動作変更は行わない。

### 3.2 過去の記録の保全

実REPLの検証は一時ディレクトリの検証用コピーで行い、元の調査ディレクトリにある保存済みログへ書き込まない。

今回保存する結果は、`research/implementation-environment/results/repl-environment-inheritance/`へ分ける。実行日・環境・コマンド・結果を記録し、今回の修正後の検証であることを明示する。

保存するログは必要なものに絞り、公開前に個人環境情報を確認する。加工した場合は、加工範囲を記載して技術的な意味を保持する。

## 4. 作業の進め方

各手順は[開発フロー](../development-workflow.md)に従い、着手依頼、作業・検証、独立レビュー、指摘対応と必要な再レビュー、二人の内容確認を行う。開発者によるコミットと、次の手順への着手依頼を受けて進む。

各手順の初回レビューは、作業中の会話履歴を引き継がない新しいレビュアーに依頼する。再レビューは原則として同じレビュアーに依頼する。

Git操作とPR作成・マージは開発者が担当する。作業結果と判断は、本手順書の実施記録へ残す。

## 5. 作業手順

### 手順1：動作・設計・テスト項目を整理する

**作業**

- スクリプト、shadow-cljs設定、既存の再現手順、保存済みログの関係を確認する。
- 第3節の方針に沿って、変更後の動作・設計・テスト項目を調査READMEの新しい節にまとめる。既存の資料調査の記述と区別する。
- 一時コピーの作成、依存の準備、watchの起動、観測、停止、結果の保存までの具体的な検証手順を記載する。
- 保存済みログと依存定義・lockfileについて、検証前後の比較対象を特定する。

テスト項目には、次を含める。

| 対象 | 確認する動作 |
|---|---|
| `JAVA_HOME`設定時 | 指定した値が、両ターゲットの実行環境とREPL接続プロセスへ引き継がれる |
| `JAVA_HOME`未設定時 | スクリプトが独自の値を補わない |
| `PATH` | 実行元の値が書き換えられずに引き継がれる |
| ログ保存 | 保存先がない場合と既にある場合の両方で、両ターゲットのログを保存できる |
| 実REPL | 両ターゲットで評価結果`REPL_OK`を確認する。各REPL接続プロセスが終了コード0・終了シグナルなしで終了し、タイムアウトによる強制終了が発生していないことを確認する |
| 記録の保全 | 元の保存済みログと依存定義・lockfileが変更されない |

環境変数とログ保存のテストでは子プロセスをスタブに置き換え、実REPLの確認と区別する。テストのために実装を広く抽象化せず、Node.jsの標準機能で確認できる構成を基本とする。

**成果物・レビュー観点**

変更後の動作・設計・テスト項目と具体的な検証手順。環境の引き継ぎを外から確認でき、過去の記録を上書きしないことを確認する。

**判断地点**

テスト項目と検証方法への独立レビュー、必要な指摘対応、二人の合意を終えてから手順2へ進む。

### 手順2：テストを追加し、固定指定を取り除く

**作業**

1. 合意したテスト項目に基づき、`node:test`によるテストを追加する。
2. 修正前のコードで、環境変数の引き継ぎに関するテストが期待する理由で失敗することを確認する。
3. JDKの固定指定と`PATH`の書換えを取り除く。
4. テストを実行し、合意した項目が成功することを確認する。
5. 変更したJavaScriptの構文と差分を確認する。

テストは一時ディレクトリで実行し、実際のJavaやREPLを起動せずに確認できるようにする。構文エラーや準備不足による失敗を、修正前の動作の問題を検出した結果として扱わない。

**成果物・レビュー観点**

修正したスクリプト、テストコード、修正前後の検証結果。固定パスがなくなり、環境変数を引き継ぎ、既存の観測処理とログ保存を維持していることを確認する。

**判断地点**

無関係なプロセス制御の変更や、広い構造変更が必要になった場合は、実装を広げる前に相談する。

### 手順3：macOSで実REPLを検証する

**作業**

1. リポジトリルートで環境を選択し、Node.js・npm・JDKの実バージョンを確認する。
2. 手順1で定めた比較対象の内容またはハッシュを記録する。
3. 修正済みコードと必要な調査用ファイルから検証用コピーを作成する。既存の生成物やキャッシュは持ち込まず、調査用lockfileに従って依存を準備する。
4. 検証用コピーで両ターゲットのwatchを起動し、ビルド完了を確認する。
5. 選択した環境を引き継いで`observe-repl.mjs`を実行する。
6. 両ターゲットで接続・式の評価・`REPL_OK`・ログ保存を確認する。各REPL接続プロセスについて、終了コード0・終了シグナルなし・タイムアウトによる強制終了なしを正常終了の基準とする。
7. 今回起動した実行環境とwatchを停止し、関連プロセスが残っていないことを確認する。
8. 元の保存済みログ、依存定義・lockfileに変更がないことを確認する。
9. 必要なログを公開用に確認し、今回の保存先へ分けて記録する。

スクリプトの終了コードだけで成功と判断せず、両ターゲットの評価結果を確認する。検証に失敗した場合も、今回起動したプロセスを停止する。

**成果物・レビュー観点**

今回の実行環境、コマンド、両ターゲットの結果、保存済み記録の比較結果。スタブによるテストと実REPLの検証、過去と今回の結果を区別できることを確認する。

**判断地点**

依存の更新や、環境変数の修正を超える対応が必要になった場合は相談する。失敗を理由に過去の調査結論を書き換えない。

### 手順4：構造を見直し、文書と記録を整える

**作業**

- スクリプトとテストの構造を、既存の調査コードや製品のREPL基盤との関係も含めて見直す。
- リファクタリングの実施・見送り・切り出しを判断する。修正する場合は範囲を合意し、検証とレビューを行う。
- 調査READMEに、環境選択、作業ディレクトリ、実行方法、保存済みログを保護する方法、今回の結果への参照を整える。
- backlogの対象課題を、確認した結果に基づいて更新する。
- 手順書0008から、後続対応として本手順書へのリンクを追記する。当時の記録は保持する。
- 日本語を`yomiyasu`で推敲し、リンク、差分、公開情報、名前と呼称を確認する。

未追跡ファイルも全文確認の対象に含め、通常の`git diff --check`だけで確認を終えない。動作に影響する追加変更がなければ、成功済みの動作検証は重複実行しない。

**成果物・レビュー観点**

構造の見直し結果、再現手順、backlog、本手順書と関連リンク。再現案内が修正後のコードと一致し、確認した範囲と未確認事項が明確であることを確認する。

## 6. 完了条件

- 個人環境の固定JDKパスと、それに基づく`PATH`の書換えがない。
- 環境変数の引き継ぎとログ保存のテストが成功している。
- macOSでESM・CommonJS両ターゲットの実REPLで`REPL_OK`を確認し、各REPL接続プロセスが終了コード0・終了シグナルなし・タイムアウトによる強制終了なしで終了している。
- 保存済みログと過去の実験結果・ハッシュを保持し、今回の結果を区別している。
- 関連する再現手順とbacklogが更新されている。
- 構造の見直し、必要な検証・独立レビュー・再レビュー・二人の内容確認を終えている。
- 公開情報と名前・呼称の確認を終えている。

全手順の確認後、本手順書には「全手順の実施・内部確認完了」と記録する。対応するPRでは既存CIと外部レビューを確認し、作業全体の完了を判断する。既存CIの成功を、今回対象外としたWindows・Linuxでの調査用REPL検証の代わりにはしない。
