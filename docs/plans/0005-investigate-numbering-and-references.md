# 0005 採番・参照・目次を既存機能で実現できる範囲を調べる

- 状態：手順2の実施・検証・独立レビュー・再レビュー・二人の確認は完了。手順3・4は未着手。

## 1. 目的

見出し、図、表、コードリストの採番と参照、目次の生成について、CSS・Vivliostyle・VFMの既存機能で満たせる範囲と不足を調べる。

見出しの出力を差し替えた場合も含め、既存機能に任せる処理と、clonoで補う必要がある処理を判断できる状態にする。

要件の出発点は、[旧前処理スクリプトの要件整理](../../research/legacy-preprocessor/results/requirements.md#12-要件に結び付けた後続の確認事項)のT03～T05とする。

## 2. 前提と対象範囲

[開発フロー](../development-workflow.md)と、そこから参照する憲章・SDD・Sora Flowに従う。Markdownの処理経路は、[実装環境の仕様](../specs/implementation-environment.md)を維持する。

### 必須要件として確認するもの

| 対象 | 確認する内容 |
|---|---|
| 見出し | 章・節・項の採番、番号だけの参照、見出し本文だけの参照、番号と見出し本文を組み合わせた参照 |
| 番号なし見出し | 目次への掲載と見出し本文の参照。番号だけの参照は対象外 |
| 目次 | 掲載対象の見出し番号・見出し本文・ページ番号・リンク。番号なし見出しには番号を表示しない |
| 図・表・コードリスト | 種類ごとの採番・キャプション・番号参照。本文と付録の両方を対象にする |
| 複数原稿 | 原稿をまたぐ参照、本文と付録の区別、原稿順の変更に伴う番号と参照の更新 |
| 見出しの出力差し替え | 文字を残してHTML構造を変える場合と、章タイトルを画像で見せる場合の採番・参照・目次掲載の維持 |

参照は、参照先より前に書く場合と後に書く場合、同じ原稿内と別原稿の場合を確認する。

調査例の採番は、次を基本にする。

- 本文：`第1章`、`1.1`、`1.1.1`。
- 付録：`付録A`、`A.1`、`A.1.1`。
- 図・表・コードリスト：種類ごとに章単位で採番する。

これは調査用の基準であり、製品の表記や設定形式を確定するものではない。

### 条件付きの希望として確認するもの

- 見出し番号の表記を変更できること。
- 目次へ載せる見出しの階層を変更できること。
- 本文中の見出し・図・表・コードリスト参照に、参照先へのリンクを付けられること。

番号表記の変更が難しければ固定を許容する。目次の掲載階層は、変更が難しければH2までの固定を許容する。本文中の参照先ページ番号は求めない。

### 評価する出力

PDFを主な評価対象とし、表示内容、参照先、目次のページ番号を確認する。リンクはPDF内のリンク情報と、閲覧時の移動先を確認する。

生成HTMLや中間Markdownは、情報がどの段階で付与・保持されるかを調べる材料にする。通常のブラウザーでのHTML表示は合否条件に含めない。

### 今回扱わないもの

- clonoの製品実装。
- 独自記法、設定形式、公開する拡張APIの確定。
- 本全体の入出力・章順共有の詳細設計。
- 索引、脚注・コラムなどとの全体的な組み合わせ検証。
- 見出し以外の要素の出力差し替え。
- 前作のデザインの完全再現、旧記法との互換性。
- 全機能の実装順、配布・公開方法の確定。
- CIの案内など、今回の調査に直接関係しない文書の更新。

複数原稿の検証に必要な最小限の構成と組版設定は、調査用として用意する。
