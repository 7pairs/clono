# clonoのライセンス方針

## 1. 目的と参照先

本文書は、clonoのライセンスの適用範囲と、ファイルの追加・更新・配布時に守る表示ルールを定める。

「そら」は、開発者がCodex上で設定しているAIの人格を指す。

採用理由は、[配布ライセンスを採用したADR](../decisions/0001-adopt-project-license.md)に記録する。比較の根拠は[配布ライセンスの比較調査](../../research/project-license/README.md)を参照する。

本文書に記載する管理ルールは、ライセンス本文の条件と区別する。利用・再配布の正式な条件は、[Apache License 2.0公式本文](https://www.apache.org/licenses/LICENSE-2.0)に従う。ルートの[LICENSE](../../LICENSE)に同じ本文を配置している。

## 2. 採用ライセンスと適用範囲

### 2.1 clonoの構成物

clonoの配布ライセンスはApache License 2.0とし、識別子は`Apache-2.0`とする。

clono側でライセンスを決められるコード・文書・サンプル・調査資料・設定ファイルには、原則として同じライセンスを適用する。第三者由来の内容は、第6節に従って区別する。

### 2.2 利用者の原稿と生成した本

利用者の原稿や生成した本には、clonoを使ったという理由でApache-2.0を適用しない。clonoの利用を理由とする、本の配布・頒布形式への制限も設けない。

第三者由来の内容を原稿や本に含める場合は、その内容の条件を別途確認する。この方針によって、他者の権利やライセンス条件がなくなるわけではない。

## 3. 著作権表示の名義と年

開発者本人の著作権表示には、`HASEBA Junya (7pairs)`を用いる。第三者の表示をこの名義に置き換えない。

年は、そのファイルを最初に公開する年を記載する。その後に変更した場合は、最初の公開年を残して、変更した年までの範囲に更新する。

| 状況 | 表示例 |
|---|---|
| 2026年に初めて公開する | `Copyright 2026 HASEBA Junya (7pairs)` |
| 同じファイルを2027年にも変更する | `Copyright 2026-2027 HASEBA Junya (7pairs)` |
| 2027年になってもファイルを変更していない | `Copyright 2026 HASEBA Junya (7pairs)`のまま |

年が変わっただけでは一括更新しない。ファイルごとに単年と年の範囲が混在していても、この管理ルール上は問題ない。

## 4. ファイル単位の表示

### 4.1 基本のヘッダ

管理する各ソースファイルには、原則として次の2行を、その形式に合うコメント構文で記載する。文書と設定ファイルにも、コメントを書ける場合は同じ方針を適用する。

```text
Copyright 2026 HASEBA Junya (7pairs)
SPDX-License-Identifier: Apache-2.0
```

年は第3節に従う。第三者由来のファイルと自動生成ファイルは、一律にこのヘッダを追加せず、第5・6節に従う。

Markdownでは、次のようにHTMLコメントで記載する。

```markdown
<!--
Copyright 2026 HASEBA Junya (7pairs)
SPDX-License-Identifier: Apache-2.0
-->
```

YAMLなど、`#`によるコメントを書ける形式では、次のように記載する。

```yaml
# Copyright 2026 HASEBA Junya (7pairs)
# SPDX-License-Identifier: Apache-2.0
```

ファイル形式が要求する先頭行や、実行に必要な記述を妨げない位置に置く。実装言語に固有のコメント構文は、その言語を採用したときに確認する。

著作権表示とSPDX識別子による短いヘッダは、[ASFの適用案内](https://www.apache.org/foundation/license-faq.html#Apply)を参考にしている。短いヘッダだけで、再配布時に必要なライセンス本文の提供を済ませたとは扱わない。

### 4.2 コメントを書けない形式

対象のファイルパス、著作権表示、ライセンスを別の文書にまとめ、対応関係を明示する。具体的な文書名と配置は、その形式のファイルを追加するときに決める。

そのファイルを配布する場合は、対応する表示も配布物に含める。コメントのためにファイル形式を変更したり、利用できなくなる記述を追加したりしない。

## 5. 自動生成ファイル

本節は、clono自身のリポジトリや配布物に含める自動生成ファイルを対象とする。利用者の原稿や生成した本は、第2.2節に従う。

自動生成ファイルを直接編集して表示を追加・更新しない。表示は生成元や生成処理で管理し、配布する場合は配布物にも必要な表示を含める。

具体的な方法は、生成元・生成方法・配布形態が決まったときに確認する。第三者由来の内容を含む場合は、その条件も確認する。

## 6. 第三者由来の内容

コード、文書、素材など、第三者由来の内容を取り込む前に、次を確認する。

- clonoでの利用・改変・再配布が許されているか。
- 著作権表示、ライセンス本文、NOTICE、変更表示など、何を保持・追加する必要があるか。
- 必要な表示を、リポジトリと配布物のどこに含めるか。

元の権利者の表示とライセンスを尊重し、clonoの表示で削除・上書きしない。Apache-2.0のファイルを変更して再配布する場合は、変更したことをファイルに明確に表示する。著作権表示の年の更新だけで、変更表示を済ませたとは扱わない。[公式本文・第4節](https://www.apache.org/licenses/LICENSE-2.0)

条件が不明な場合は、取り込む前に開発者とそらで相談する。

出典と確認結果は、採用時の調査資料など、あとから確認できる場所に記録する。必要な表示の具体的な配置も、そのときに決める。

未選定の依存ライブラリを確認済みとは扱わず、実際の採用時に条件を確認する。

## 7. リポジトリと配布物への案内

ルートの`LICENSE`には、Apache License 2.0の公式本文を改変せず配置する。

READMEのライセンス欄には、採用ライセンスと開発者本人の著作権表示を記載し、`LICENSE`と本文書へのリンクを設ける。適用範囲と例外を確認できるように案内する。

`NOTICE`は、今回の採用時点では作成しない。第三者由来の内容の取り込みなどで必要になった場合に追加する。既存のNOTICEに含まれる関連する帰属表示の引き継ぎが必要な場合は、その条件を守る。[公式本文・第4節](https://www.apache.org/licenses/LICENSE-2.0)

clonoを配布するときは、ライセンス本文と、配布内容に応じて必要な著作権・ライセンス・NOTICEなどの表示を含める。具体的な同梱方法は、配布方法が決まったときに確認する。

## 8. 追加・更新時の確認

ファイルを追加・更新するときは、該当する項目を確認する。

- clono側でライセンスを決められる内容か、第三者由来の内容か。
- ファイルの形式に合う表示があり、名義・年・識別子が正しいか。
- 自動生成やコメントできない形式について、別途管理する表示との対応が保たれているか。
- 第三者の表示や、必要なライセンス本文・NOTICEなどを保持しているか。
- 配布する場合、必要な表示が配布物にも含まれるか。

本文書の確認だけで、公式のライセンス条件をすべて満たしたと判断しない。対象の内容と配布形態に応じて、適用される条件を確認する。
