# CLIの仕様

- 状態：合意済み。実装・ローカル検証・独立レビュー・二人の確認完了。3OSでの実行確認は後続のCIで行う。
- 関連する手順書：[0003 最小限の開発基盤とバージョン表示を実装する](../plans/0003-set-up-development-foundation.md)
- 関連する仕様：[開発環境](development-environment.md)

## 1. 対象範囲

今回受け付ける機能指定は`--version`だけとする。インストールは扱わず、Node.jsでビルド済みの入口を直接実行する。

CLIは原稿や設定ファイルを読み書きせず、標準入力も読み取らない。

## 2. 引数と出力

以下の`\n`は、LFの改行1文字を表す。OSによって出力の改行を変えない。

| 引数 | 標準出力 | 標準エラー | 終了コード |
|---|---|---|---|
| `--version`だけ | `<version>\n` | 空 | `0` |
| 引数なし | `Usage: clono --version\n` | 空 | `0` |
| それ以外 | 空 | 下記のエラー表示 | `1` |

不正な引数を指定した場合は、受け取った引数の並びをコンパクトなJSON配列で表示する。要素の順序を保ち、空文字列、引用符、改行などはJSONの規則に従って表す。

`--invalid`を指定した場合の標準エラーは、次の文字列とする。

```text
Error: unsupported arguments: ["--invalid"]
Usage: clono --version
```

受け取った引数の配列全体を表示する。有効なオプションを含んでいても、指定された引数の組み合わせを受け付けない場合はエラーとする。

`--version`と空文字列を指定した場合は、次の表示になる。

```text
Error: unsupported arguments: ["--version",""]
Usage: clono --version
```

各行の末尾にLFを付ける。JSON配列の要素間に空白を追加しない。

`--version --unknown`や`--version --version`などの複数引数もエラーとする。`--help`、`-v`、`--`、位置引数は今回受け付けない。空文字列を引数として渡した場合もエラーとする。

表示用の名前は`clono`に固定し、Node.jsや生成ファイルの実際のパスを使い方へ表示しない。

将来`--help`を追加する際は、引数なしの使い方表示との統合を検討する。

## 3. 実装上の責務

`clono.cli`は、引数とバージョン番号を受け取り、出力文字列と終了コードを返す。

`clono.main`は次を担当する。

1. Node.jsの引数から、CLIへ渡された引数だけを取り出す。
2. 埋め込まれたバージョン番号とともに判定関数へ渡す。
3. 結果を標準出力・標準エラーへ書き込む。
4. `process.exitCode`を設定し、自然に終了する。

通常の完了処理では`process.exit()`で強制終了しない。出力を途中で切らないため、出力後に自然終了する構成とする。[Node.jsの終了処理の注意点](https://nodejs.org/docs/latest-v24.x/api/process.html#processexitcode)

引数判定用の外部ライブラリは追加しない。

## 4. バージョン表示の性質

表示する番号は、ビルド前に生成されたバージョン情報と一致する。

- 初期の出力は`0.0.0\n`とする。
- ビルド後に`package.json`を変更しても、既存の配布用ビルドの表示は変わらない。
- 番号変更後に再ビルドすると、新しい番号を表示する。
- 実行時の作業ディレクトリに依存しない。
- 配布用ビルドの実行に、CLJSソース、JDK、shadow-cljsの起動を必要としない。

## 5. テスト項目

| ID | 対象 | 入力・条件と期待結果 |
|---|---|---|
| C01 | 単体・CLI | `--version`だけを渡し、番号とLF、標準エラーが空、終了コード0を確認する |
| C02 | 単体・CLI | 引数なしで、使い方とLF、標準エラーが空、終了コード0を確認する |
| C03 | 単体・CLI | 未知のオプションで、標準出力が空、受け取った引数をJSON配列で含む規定のエラー表示、終了コード1を確認する |
| C04 | 単体・CLI | `--help`、`-v`、`--`、位置引数、空文字列もC03と同じ規則でエラーになる |
| C05 | 単体・CLI | `--version`と他の引数の組み合わせ、重複指定もC03と同じ規則でエラーになり、JSON配列は受け取った順序を保つ |
| C06 | CLI | 開発用・配布用の両ビルドで、C01〜C05の結果が一致する |
| C07 | CLI | 別の作業ディレクトリから絶対パスで起動しても、同じ結果になる |
| C08 | CLI | 空白と日本語を含むディレクトリへ配布用出力一式をコピーし、Node.jsで実行できる |
| C09 | ビルド・CLI | ビルド時の管理元と表示が一致し、管理元だけを書き換えても既存出力は変わらず、再ビルドすると新しい番号になる |
| C10 | 生成処理 | 管理元の欠落・不正なJSON・番号の欠落・文字列以外・空文字列で、生成処理と後続ビルドが失敗する |
| C11 | 分離実行 | 配布用出力一式をCLJSソース・shadow-cljsのない場所へ置き、Javaを起動できない条件でも正常に実行できる |
| C12 | 単体・CLI | 引数に含まれる空文字列、引用符、改行がJSONの規則で表され、要素間に空白が追加されず、エラー表示は規定の2行と末尾LFを保つ |

C09〜C11は一時的な作業場所で確認し、管理中のバージョン番号や開発環境を検証用に書き換えたままにしない。

CLIの結合テストにはプロセスの実行時間上限を設ける。正常系・引数エラーのいずれも、入力待ちや接続待ちで終了しない場合は失敗とする。
