# ADR 0001：配布ライセンスにApache-2.0を採用する

- 状態：合意済み

## 1. 背景

clonoは、最初のコードを追加する前に、配布ライセンスと適用範囲を明示する。

商用利用、改変、ソースを公開しない形での組み込み・再配布を許容しながら、再利用者が条件と元の作者を把握できるようにしたい。悪意のない再利用での行き違いを減らすことを重視する。

すべてのライセンスから最適なものを探すことや、悪意ある相手への対抗策を網羅することは目的にしない。希望に合う候補としてMITとApache License 2.0を比較した。GPL系は、再配布者にもソース公開などの条件を課す方針を今回採らないため、比較対象から外した。

比較の根拠は、[配布ライセンスの比較調査](../../research/project-license/README.md)に記録している。

## 2. 決定

clonoの配布ライセンスにApache License 2.0を採用する。識別子は`Apache-2.0`とする。

clono側でライセンスを決められるコード・文書・サンプル・調査資料には、原則として同じライセンスを適用する。第三者由来の内容は、その権利とライセンス条件に従って区別する。

開発者本人の著作権表示には`HASEBA Junya (7pairs)`を用いる。Thunder Clawは主な利用者であり、著作権表示の名義にはしない。

利用者の原稿や生成した本には、clonoを使ったという理由でApache-2.0を適用しない。clonoの利用を理由とする、本の配布・頒布形式への制限も設けない。

## 3. 採用理由と見送った案

### Apache-2.0を採用する理由

Apache-2.0は、商用利用、改変、ソースを公開しない形での組み込み・再配布を許容するという希望に合う。再配布時には、ライセンスの提供、関連する既存の表示の保持、変更したファイルへの明確な変更表示などの条件がある。[公式本文・第2・4節](https://www.apache.org/licenses/LICENSE-2.0)

特に、再配布する変更済みファイルに変更したことを表示する条件を評価した。元の表示を残すだけでなく、手を加えたものだと分かることが、行き違いを減らしたいという方針に合う。

この差が圧倒的な決定打だったわけではない。両候補が希望を満たす中で、改変の区別を明示するApache-2.0の方を選んだ。

### MITを見送る理由

MITも商用利用・改変・再配布を許容し、著作権表示と許諾文の保持を条件とする。本文が短く、管理の手間が少ない点は利点である。一方、変更したファイルへの変更表示を求める明文はない。[MIT公式本文](https://opensource.org/license/mit)

MITが希望を満たさないために除外したのではなく、今回は改変の区別を明示する方を選んだため、採用を見送った。どちらも希望に合うため、比較候補は広げなかった。

## 4. 表示と管理の方針

ファイルが単体で参照された場合にも名義とライセンスを確認できるよう、管理する各ソースファイルには、原則として著作権表示とSPDX識別子の短いヘッダを入れる。READMEにも名義とライセンスを明示し、ライセンス本文と適用ルールへ案内する。

年は最初の公開年を記載し、その後に変更した年には末尾の年を更新する。年が変わっただけで全ファイルを一括更新する運用にはしない。これはclonoの管理ルールとして定める。

コメントを書けない形式は、対象のパスと表示を別の文書にまとめる。clono自身の配布物に含める自動生成ファイルは直接編集せず、生成元で管理し、配布物にも必要な表示を含める。具体的な記載場所は、対象のファイルが登場したときに決める。

第三者由来の内容を取り込む前には、利用・改変・再配布の可否、保持が必要な表示、その配置を確認し、出典と確認結果を記録する。条件が不明な場合は、取り込む前に相談する。

`NOTICE`は、今回の採用時点では作成しない。第三者由来の内容の取り込みなどで必要になった場合に追加する。取り込む内容に既存の`NOTICE`がある場合の表示条件は、別途遵守する。

書式や更新時の具体的なルールは、[ライセンス方針](../specs/licensing.md)にまとめる。本文書には採用時の判断理由を残す。

## 5. 影響と限界

Apache-2.0の採用により、MITよりも変更表示や該当するNOTICEの扱いなど、確認する事項が増える。各ファイルの表示を管理する方針と合わせて、許容できる負担と判断した。

変更表示の条件は、詳細な変更履歴や差分の公開を求めるものとして扱わない。また、ライセンスや著作権表示だけで、元の作者の証明や無断利用の防止ができるとは考えない。

ヘッダの短縮によって、再配布時のライセンス本文の提供などが不要になるわけではない。具体的な条件は公式本文に従い、clono独自の表示ルールと区別する。

未選定の依存ライブラリまで確認済みとは扱わず、実際に採用するときに条件を確認する。
