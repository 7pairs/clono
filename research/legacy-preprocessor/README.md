# 旧前処理スクリプトの要件整理

前作で必要としていた機能と表現を旧スクリプト・設定・CSSから読み取り、次回作以降の要件を相談するための資料である。clonoの確定仕様ではない。

- 関連する手順書：[0004 旧前処理スクリプトから書籍制作の要件を整理する](../../docs/plans/0004-review-legacy-preprocessor-requirements.md)
- 読解結果と対話結果：[機能一覧と確認事項](results/requirements.md)
- 後続の相談：[全体の見直し](results/requirements.md#11-全体の見直し)、[後続の確認事項](results/requirements.md#12-要件に結び付けた後続の確認事項)。保留・対象外・資料不足の追跡は同資料の第13節を参照する。
- 現在地：全手順の実施・内部確認完了。外部レビューと作業全体の完了状況は通常のPRで確認する。各手順のレビュー結果は手順書の実施記録を参照する。

## 対象資料

2026-10-26、公開用の記録として、提供時のローカルパスのホームディレクトリ部分を`~`へ一般化した。ファイル名、バイト数、行数、原資料のSHA-256は変更していない。

2026-10-19（日本時間）に、開発者からスクリプトと設定ファイルが提供され、追加でCSSとVivliostyleの設定ファイルが提供された。

| 資料 | 提供時のローカルパス | バイト数 | 行数 |
|---|---|---:|---:|
| `prebuild.js` | `~/Downloads/prebuild.js` | 36,169 | 1,068 |
| `catalog.js` | `~/Downloads/catalog.js` | 1,588 | 72 |
| `theme.css` | `~/Downloads/theme.css` | 37,885 | 1,798 |
| `vivliostyle.config.js` | `~/Downloads/vivliostyle.config.js` | 573 | 22 |

確認した版のSHA-256は次のとおり。読解結果の行番号はこの版に対するものである。


開発者の説明では、`theme.css`の1～581行はVivliostyleのtheme-techbookのCSSをそのままコピーした部分で、それ以降はThunder Clawで書いた追加部分である。原本には583行目に独自実装の開始を示すコメントがあり、1行目には元CSSを示すURLがある。上流の原本や採用バージョンとの照合は行っていない。

複数のCSSを読み込む形では何かがうまく動かず、一つのCSSへまとめたという経緯も開発者から共有された。具体的な症状や原因は覚えていないとのことで、読み込み順、優先順位、Vivliostyleの制限などの原因は特定しない。

原本はこのリポジトリへコピーしていない。提供ファイルにライセンスを明示する記述はなく、CSSには上記の第三者由来部分が含まれる。リポジトリへの収録条件は未確認であり、原本へのApache-2.0の適用や再配布を判断したものではない。収録する場合は[ライセンス方針](../../docs/specs/licensing.md)に従って確認する。

このため、リポジトリだけでは原本を再読できない。上記のファイルが移動・変更された場合は、同じSHA-256の資料を用意する必要がある。

手順3の確認時点では、上記のローカルパスに4原本とも見つからなかった。理由や移動先は未確認である。手順3はレビュー済みの読解結果と対話記録をもとに整理し、原本の再読とSHA-256の再照合は行っていない。記載した識別情報は手順1で確認したものを維持している。

## 確認方法と限界

4ファイルをテキストとして全体を読み、機能ごとに処理、条件、関連設定、CSSの宣言を整理した。CSSはコピー部分と追加部分を区別し、スクリプトが出力する要素とセレクターを照合した。Vivliostyleの設定では`catalog`の呼び出しと生成先からの原稿指定を確認した。スクリプトや設定をNode.jsで実行・importしていない。依存の導入、公式資料の調査、フィクスチャの作成、組版の検証も行っていない。

再確認する場合も、まずファイルをテキストとして読み、SHA-256と行番号を照合する。スクリプトには出力先ディレクトリの再帰削除処理が含まれるが、今回の静的な確認では実行しない。

開発者から、Vivliostyleのビルド直前にスクリプトを実行し、生成先をVivliostyleの入力にしていたとの説明を受けた。追加提供された設定から、`catalog.getAllManuscripts()`を使い、`./manuscripts`配下を`entry`へ指定することを確認した。スクリプトの起動順を定めるコマンドやビルド設定は未提供であり、起動順は開発者の説明として扱う。

原稿、取り込み対象ファイル、画像、フォント、依存バージョンを特定するファイル、生成結果、PDFは未提供である。CSSとVivliostyleの設定は確認できたが、実際の適用・使用箇所、組版上の見た目、旧環境での正常動作は未確認である。扉と空白ページの設定が参照する`illustration.css`も未提供である。

開発者は共有スクリプトを使って入稿PDFを作ったはずと回答したが、版の一致には自信がないとのことで、確定情報とは扱わない。一方、本を確認した結果として、付録にコードリスト参照はなく、付録で採番したものは図だけだったとの報告を受けた。この使用実績の報告と、そらによる原本の静的な読解結果を区別する。

`prebuild.js`が参照する外部モジュールは`fs`、`path`、`dedent`、`parsimmon`とローカルの`catalog`である。依存のバージョンや実装は確認していない。

「必要・不要・保留」は旧機能の再実装の採否ではなく、今後の目的やclonoの専用処理の必要性を整理した区分である。CSS・Vivliostyle側で行う表現まで不要とするものではない。手順2の独立レビューは指摘なしで完了した。独立レビューと実施結果の記録は手順書から追う。
