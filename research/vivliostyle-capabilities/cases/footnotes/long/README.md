# 長い脚注

## 目的

一ページの脚注領域へ収まらない長い一段落の脚注について、VFMの`dpub`および`gcpm`モードによるページ間の分割、内容保持、番号、区切り線および後続本文との位置関係を比較する。

脚注内の複数段落、強調、リンク、コードなどのMarkdownは扱わず、長さだけを検証対象とする。

## 入力とCSS

一ページ目の上部から一件の脚注を参照し、その後に通常の本文段落を置く。脚注は一つのMarkdown段落であり、`区間01`から`区間36`までの識別可能な文章を順番に含む。

識別子によって、PDFのページ境界で脚注内容が欠落、重複または並べ替えられていないことを確認する。

`footnotes.css`は共通CSSを読み込み、次の指定だけを加える。

```css
.footnote {
  float: footnote;
}
```

`@footnote`および`footnote-policy`は指定せず、Vivliostyleの既定動作を確認する。

## 実行方法

`research/vivliostyle-capabilities/`で、HTMLとPDFを生成する。

```console
npm run build:footnotes:long
```

個別に生成する場合は、次のコマンドを使用する。

```console
npm run build:footnotes:long:html
npm run build:footnotes:long:pdf
```

生成物は`output/footnotes/long/`へ出力され、Git管理対象には含まれない。

HTMLは直接固定した`@vivliostyle/vfm` 2.7.2で生成する。
PDFはVivliostyle CLI 11.1.0を通じて生成するため、CLIが内蔵する`@vivliostyle/vfm` 2.7.0がMarkdownの変換に使用される。

## HTMLの結果

2026-08-08に標準条件で実行し、次の結果を確認した。

### `dpub`

- 本文へ番号1を含む`a[role="doc-noteref"]`を出力した
- 脚注を一つの`aside.footnote[role="doc-footnote"]`として出力した
- 参照と脚注本体をIDと`a[role="doc-backlink"]`で相互参照した
- `区間01`から`区間36`までを、一つの脚注要素内へ一度ずつ順番どおり出力した

### `gcpm`

- 参照位置へ一つの`span.footnote[role="doc-footnote"]`を出力した
- 参照番号、脚注番号および相互リンクはHTMLへ出力しなかった
- `区間01`から`区間36`までを、一つの脚注要素内へ一度ずつ順番どおり出力した

Vivliostyle CLI内蔵VFM 2.7.0の中間HTMLについても、脚注に関係する構造と36区間の内容はVFM 2.7.2の結果と一致した。

## PDFの結果

| 項目 | `dpub` | `gcpm` |
|---|---|---|
| ページ数 | 2 | 2 |
| 脚注の開始 | 参照と同じ一ページ目 | 参照と同じ一ページ目 |
| 一ページ目の末尾 | `区間22`の途中 | `区間19`の途中 |
| 脚注の継続 | 二ページ目の脚注領域 | 二ページ目の脚注領域 |
| 脚注番号 | 一ページ目だけに表示 | 一ページ目だけに表示 |
| 区切り線 | 両ページに一本ずつ | 両ページに一本ずつ |
| 参照後の本文 | 二ページ目の通常本文領域 | 二ページ目の通常本文領域 |

両モードとも、二ページ目では参照後の通常本文をページ上部へ配置し、継続する脚注をページ下部の脚注領域へ配置した。脚注の継続部分に番号は繰り返されなかった。

PDFから空白文字を除去して検査した結果、`区間01`から`区間36`までがそれぞれ一度ずつ順番どおり出力されていた。紙面の全ページを画像として確認し、本文および脚注に欠落、重複、文字化け、重なり、切れまたはページからのはみ出しがないことを確認した。

同じCSSを使用しても一ページ目へ収まる脚注量に差が出た。`dpub`と`gcpm`は脚注のHTML要素構造が異なり、本ケースでは`dpub`のほうが多くの内容を一ページ目へ配置した。具体的な書体、文字サイズ、行間などは本ケースで明示していないため、最終的な紙面デザインではCSSによる統一が必要になる可能性がある。

Popplerで`dpub`のPDFを検査した際、これまでのケースと同じname tokenの長さに関する警告が出た。`gcpm`では警告は出なかった。

## 暫定的な判断

一ページの脚注領域へ収まらない長い一段落の脚注でも、`dpub`と`gcpm`は内容を保持したまま複数ページへ分割できる。clonoが脚注を分割したり、継続ページを生成したり、内容を複製したりする必要はない。このケースの分類は「clono不要」、確信度は高とする。

継続ページで脚注番号を繰り返さないことと、両モードの既定の組版密度が異なることを実制作で許容できるかは、CSSおよび紙面仕様の検討事項とする。これらは本ケースだけを理由にclonoの変換責務へ含めない。
