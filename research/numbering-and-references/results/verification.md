## 1. 資料調査から分かったこと

採番、参照値の取得、目次の抽出、キャプションのHTML化には既存機能の候補がある。一方、それぞれの機能があることだけでは、複数原稿・付録・見出し差し替えの組み合わせを満たせるとは判断できない。

| 対象 | 資料・対象版コードから確認したこと | 後続で確かめる問い | 根拠 |
|---|---|---|---|
| 見出しの番号 | CSSカウンターで階層別の増分・リセット・表記を定義する方法がある | VFMのsection構造で正しい範囲に作用するか。原稿境界を越える章番号をどう与えるか | S03・S08 |
| 番号の参照 | `target-counter()`で参照先のカウンター値を取得する候補がある | 増分を疑似要素に置いた場合もID位置で値を取得できるか。別原稿・前方参照でも成立するか | S01・S02・S08 |
| 見出し本文の参照 | `target-text()`で本文と疑似要素を分けて取得する処理がある | 強調等を含む本文、番号なし見出し、差し替え後でも必要な文字列を得られるか | S02・S08 |
| 目次 | CLIに見出し抽出、掲載階層、出力変更の機能がある。抽出時点ではHTMLを読み、既定の出力は見出しの内部HTMLを使う | CSSで表示する番号をどう目次へ渡すか。番号と本文を二重に出さず、正しい見出しへリンクできるか | S04・S07 |
| 目次のページ番号 | 公式チュートリアルに`target-counter(attr(href), page)`の使用例がある | 前付けを含む本で、実際の参照先ページと一致するか | S05・S08 |
| 図とコードのキャプション | VFMが`figure`・`figcaption`を作る。IDをキャプションへ移すオプションがある | IDと増分の位置を合わせられるか。図・コードを区別し、各種類を独立採番できるか | S06・S09 |
| 表のキャプション | 確認したVFMの表handlerはGFM表とセル配置を扱い、専用キャプション生成は見つからない | 通常HTMLのcaption等とMarkdown表を組み合わせられるか。補助処理が必要な範囲はどこか | S06・S09 |
| 差し替え | HTML見出しを保持する構造や、表示用画像と本文情報を分ける構造を検討できる | CLIが読む組版前HTMLと、Coreが読む組版結果の両方に必要な情報を残せるか | S07～S09 |

以上は資料調査と静的読解の結果であり、CSS・変換・組版の実行結果ではない。CSS仕様の複数文書に関する制限と、VivliostyleのURL変換・参照解決の実装を区別する。別原稿への参照は、対象版での実測を必須とする。

## 3. 検証する方式の候補

最初から番号を自前計算せず、次の順で比較する。ここでの順序は手順2・3の実験内での順序であり、製品の方式を採用したものではない。

| 候補 | 方法 | 比較で明らかにすること |
|---|---|---|
| A：既存機能と調査用CSS | VFM標準出力、CLIの目次、CSSカウンターとtarget系関数を使う。文書区分や参照形式を選ぶためのID・classは調査例に明示する | 数値・本文・目次項目を独自計算しない場合の成立範囲。文書をまたぐ章番号の継続も試す |
| B：最小限の情報を補う | Aで不足した箇所に限り、原稿順から章の開始値や本文・付録の識別情報を付ける、表にcaptionとIDを与える、CLIの目次出力フックを使うなどの補助を加える | 入力へ必要情報を付ければ既存機能に任せられる範囲。付与した値と補助コードを別記する |
| C：clonoで補う処理の候補 | A・Bで成立しない処理について、番号・本文・目次情報を前処理で管理する案を整理する | 自前処理が必要と考える理由と入出力。製品実装や汎用の参照エンジンは作らない |

AとBの結果を混ぜない。手で章開始値を固定して番号が出ただけでは、「原稿を並べ替えれば自動更新される」と判断しない。Bで原稿順から開始値を生成する場合も、その補助が必要だったと記録する。

番号の取得はまず、対象要素自身で増分を行い、疑似要素で表示する構成を候補にする。階層は章・節・項の別カウンターを組み合わせ、付録の章は英字表記を試す。CSSによる階層スコープとVFMのsection構造の相性は未確認なので、単一文書での期待値を先に確かめる。

目次の番号は、CSSで表示した番号が`headingHtml`に入らない点を踏まえて、目次側でも参照先のカウンターを取得する案を優先する。番号なし項目を区別する情報や、目次から見出しIDへリンクする情報が必要なら、その受け渡しを補助処理として分ける。

参照記法、class名、IDの付け方、原稿区分の指定は調査用であり、製品の利用者向け記法・設定を確定しない。

## 4. 検証用原稿の構成と期待値

手順2で次の原稿を新規作成する。手順1では原稿ファイルやPDFを作っていない。

| 原稿 | 見出しと役割 | 基本構成での期待値 |
|---|---|---|
| `preface.md` | H1「はじめに」、前方の参照を配置 | 見出しは番号なし。目次掲載と本文参照は可能 |
| 目次 | CLIが生成する調査用目次 | 初期はH2までを掲載。条件付きの検証でH3までに変更 |
| `alpha.md` | H1「導入」、H2「準備」「実行」、各H2の下にH3を配置 | 第1章、1.1・1.2、1.1.1・1.2.1 |
| `beta.md` | H1「応用」、同じ見出し階層を配置 | 第2章、2.1・2.2、2.1.1・2.2.1 |
| `appendix-a.md` | H1「補足」、同じ見出し階層を配置 | 付録A、A.1・A.2、A.1.1・A.2.1 |
| `appendix-b.md` | H1「資料」、同じ見出し階層を配置 | 付録B、B.1・B.2、B.1.1・B.2.1 |
| `afterword.md` | H1「おわりに」、後方の参照を配置 | 見出しは番号なし。目次掲載と本文参照は可能 |

本文・付録の各章に図・表・コードをそれぞれ2件置く。各種類の番号は本文なら`1.1`・`1.2`、次章は`2.1`・`2.2`、付録なら`A.1`・`A.2`、次の付録は`B.1`・`B.2`を期待する。表示上の種類名は調査用に「図」「表」「リスト」を使い、参照にも同じ番号を出す。見出し・他種類のカウンターを増やしても、種類ごとの番号が混ざらないことを確かめる。

番号と見出し本文を組み合わせる参照は、調査用の期待値を「1.1 準備」のように定める。引用符・区切りの装飾は製品仕様に固定しない。本文だけの参照は「準備」とし、番号が混入しないことを確認する。

参照先には安定した明示IDを付け、`alpha.html#alpha-preparation`のように生成HTMLのファイル名とIDで参照する構成を基本にする。VFMの属性記法を採用済みのAST再出力が保つかも検証する。保持できない場合は、調査用HTMLや補助処理の必要性を記録し、経路を黙って変えない。自動生成IDは補助的な比較とし、全原稿での一意性を期待しない。

各原稿の参照段落を使い、同一原稿の前方・後方、別原稿の前方・後方を検証する。見出しH1～H3は番号のみ・本文のみ・番号と本文の3形式、図・表・コードは番号参照の1形式を対象にする。番号なし見出しは本文のみを使う。

章順変更は本文2章を交換する例と付録2章を交換する例を分ける。ファイル名とIDは維持し、元の導入が第2章、元の補足が付録Bとなっても、参照が同じ対象を指し、新しい番号と本文を表示することを期待する。

## 6. 手順3の差し替え例と検証項目

差し替え例は最初にH1～H3の標準出力を対照として保存する。文字を残す例ではH1～H3の内部に装飾用要素を置き、画像の例ではH1の表示を画像にする。画像以外のH2/H3は標準出力を維持する。番号なしH1にも同じ差し替えを適用し、誤って番号を付けないか確認する。

| ID | 関連要件 | 差し替え・比較 | 期待する結果と観測 |
|---|---|---|---|
| X01 | T04・必須 | H1～H3の文字をspan等に分ける。見出し要素とIDを保持する | 番号・本文の各参照と目次が標準出力と同じ内容になり、装飾用文字が混入しない |
| X02 | T04・必須 | H1を画像で見せ、参照用の見出し本文とIDをHTMLに残す | 章扉に文字が二重表示されず、本文参照と目次は画像だけにならず文字を示す。保持する要素・CSSの条件を記録 |
| X03 | T04・成立条件の比較 | X02について、表示を消す方法を`display: none`と、要素のレイアウト参加を保った文字の隠し方で比較する | 番号・target-text・CLIの目次に与える差を記録。非表示要素でも動くと先に保証しない |
| X04 | T04・不足を調べる対照 | 見出し要素を装飾用divだけへ置換する例、画像のみで本文文字を持たない例を比較する | 目次抽出・本文取得が欠ける範囲を記録。任意の構造で成立するという要件へ広げず、必要な情報を説明する材料にする |

### 方式と実行環境

[公式チュートリアルS10](../sources.md#5-手順2aで確認したページ側カウンターの資料と実装)を出発点に、本文用の`chapter`と付録用の`appendix`を分けた。要点は次のCSSである。

```css
@page :first { counter-reset: chapter 0 appendix 0; }
@page main:nth(1) { counter-increment: chapter; }
@page appendix:nth(1) { counter-increment: appendix; }
body.main { page: main; }
body.appendix { page: appendix; }
body.front { page: front; }
```

画像の例では、H1とIDを保持し、画像とは別に参照用の文字を残した。構造の要点は次のとおりである。


```css
  height: 1px;

}
```
